# leneu

지도·여행 일정·여행 기본 문서 템플릿의 새 작성 메뉴는 별도 여행 서비스로 분리하기 위해 제거했습니다. 기존 문서와 공유·내보내기는 유지하며, [재활용 자료와 코드 인계](docs/handoffs/2026-10-05-travel-service-extraction.md)에 위치와 의존성을 정리했습니다.

빠르게 기록하는 개인 입력함, 메모 관리, 블록 페이지, 할 일 관리의 로컬 실행 버전입니다. 메모·URL·이미지·파일과 AI 요청을 저장하고 검색할 수 있습니다. AI 실행기를 설정하면 메모나 저장된 페이지를 대상으로 요청하고 처리 상태·결과·이력을 확인할 수 있습니다. 페이지에 담은 메모는 정리 완료로 보관하며 원본을 입력함으로 되돌릴 수 있습니다. 저장한 항목은 SQLite와 `data/blobs`에 남습니다.

`/tasks`에서는 **목록 / 보드**를 전환할 수 있습니다. 보드는 대기·진행 중·완료로 나누며 PC에서는 드래그, 모바일에서는 상태 선택으로 옮깁니다. 선택한 보기는 이 브라우저에 기억하며 홈은 짧은 할 일 목록을 유지합니다.

모바일 홈에서는 작은 입력 카드에 바로 기록하고 **크게 쓰기**로 전체 화면을 엽니다. 메모·페이지·할 일 등 공통 도크가 있는 화면에서는 하단 **바로 기록하기**와 첨부 버튼을 사용할 수 있습니다. 닫아도 초안은 남고, 비어 있는 메모에 URL 하나를 붙여넣으면 링크 입력으로 전환됩니다.

작성 중인 메모·AI 설정과 템플릿은 같은 탭에서 새로고침해도 복구됩니다. 첨부는 **첨부 임시저장 중…**이 끝나면 함께 복구됩니다. 저장 중 다음 메모를 쓰면 새 입력을 유지합니다. 초안은 이 브라우저에만 있으며 탭을 닫은 뒤 새 탭에서 고르는 기능은 아직 없습니다.

목록과 상세의 생성 시각은 기기 설정과 관계없이 한국 시간(`Asia/Seoul`)으로 보여줍니다. 오늘 쓴 글은 `오늘 오후 12:30`, 이전 글은 `YYYY-MM-DD HH:mm` 형식입니다. 저장값은 UTC ISO 형식이며, 저장 후 24시간 동안 목록의 생성 시각과 같은 줄 오른쪽 끝에 `NEW`가 표시됩니다. 메모에는 별도 제목 필드가 없으며 목록과 상세 모두 입력한 원문을 보여줍니다.

보관한 메모·링크·이미지·파일을 열고 **항목 수정**을 누르면 내용이나 설명을 고칠 수 있습니다. 링크 항목은 주소도 바꿀 수 있습니다. 첨부 원본과 작성 시각은 유지되고, 상세에는 생성일·최종 수정일이 항상 표시되고, 저장이 성공하면 최종 수정일이 갱신됩니다. 다른 탭이 먼저 저장했다면 내 초안을 남긴 채 알려줍니다.

홈은 빠른 입력·할 일·AI 요청 현황·정리 전 일반 메모 최근 3개·최근 페이지 4개를 보여줍니다. PC에서는 입력·메모·페이지가 왼쪽, 할 일·AI 현황이 오른쪽이며 모바일에서는 입력·AI·할 일·메모·페이지 순서입니다. 일반 입력은 **저장**, AI를 선택한 입력은 **저장하고 AI 요청**을 누릅니다. 사이드바 **메모** 또는 <http://127.0.0.1:5173/memo>에서 전체 보관 목록을 관리합니다. **보관한 메모**와 **AI 요청**은 별도 탭이며 보관한 요청문 탭 주소는 <http://127.0.0.1:5173/memo?view=ai>입니다. 각 탭에서 종류별 필터·검색·상세·수정을 쓸 수 있고 **입력함 / 정리 완료**를 선택합니다. 기본 입력함의 목록·개수에는 정리 완료 메모가 포함되지 않습니다. 메모 화면은 한 번에 50개를 보여 주고 다음/이전 목록으로 이동합니다. 기존 서버 API의 기본 조회 한도는 100개입니다.

홈의 **AI 요청** 현황은 진행 중 작업을 우선해 최대 3개를 보여줍니다. **모두 보기** 또는 사이드바 **AI 요청**(`/ai`)에서 메모·페이지 작업을 함께 확인하고 **전체 / 진행 중 / 결과 준비 / 실패**로 좁힙니다. 개수는 해당 기록의 전체 작업 수이며 선택한 상태의 최근 50개와 한국 시간의 요청·시작·완료/종료 시각을 표시합니다. 행을 누르면 그 요청의 결과·이력을 열고 페이지 AI 도구는 자동으로 펼쳐집니다. 정리 완료된 메모의 작업도 보이며 휴지통 기록은 제외합니다. 실행 전 요청문은 **보관한 요청문**으로 찾습니다. **새 AI 요청**은 작성 중인 초안을 유지한 채 입력함의 AI 설정을 켭니다. 모바일 `/ai`에서는 하단 기록 도크를 숨기고 이 버튼으로 작성합니다.

AI 현황은 화면에 보이고 탭이 활성일 때만 확인합니다. 진행 중 작업이 있으면 2초, 없거나 조회가 실패하면 30초 간격으로 갱신하며 화면 밖·탭 숨김·이탈 때 중단합니다. 조회 오류에는 마지막 확인 상태라는 안내와 **다시 불러오기**를 표시합니다. 모니터를 여는 것만으로 요청을 실행하거나 재시도하지 않습니다.

모든 화면의 사이드바 **검색** 또는 `⌘K`·`Ctrl+K`로 **통합검색**을 엽니다. 일반 메모의 현재 원문·URL, AI 요청의 현재 원문과 보관 당시 요청문, 페이지 제목·본문·링크·표·Mermaid·일정의 작성 텍스트, 첨부 **파일명**을 찾습니다. **전체 / 메모 / 페이지 / 파일 / AI 요청**으로 좁힐 수 있고, 빈 입력은 최근 활성 기록 20개, 검색 결과는 20개씩 **더 보기**로 표시합니다. 검색에는 두 글자 이상인 단어 하나가 필요하며 `교토 3`처럼 한 글자 조건을 함께 쓸 수 있습니다. `%`, `_`, 따옴표도 그대로 찾습니다. 방향키·Enter로 열고 Escape로 닫으며, 뒤에서 작성하던 메모·페이지 초안은 유지됩니다. 정리 완료 메모·AI 요청은 통합검색에서 제외합니다. 파일명은 정리 전의 활성 소유 메모 또는 사용하는 활성 페이지가 있을 때 찾으며 해당 기록으로 이동합니다. 파일 본문·OCR·AI 실행 결과는 검색하지 않습니다.

**내 페이지** 목록은 입력함에서도 바로 보이며, 항목을 누르면 해당 페이지가 열립니다. **내 페이지** 옆 `+`로 새 문서를 만듭니다. 개별 문서는 `/pages/:id`를 사용하고 별도 페이지 목록 화면은 없습니다. 이전 `/pages`·`/temp` 주소는 `/memo`로 연결합니다. 기존 **임시 정리** 문서는 일반 페이지로 보존하며 자동으로 새 임시 문서를 만들지 않습니다. 전환 중 작성하던 빠른 입력 초안은 남으며, 휴대폰에서는 페이지를 보다가도 하단 **바로 기록하기**를 누를 수 있습니다. **더보기 → 선택 블록 이동**에서 다른 페이지 끝으로 옮길 수 있습니다. 원본과 대상의 저장 버전을 확인하며 충돌 시 초안을 유지합니다.

메모 상세의 **내 페이지에 정리**에서 기존 페이지를 고르거나 **새 페이지**로 상위 페이지와 제목을 정합니다. 내용 복사·첨부를 선택해 **페이지에 담기**를 누르면 문서로 이동하고 원본 메모는 **정리 완료**가 됩니다. 본문에는 원본 메모 카드나 태그를 자동으로 넣지 않습니다. 원본·첨부·AI 이력은 남으며 페이지 사본의 편집은 원본을 바꾸지 않습니다. **페이지 정보**의 **원본 메모**에서 출처를 확인하고 `/captures/:id`로 다시 엽니다. 메모 목록의 **정리 완료**에서 원본을 열어 **입력함으로 되돌리기**를 누르면 일반 목록·개수·검색에 돌아옵니다. 연결 페이지를 휴지통으로 옮겨도 원본 메모는 삭제되지 않습니다. 응답이 끊기면 같은 요청을 다시 확인하며, 같은 탭에서 새로고침한 뒤에도 최초 UUID·대상·선택을 유지해 중복 생성을 막습니다.

페이지의 이미지·파일은 기존 첨부 바이트를 재사용합니다. 기존 페이지에 저장된 원본 메모 블록은 보관하되 본문과 Markdown 보기·복사에서는 숨깁니다. 첨부의 설명·앱 전용 ID는 Markdown에 포함되지만 파일 바이트는 포함되지 않습니다. **더보기 → 파일 첨부**로 페이지에 직접 업로드할 수도 있습니다. 숨은 메모를 만들지 않고 페이지가 소유하며 한 번에 8개·개별 25MB·합계 100MB까지 받습니다. Markdown과 첨부를 한 묶음으로 내보내는 기능은 이후 단계입니다.

메모 상세의 **휴지통으로 이동**, 페이지의 **페이지 정보** 메뉴에서 기록을 휴지통으로 옮깁니다. 페이지는 현재 하위 문서도 함께 옮기며 확인 단계에 개수를 표시합니다. 이동 직후 **되돌리기**, 또는 사이드바 **휴지통**(`/trash`)의 **복원**으로 다시 꺼낼 수 있습니다. 본문·첨부·생성일·최종 수정일을 보존하며 영구 삭제·자동 비우기는 없습니다. 다른 활성 페이지가 사용하는 첨부는 메모를 옮겨도 계속 열립니다. 저장 중이거나 해결하지 않은 페이지 초안이 있으면 먼저 저장·복구를 마쳐야 합니다.

사이드바의 leneu. 로고 오른쪽 **화면 모드**에서 시스템·밝음·어두움을 고를 수 있습니다. 그 아래 줄에는 한국 날짜를 `YYYY-MM-DD (요일)`로 오른쪽 정렬해 보여줍니다. 기본은 운영체제 설정을 따르고, 직접 고른 값은 이 브라우저에 저장됩니다. 페이지 편집기와 Mermaid 미리보기까지 화면 모드에 맞춰 표시됩니다. 브라우저 탭 아이콘은 leneu.의 네 칸 로고입니다. 데스크톱 공통 상단바는 없으며 모바일에서는 메뉴·로고·현재 영역만 작은 줄로 보여줍니다.

페이지를 열면 바로 편집할 수 있습니다. 문서 위에는 경로·저장 상태와 아이콘 도구를 두고, 생성일·최종 수정일은 제목 바로 아래에서 확인합니다. 제목에서 Enter를 누르면 본문으로 이동합니다. 본문에 `#`, `-`, `- [ ]`, `>`, `"` 같은 표기를 바로 입력하거나 Markdown/서식 있는 글을 붙여넣으면 블록으로 정리됩니다. `>`는 접을 수 있는 목록, `"`는 인용으로 바뀝니다. 표와 `Mermaid` 다이어그램도 넣을 수 있습니다. `/` 메뉴에서는 접을 수 있는 목록·제목, 목차, 이모지, 하위 페이지도 고를 수 있고, `Tab`으로 블록을 다른 블록 안쪽에 넣을 수 있습니다. 제목 위에서 페이지 대표 이모지를 정하면 사이드바·목록·페이지 링크에 함께 보이고, 하위 페이지는 사이드바에서 상위 아래에 들어가 보입니다. 사이드바 행은 드래그해서 순서를 바꾸거나 다른 페이지 안에 넣을 수 있고, 화살표로 하위를 접었다 펼 수 있습니다. 편집 내용은 `⌘Z`·`⇧⌘Z`나 위쪽 **되돌리기**·**다시 실행** 버튼으로 되돌립니다. **Markdown 보기**에서 원문을 확인하고 **Markdown 복사**로 다른 곳에 옮길 수 있습니다. 본문은 블록 JSON으로 자동 저장하며, 충돌 시 늦은 저장을 거절하고 이 기기의 초안을 남깁니다. 전체 문법과 예시는 [Markdown 사용 안내](MARKDOWN_GUIDE.md)에 정리했습니다.

**더보기 → 페이지 복제**는 현재 문서만 같은 상위 아래 복사합니다. 하위 페이지는 복제하지 않고 본문의 기존 링크·첨부는 재사용합니다. **템플릿**에서는 현재 문서를 이름과 함께 보관해 새 페이지를 만들거나 템플릿을 삭제합니다. 프롬프트 템플릿과 별개입니다.

**더보기 → 수정 이력**은 최근 100개 저장 버전의 제목·아이콘·본문을 읽기 전용으로 보여줍니다. 선택한 수정본으로 복원하면 현재 계층을 유지한 새 버전이 생깁니다. 기존 문서는 기능 도입 당시 현재 버전부터 기록하며 이후 편집·AI 반영·메모 담기도 기록됩니다. 저장 문제·충돌·확인 대기 중에는 복원이나 이동으로 초안을 덮지 않습니다. 응답 유실 뒤에는 같은 UUID·최초 내용으로 **같은 요청 다시 확인**을 사용하며 첨부는 처음 선택한 파일을 다시 골라야 할 수 있습니다.

실행 중인 로컬 저장소에 예시 페이지가 없다면 `npm run seed:showcase`로 [예시 원문](examples/markdown-showcase.md)을 페이지에 한 번 넣을 수 있습니다. 같은 이름의 페이지에 내용이 있으면 덮어쓰지 않습니다.

**페이지 공유**에서는 지정한 문서를 읽기 전용 링크로 보여주고 1·7·30·90일 또는 만료 없이 발급할 수 있습니다. 새 링크 발급과 **링크 끊기**는 기존 링크를 즉시 무효화합니다. 개발 중에는 `npm run start:public`로 별도 공개 뷰 서버를 켠 뒤 `http://127.0.0.1:8790/s/…` 주소를 확인합니다. 이 서버에는 개인 API·검색·업로드·AI 기능이 없습니다. 개인 API에는 아직 본인 인증이 없으므로 인터넷 Tunnel에는 공개 뷰 서버만 연결해야 합니다. 외부 주소를 사용할 때는 `PUBLIC_SHARE_ORIGIN=https://share.example.com`을 개인 서버 환경에 지정합니다. [공유·계획 사용 안내](SHARING_AND_PLANS.md)에 배포 경계와 현재 제한을 적었습니다.

기존 문서의 호환용 **일정** 블록은 한국시간 날짜·시작/끝·활동 유형·일정·장소·좌표·링크·메모를 최대 50개까지 저장합니다. 관광·이동·식사·휴식·숙박·기타는 선택 사항이며 시작/끝으로 소요시간을 계산하고 겹치는 시간을 안내합니다. 이동과 장소 없는 활동에는 방문 번호를 붙이지 않습니다. 개인 화면의 **장소 지도 보기**는 Google 지도만 지연 로딩합니다. 공유 화면은 이미지·시간표·Google Maps 외부 링크이며 지도 API를 호출하지 않습니다. **일정 설정(···) → 지도 이미지**에서 페이지에 첨부한 이미지를 고릅니다. 이미지가 없으면 자체 방문 위치·순서 이미지를 표시합니다. Geoapify 키를 설정하면 실제 도로 배경의 정적 지도 이미지를 만들 수 있습니다. 실제 이동 경로 계산·Google 자동 캡처는 제공하지 않습니다. `npm run seed:activity-plan`은 이 구성을 확인할 새 하루 계획을 한 번 추가하고 기존 페이지를 덮지 않습니다.

**Geoapify 지도 이미지**는 `.env`의 `GEOAPIFY_API_KEY`를 설정하고 개인 서버를 재시작한 뒤 일정 블록의 **지도 이미지 만들기**를 누릅니다. 저장된 장소 좌표로 번호 핀·방문 순서 화살표가 있는 PNG를 만들어 페이지에 첨부합니다. 기본 **주변 지역·도로**는 Noto Sans Regular 지역명과 자연스러운 자간, 연한 건물·공원·물·주요 도로 색을 사용합니다. 주변 동네가 보이도록 범위를 넓히며 **지역명 강조**, **도로와 장소 자세히**, **밝고 간결하게**, **어두운 지도**도 고를 수 있습니다. 정적 API는 글자 크기·색을 지원하며 폰트/굵기/자간은 선택한 지도 스타일에 따릅니다. 장소/방문 순서가 바뀌면 갱신 안내만 표시하며 자동 생성하지 않습니다. 개인·공유·오프라인 ZIP은 저장 이미지와 출처를 사용하고 Google Maps 링크는 클릭할 때만 엽니다. 생성 키는 개인 서버에서만 사용합니다. 앱의 보호 한도는 UTC 하루 20회 생성 시도이며 제공자 크레딧과는 다릅니다. Google 키는 이 이미지 생성에 필요하지 않습니다.

Google의 **데모 키** 입력은 이 탭의 `sessionStorage`에만 보관하며 페이지 본문·DB·공유 링크에 저장하지 않습니다. 로컬 `.env`의 `GOOGLE_MAPS_DEMO_KEY`는 개인 서버의 지도 설정입니다. `npm run dev`·`npm start`는 이 파일을 읽고 Compose의 개인 서비스에 전달합니다. 공유 서버는 키를 사용하지 않습니다. `.env`는 Git과 Docker 빌드 컨텍스트에서 제외됩니다. `npm run seed:google-map`의 기존 세 장소 예시도 보존합니다. [Google 일정 지도 안내](SHARING_AND_PLANS.md#google-일정-지도)를 따릅니다.

기존 **지도** 블록의 좌표·이름·저장된 확대 값은 보존합니다. 화면은 이미지와 Google Maps 링크로 제공하며 OSM 임베드와 Leaflet 패키지는 제거했습니다. `npm run seed:itinerary`의 기존 교토 표·장소 예시도 덮지 않습니다.

`npm run seed:memo`는 이해하기 쉬운 여행 예시를 실제 저장소에 추가합니다. 일반 메모·문서 링크·PNG 여행 메모·Markdown 첨부 4개, 실행 전 리서치·여행 계획 요청 2개, 직접 편집할 수 있는 여행 페이지와 하위 예약 체크 페이지 2개, 페이지 체크리스트와 독립된 할 일 2개입니다. 추가한 메모는 별도 예시 표시 없이 일반 항목처럼 관리하며 AI 결과로 꾸미지 않습니다. 재실행해도 중복 생성하거나 수정한 예시·할 일 제목과 상태를 덮어쓰지 않습니다. 앱 시작 시 자동 생성하지 않고, 별도 저장소에는 `DATA_DIR=/원하는/경로 npm run seed:memo`로 넣습니다.

홈의 **할 일**에서 제목을 적고 Enter 또는 `+`로 추가합니다. 제목을 누르면 내용·기한을 수정할 수 있고, 체크하면 완료 탭으로 이동합니다. 완료 탭에서 체크를 풀면 되돌아옵니다. **전체 보기** 또는 사이드바 **할 일**은 `/tasks`를 엽니다. 홈은 PC 5개·모바일 3개를 먼저 보여주며, 1100px 이하에서는 AI 현황 다음·최근 메모 앞에 배치합니다. 저장 실패는 상태를 복원하고 재시도를 제공하며, 수정 충돌 때는 초안을 유지합니다. 할 일은 AI 없이 별도로 저장됩니다.

입력함의 **AI 요청**을 체크하면 템플릿 선택·추가 요청·요청문 미리보기를 볼 수 있습니다. 체크한 뒤 **저장하고 AI 요청**를 누르면 원본·당시 템플릿·입력·요청문과 작업을 함께 저장하고, AI 완료를 기다리지 않고 저장을 확인합니다. 저장 안내의 **요청 보기**나 사이드바 **AI 요청**에서 **대기 중 / 처리 중 / 결과 준비됨 / 처리 실패**를 확인합니다. 실행기가 미설정이면 원본과 요청문은 남고 **연결 필요**로 표시합니다.

상세의 **AI 결과**에서 안전한 Markdown 텍스트·출처·**Markdown 복사**와 접힌 **요청 당시 입력·프롬프트 / 이전 요청**을 확인합니다. **현재 메모로 다시 요청**은 현재 저장된 원문과 처음 보관한 템플릿 사본·추가 지시로 새 작업을 만들고, **실패한 요청 그대로 재시도**는 실패한 작업의 입력·프롬프트 사본을 유지합니다. 원본을 고치면 이전 결과에 **이전 내용 기준**이 표시됩니다. 결과는 원문·첨부·생성일·최종 수정일을 바꾸지 않으며 자동으로 페이지나 할 일이 되지 않습니다. 이전에 보관한 요청과 예시 요청은 자동 실행하지 않습니다.

선택한 완료 결과의 **결과를 페이지로 정리**를 누르면 결과와 출처를 편집 가능한 페이지에 담습니다. 기본은 **새 페이지**이며 기존 페이지에 추가하거나 상위 페이지를 골라 새 하위 페이지로 만들 수도 있습니다. 맨 앞 `#` 제목을 새 페이지 제목으로 제안하고 같은 제목은 본문에 반복하지 않습니다. 원본 메모는 정리 완료로 보관하고 출처는 페이지 정보에 남깁니다. 원문 내용·첨부는 추가로 선택하며 본문에 메모 카드나 태그를 자동으로 넣지 않습니다. 담기를 누를 때 Markdown을 제목·목록·표·코드·Mermaid 블록으로 변환하고, 페이지는 블록 JSON으로 저장합니다. 열린 페이지에서 바로 고치고 문서 전체를 하나의 **Markdown 보기 / Markdown 복사**로 옮길 수 있습니다. 페이지 수정은 원본 메모·요청 사본·AI 결과를 바꾸지 않습니다. 응답 유실 뒤 **같은 요청 다시 확인**은 제출 당시 결과·대상·UUID를 유지해 중복 생성을 막습니다.

페이지 도구의 **AI 요청**은 저장된 페이지 전체를 기본 입력으로 사용합니다. 편집 가능한 블록을 골라 요청 범위를 줄일 수도 있습니다. 요청 당시 제목·블록 문서·버전·선택과 템플릿·추가 지시를 사본으로 고정하고, 미저장·충돌·초안 복구 상태에서는 먼저 저장 문제를 해결합니다. 참조 대상 본문·첨부 바이트를 자동으로 보내지 않으며 페이지 입력은 64,000자까지입니다. AI 실행 중에는 페이지를 계속 편집할 수 있고 결과가 자동으로 본문을 바꾸지 않습니다.

완료 결과는 **본문 아래 추가 / 선택한 블록 교체 / 새 하위 페이지**로 명시적으로 반영합니다. 기본은 본문 아래 추가이며 교체는 선택한 블록으로 요청했고 요청 후 페이지 버전이 바뀌지 않았을 때만 가능합니다. 추가·교체의 **AI 반영 되돌리기**는 반영 직전의 저장 문서·제목을 새 버전으로 복원하며 이후 편집이 있으면 덮어쓰지 않고 멈춥니다. 새 하위 페이지는 그 페이지를 휴지통으로 옮겨 되돌립니다. 요청·반영·되돌리기의 UUID와 최초 요청문은 브라우저에 보존하고 응답 유실·페이지 이동·새로고침 뒤 **같은 요청 다시 확인**으로 확인합니다. 확인 대기 중에는 새 AI 제출을 막으며 반영·되돌리기를 확인 중일 때는 해당 페이지 편집도 잠급니다. 확인된 실패는 **확인된 실패 닫기**로 해제합니다. 자세한 계약은 [페이지 AI](CURRENT_IMPLEMENTATION.md#페이지-ai)를 따릅니다.

주제로 조사하려면 메모 본문에 `N100에서 SQLite FTS5를 쓰는 장단점`처럼 적고 **AI 요청 → 키워드 리서치 → 저장하고 AI 요청**를 선택합니다. 원본 저장 후 검색·본문 수집·정리가 비동기로 진행되며 **AI 요청** 탭(`/memo?view=ai`)의 상세에서 결과·이력·확인한 출처를 봅니다. URL이 있으면 주제 검색보다 URL 본문 하나를 읽는 경로가 우선합니다. URL 없는 리서치에는 비어 있지 않은 주제 글과 리서치 템플릿 선택이 필요합니다. 자유 요청은 검색하지 않습니다. 템플릿 없는 직접 요청은 URL이 있으면 URL 리서치, 없으면 자유 요청입니다.

URL 리서치는 공개 HTTP·HTTPS 본문을 수집하고, 키워드 리서치는 검색 가능한 Devin 실행기에서 후보를 찾은 뒤 앱이 본문을 확인합니다. HTTP 게이트웨이는 URL 리서치만 지원합니다. 검색 미지원·확인한 본문 없음은 원본을 보존한 한국어 실패 안내로 남으며 URL이나 주제를 고쳐 명시적으로 다시 요청합니다. 첨부 바이트는 전송하지 않고 첨부만 있는 요청은 지원하지 않습니다. 자동 유료 재시도와 다른 제공자로의 자동 전환은 없습니다. 설정과 제한은 아래 **AI 실행기 설정**과 [현재 규격](CURRENT_IMPLEMENTATION.md#ai-요청-실행)을 따릅니다.

사이드바 **프롬프트**(`/prompts`)에서 기본 템플릿 **URL 리서치·키워드 리서치·생각 정리·여행 계획**을 편집·추가·복제·보관할 수 있습니다. 종류 이름은 **리서치 / 자유 요청**입니다. 템플릿은 **서버 SQLite에 저장**되어 같은 서버에 접속한 PC·휴대폰에서 사용할 수 있습니다. 기존 라이브러리에는 `research-keyword`가 없고 템플릿이 200개 미만일 때만 추가하며 수정·보관·이력은 유지합니다. 가득 찬 라이브러리는 기존 템플릿을 리서치 종류로 고쳐 사용할 수 있습니다. 수정 충돌이 나면 초안을 유지합니다.

이전 템플릿은 **브라우저 템플릿 가져오기**로 옮깁니다. 원본은 그대로 남기며 서버의 수정 내용과 충돌하면 복사본을 만듭니다. 상단 **가져오기·내보내기**에서 현재 템플릿을 JSON으로 옮길 수도 있습니다.

리서치와 일반 메모는 각각 마지막 템플릿 선택을 기억합니다. 모바일 템플릿 편집은 본문부터 시작하고 이름·종류·설명은 **템플릿 설정**을 펼쳐 고칩니다. 전용 하단 버튼으로 미리보기와 저장을 할 수 있습니다.

## 개인 계정

로컬 개발은 기본 인증 없이 동작합니다. 공개 운영 전에 `npm run auth:setup`으로 비밀번호와 Google Authenticator를 등록하세요. **설정 → 보안**에서 로그인한 브라우저를 확인하고 로그아웃할 수 있습니다. 기억한 브라우저는 최대 30일, 미사용 7일 뒤 다시 인증합니다. 인증 만료 시 로컬 글·첨부·전송 대기 UUID를 보존하며 재로그인 후 동기화를 이어갑니다. [최초 설정·복구·배포 경계](docs/AUTHENTICATION.md).

## 로컬 실행

Node.js 24 이상이 필요합니다.

```bash
npm install
npm run dev
```

브라우저에서 <http://127.0.0.1:5173>을 엽니다. 개발 서버는 프런트엔드를 5173번, 저장 API를 8787번 포트에서 실행합니다.

Vite의 `/api` 프록시는 브라우저의 Host를 유지합니다(`changeOrigin: false`). 따라서 로컬 저장 요청은 같은 출처로 검사되며, 외부 출처의 변경 요청은 개인 API에서 거절합니다.
개발 중 서버 파일이 바뀌면 저장 API 프로세스도 자동으로 다시 시작합니다.

```bash
npm test       # SQLite·API 저장·버전 충돌 테스트
npm run qa     # Chrome으로 입력함·페이지·할 일의 실제 동작 점검
npm run build  # 배포용 화면 생성
npm start      # 빌드된 화면과 API 실행, 127.0.0.1:8787
```

`npm run qa`는 별도의 임시 저장소를 사용하고 종료 후 지웁니다. macOS에서는 설치된 Chrome을 사용합니다. 다른 OS에서는 `CHROME_BIN`에 Chrome 실행 파일 경로를 지정하세요.

계획·페이지 도구·수정 이력·자동 백업의 대상 Chrome QA는 `npm run qa:features`입니다. 임시 저장소를 쓰며 실제 AI 제공자는 호출하지 않습니다.

Google 일정 지도는 `npm run qa:google-map`으로 빌드와 대상 QA를 실행합니다. 임시 DB·가짜 Google SDK로 개인 지도 연동과 정적 공개 뷰를 확인합니다. `npm run qa:static-plan`은 활동·시간·이미지 참조·공유·모바일을 확인합니다. SDK 경계 QA와 실제 Google 검증은 범위가 다르며 결과·제한은 [검증 기록](.omo/evidence/google-map.md)을 따릅니다.

AI 요청 모니터만 확인하려면 빌드 후 `node scripts/qa-ai-activity.mjs`를 실행합니다. 임시 저장소·로컬 HTTP 실행기로 확인하며 실제 제공자를 호출하지 않습니다. 기존 캡처를 유지하려면 `QA_AI_ACTIVITY_SCREENSHOTS=0`을 앞에 붙입니다.

통합검색만 확인하려면 다음 명령을 사용합니다. 테스트·QA·벤치마크는 실제 `data/` 대신 임시 저장소를 사용합니다.

```bash
node --test test/search.test.mjs test/search-api.test.mjs
npm run build && QA_SEARCH_SCREENSHOTS=0 node scripts/qa-search.mjs
node scripts/benchmark-search.mjs
```

벤치마크는 1만·10만 건의 임시 혼합 자료를 생성·정리합니다. 기록된 결과는 Apple M1 Max의 저장소 호출이며 N100·HTTP·브라우저 지연 실측은 아닙니다. 상세 수치와 남은 조합 입력 제한은 [현재 구현 규격](CURRENT_IMPLEMENTATION.md#통합검색)을 따릅니다.

## AI 실행기 설정

기본 실행 프로필은 **Hive**입니다. 키·모델이 없으면 실행되지 않습니다. `.env.example`과 Compose는 `AI_RUNNER_KIND=disabled`로 모든 실행을 꺼두므로 설정 후 `hive`로 바꾸세요. **설정 → AI**에서 기본 실행기·모델을 저장하고 요청 옆에서 Hive 또는 Devin을 선택합니다. 키는 서버에만 보관하며 상주 로컬 LLM은 필요하지 않습니다.

- **Hive:** `HIVE_API_KEY`, `HIVE_BASE_URL`, `HIVE_MODEL`을 서버에 설정합니다. Chat Completions/SSE로 직접 호출합니다. URL 리서치는 지원하며 URL 없는 키워드 검색은 Devin이 필요합니다. [설정·운영 가이드](docs/AI_CONFIGURATION.md).

- **설치형 Devin:** 서버를 실행하는 환경에 Devin CLI를 설치·인증한 뒤 아래처럼 시작합니다. `AI_DEVIN_BIN`은 선택적 실행 파일 경로이고 기본은 `PATH`의 `devin`, `AI_DEVIN_MODEL`의 기본은 `swe-2-high`입니다. 앱은 이 모델값을 CLI에 명시적으로 전달하며 결과에는 실행기와 작업의 모델을 구분해 표시합니다. 앱이 CLI를 설치하거나 로그인하지 않습니다.

```bash
AI_RUNNER_KIND=devin AI_DEVIN_MODEL=swe-2-high npm run dev
```

- **HTTP 게이트웨이:** `AI_RUNNER_KIND=http`와 `AI_RUNNER_URL`을 설정합니다. 이전 설정과의 호환으로 KIND 없이 URL만 설정해도 이 경로를 선택합니다. URL은 HTTPS 또는 루프백 HTTP이고, 선택적 `AI_RUNNER_TOKEN`은 서버의 Bearer 인증값입니다. `AI_RUNNER_LABEL`은 표시 이름, `AI_RUNNER_MODE=test`는 테스트 응답 표시입니다. 이 앱의 JSON 계약을 번역하는 게이트웨이가 필요하며 OpenAI·Anthropic의 직접 API 주소를 넣는 방식은 지원하지 않습니다. 요청·응답 규격은 [실행기 계약](CURRENT_IMPLEMENTATION.md#실행기-설정과-경계)에 있습니다.

Devin은 요청문과 설정만 있는 임시 작업 공간과 최소 환경 변수를 사용합니다. 키워드 검색 단계는 `web_search`만 허용하고 요약 단계는 웹 검색·파일·셸·Fetch·MCP·하위 에이전트를 금지합니다. 다른 에이전트 설정 가져오기와 자동 업데이트도 끕니다. 키워드 작업의 검색·요약은 순차 CLI 실행 2회이며 수집까지 같은 작업의 120초 한도를 공유합니다. 검색 export 검증은 호출 후 검사이며 제공자 과금 상한은 아닙니다. **OS 샌드박스는 아니며** 설치된 CLI의 인증과 외부 제공자가 존재합니다. Mac/Linux에서는 소유한 프로세스 그룹을 종료하고 실제 종료·임시 공간 정리를 기다립니다. HTTP 중단과 로컬 프로세스 종료가 제공자의 진행 중인 작업·과금 취소를 보장하지는 않습니다.

일반 테스트는 외부 AI 제공자를 호출하지 않습니다. Node 테스트는 임시 DB·HTTP 응답·가짜 CLI를 사용하고, 일반 Chrome QA의 서버는 AI 실행기를 강제로 끕니다. 설정된 결과 화면은 임시 로컬 게이트웨이로 별도 확인합니다.

```bash
npm test
npm run build
QA_AI_SCREENSHOTS=0 node scripts/qa-ai.mjs  # 임시 게이트웨이, 실제 AI 호출 없음
node scripts/qa-keyword-research.mjs       # 빌드 후 임시 DB·HTTP fixture, 실제 AI 호출 없음
node --test test/page-lifecycle.test.mjs test/page-ai-api.test.mjs test/page-document-visibility.test.mjs
node scripts/qa-page-ai.mjs                # 빌드 후 임시 DB·로컬 게이트웨이, 실제 AI 호출 없음
```

**실제 호출은 별도 선택입니다.** 다음 명령은 설치·인증된 Devin에 합성 텍스트의 앱 작업 하나를 요청하므로 외부 계정 사용량과 요금이 발생할 수 있습니다. 임시 저장소를 쓰고 자유 요청 결과를 `.omo/evidence/ai-devin-smoke.json`에 기록합니다. 선택적 설정은 `DEVIN_BIN`·`DEVIN_SMOKE_MODEL`이며 일반 테스트·QA에는 포함되지 않습니다.

```bash
node scripts/ai-devin-smoke.mjs
```

공개 SQLite 주제의 키워드 작업을 선택하려면 다음처럼 실행합니다. 호출할 때마다 합성 키워드 작업 하나를 만들고 검색·요약 CLI 실행 2회를 거쳐 `.omo/evidence/keyword-devin-smoke.json`에 기록합니다. 이 작업 수는 제공자의 내부 요청 수나 정확한 비용을 뜻하지 않습니다. 이전 키워드 확장의 기록에는 최초 검색 probe와 키워드 작업 2개(두 번째는 smoke 입력 조건 수정)가 포함됩니다. 현재 메모 정리·페이지 AI 작업의 실호출 기록은 아니며 전체 실호출이 한 번이었다는 의미도 아닙니다.

```bash
DEVIN_SMOKE_RESEARCH=1 DEVIN_BIN=/installed/path/devin node scripts/ai-devin-smoke.mjs
```

## 데이터 백업과 복원

`data/`의 DB와 등록된 첨부를 함께 백업합니다. 서버가 켜져 있어도 SQLite 스냅샷을 만들 수 있습니다. 원본 자료는 바꾸지 않으며, 완료된 백업만 지정한 이름으로 나타납니다. 대상의 **상위 디렉터리는 먼저 만들어 두고**, 백업·복원 대상 자체는 아직 없어야 합니다.

```bash
mkdir -p backups
npm run backup -- create ./data ./backups/2026-09-30
npm run backup -- verify ./backups/2026-09-30
npm run backup -- restore ./backups/2026-09-30 ./restored-data
```

복원은 새 `restored-data/`를 만들며 기존 `data/`를 덮어쓰지 않습니다. 확인 후 서버를 멈추고 배포 설정의 데이터 경로를 복원 디렉터리로 바꾸거나, 별도 검증 인스턴스에서 열어보세요. 백업에는 서버 SQLite의 페이지·메모·작업·프롬프트·휴지통과 DB가 참조하는 첨부가 포함됩니다. 브라우저의 미저장 초안·최근 선택·실행기 인증 정보·Compose 설정은 포함되지 않습니다. 사이드바 **백업**(`/backups`)에서 **지금 백업**을 실행하거나 자동 실행을 켤 수 있습니다. 자동 실행은 처음에는 꺼져 있으며 기본 시각은 매일 **04:00 한국시간**, 보관 수는 **7개**(1~60개)입니다. 다음 실행·최근 성공·실패와 최근 실행을 표시하고 검증된 새 백업을 만든 뒤 관리 중인 이전 사본만 정리합니다. 다른 디스크/원격 보관은 별도로 구성합니다. [백업 형식](docs/superpowers/specs/2026-09-30-data-backup-design.md)을 참고하세요.

자동 백업은 `BACKUP_DIR`에 저장합니다. 지정하지 않으면 실제 데이터 경로의 상위 디렉터리에 `<데이터 폴더 이름>-backups`를 만들며 기본은 `data-backups/`입니다. 데이터 폴더와 같은 경로이거나 두 폴더 중 하나가 다른 쪽을 포함하는 경로, 심볼릭 링크 경로에는 저장하지 않습니다. 예약 설정과 실행 목록은 백업 폴더의 `automatic-backups.json`에 있으며 서버 DB 백업과 별도로 보존하세요. 수정본·페이지 템플릿의 파일은 개인 복구용으로 유지하지만 공유 링크는 현재 본문에 놓은 첨부만 제공합니다.

## Docker 실행

```bash
docker compose up --build -d
```

브라우저에서 <http://127.0.0.1:8787>을 엽니다. 데이터는 이 디렉터리의 `data/`, 자동 백업은 `backups/`에 남으므로 이미지를 다시 빌드해도 유지됩니다. 개인 서비스만 `BACKUP_DIR=/backups`와 별도 `./backups:/backups` 볼륨을 사용하며 공유 서비스에는 백업 경로를 마운트하지 않습니다. Docker Compose는 기본적으로 PC의 루프백 주소에만 바인딩합니다.

기본 이미지는 서버·AI 작업자를 포함하지만 Devin/OpenCode CLI나 인증을 포함하지 않습니다. Compose는 개인 서버에 AI 환경 변수를 전달하며 실행은 기본적으로 꺼져 있습니다. AI를 쓰려면 대상 환경에 실행기·인증·서버 설정을 별도로 준비해야 합니다. [AI 설정 안내](docs/AI_CONFIGURATION.md)를 참고하세요. 서버 프로세스·작업자는 한 개로 운영합니다.

UI·저장·AI 실행 흐름은 로컬에서 개발하고 나중에 미니PC로 옮길 수 있습니다. 별도 읽기 전용 공유 서버는 로컬에서 실행할 수 있고, 본인 인증과 실제 공개 도메인 연결은 후속 개발 범위입니다. 이전 전에 N100 대상인 `linux/amd64` Docker 기동을 확인하고, 서버를 멈춰 DB와 첨부를 함께 복사하거나 일관된 백업을 복원합니다. 저장된 프롬프트와 수정본도 서버 DB에 포함됩니다. 이전 브라우저 템플릿은 먼저 가져오고, 미저장 초안은 저장하거나 복사해 두세요. 최근 선택·미저장 초안은 브라우저 주소에 속하며 서버 복사에 포함되지 않습니다. 운영 네트워크·설치형 에이전트 실행은 대상 환경에서 확인합니다. 자세한 절차는 [기술 아키텍처](TECH_ARCHITECTURE.md#로컬-개발에서-미니pc로-이동)를 따릅니다.

현재 버전은 **로컬 개인 입력함·통합검색·페이지 편집기·메모 정리 완료와 복귀·페이지 출처·할 일·프롬프트 관리·선택적 메모/페이지 AI·결과 반영과 되돌리기·일정과 지도·페이지 복제/템플릿/직접 첨부/블록 이동·수정 이력·자동 백업·로컬 읽기 전용 페이지 공유**입니다. 개인 블록 댓글, 오프라인 읽기 ZIP, 선택한 AI 결과의 할 일 등록, 완료 결과/Task/OCR 검색, 프롬프트 수정 이력도 구현했습니다. OCR은 별도 이미지 API 게이트웨이를 연결해야 실제 인식할 수 있습니다. 일반 첨부 이해·실제 외부 주소 연결·방문자 댓글·원격 백업은 아직 없습니다. 현재 API에는 인증이 없으므로 외부 공개 전에 계획 문서의 개인 접근 및 공유 진입점을 구현해야 합니다.

## 데이터 및 제한

- 메모는 10,000자까지 저장합니다.
- 할 일 제목은 500자, 선택적 기한은 한국 날짜 기준의 `YYYY-MM-DD`입니다.
- 파일은 하나당 25MB, 한 번에 8개, 요청당 총 100MB까지 받습니다. 100MB는 하루 사용량이 아닌 **한 번 저장 요청의 상한**입니다.
- SQLite 파일은 `data/storage.sqlite`, 첨부 원본은 `data/blobs/`에 저장합니다. 운영 중에는 위 백업 도구를 사용하거나 서버를 멈춘 뒤 `data/` 전체를 함께 복사하세요.
- 페이지는 한 문서당 1MB·1,000블록까지 저장합니다. 제목은 160자까지 입력할 수 있습니다.
- AI는 한 번에 작업 하나, 작업 전체 120초·응답 256KiB까지 처리합니다. URL 하나의 수집은 10초·리다이렉트 3회·2MiB·추출 텍스트 50,000자까지이며 각 주소와 DNS 응답을 검사하고 연결 주소를 고정합니다. 키워드는 검색 1회(질의 240자·후보 최대 5개), 후보 순차 수집·서로 다른 최종 URL 최대 3개, 본문당 16,666자·합계 49,998자까지 사용합니다. 본문이 하나도 없으면 요약하지 않고 실패하며 일부만 확보했으면 결과에 수집 안내를 붙입니다. 실패·중단을 자동으로 재실행하지 않습니다.

## 이름으로 남기는 공유 댓글

개인 페이지의 **공유 → 방문자 댓글 허용**을 켜면 공유 링크에서 이름만 입력해 블록 댓글/답글을 남길 수 있습니다. 이름은 본인 인증이 아닌 표시 이름입니다. 개인 화면의 **댓글 → 공유 댓글**에서 확인·답글·해결·삭제를 관리합니다. 개인 댓글은 계속 비공개이며, 같은 페이지의 새 링크에서는 기존 공유 대화가 이어집니다. 패널의 **댓글 새로고침**으로 최신 답글을 확인할 수 있고 이름·작성 중인 초안은 유지합니다.

공유 웹은 개인 DB를 읽기 전용으로 유지하고 댓글 전용 Unix socket을 통해 저장합니다. 기본 경로는 `DATA_DIR/share-comments.sock`; Compose는 `COMMENT_SOCKET_PATH=/run/leneu/share-comments.sock`과 `comment-ipc` 볼륨을 사용합니다. 로컬 개발은 개인 서버를 먼저 켜고 `npm run build` 후 `npm run start:public`을 실행합니다. 도메인을 사용하면 `PUBLIC_SHARE_ORIGIN=https://share.example.com`을 개인/공유 프로세스 양쪽에 동일하게 설정합니다. 개인 주소는 Tailscale로만 접근하게 구성하며 DNS/Tunnel 실제 설정은 별도 운영 단계입니다.

검증: `node scripts/qa-shared-comments.mjs`는 임시 DB에서 방문자 이름·작성자 답글·개인/공유 분리·링크 설정·PC/모바일을 확인합니다.

### 개인 API 출처 보호

개인 서버는 기본적으로 `localhost`, `127.0.0.1`, `[::1]` Host만 받습니다. 변경 요청의 Origin은 요청 주소 또는 `PRIVATE_ALLOWED_ORIGINS`의 정확한 출처와 같아야 하며 `Sec-Fetch-Site: cross-site`는 거절합니다. 헤더 없는 기존 로컬 CLI 요청은 유지합니다. Vite의 같은 출처 API 프록시도 유지합니다. 전달된 `X-Forwarded-Host`·`X-Forwarded-Proto`를 허용 근거로 사용하지 않습니다.

Tailscale Serve 등 개인 HTTPS 프록시를 사용하기 전 Git에서 제외한 `.env`에 `PRIVATE_ALLOWED_ORIGINS=https://본인의-개인-주소`를 설정하고 개인 프로세스를 재시작합니다. 여러 출처는 쉼표로 구분하며 경로·마지막 슬래시·와일드카드는 넣지 않습니다. Compose는 이 설정을 개인 서비스에만 전달합니다. 이 검사는 계정 인증을 대신하지 않으므로 기존 루프백·본인만 허용한 Tailnet 경계를 유지합니다.

### 일지와 독립 HTML 호스팅 (2026-10-05)

`/journal`은 날짜별 타임박싱·할 일·회고를 기존 기기 저장/전송 대기/충돌 보존 구조로 서버와 동기화한다. 한국시간24시간 표시를 유지하며 할 일을 시간표로 드래그해 연결하고 주간·월간·미이행 되짚기를 제공한다. 예전 브라우저 일지 원본은 보존한 채 이관한다. 독립 디자인 프리뷰는 별도 샘플 저장소를 유지한다.

`/hosting`은 별도 제작 HTML/CSS/JS 사이트의 폴더 등록·이름 수정·주소 복사·공개/중지를 관리한다. 설정 → 작업 공간 → 웹 호스팅에서 진입한다. 사이트 파일은 개인 앱과 다른 origin의8792 정적 프로세스가 제공한다. `npm run dev`에 이 프로세스를 포함하며, 단독 실행은 `npm run start:sites`. 로컬 샘플 `http://127.0.0.1:8792/mathematics/`는 원본에서 PDF를 제외한 사본이다. [호스팅 사용·배포·백업 안내](docs/STATIC_HOSTING.md)를 참고한다.

### OpenCode 모델 선택

**설정 → AI → OpenCode CLI**에서 모델 목록과 기본 모델을 관리한다. 초기에는 무료로 확인된 Zen 텍스트 모델 11개만 등록하며 목록의 추가·수정·삭제·사용 여부 변경과 공식 목록 갱신을 지원한다. 실제 CLI 실행은 서버 설치·인증과 명시 활성화가 필요하다. [설정·Oracle 준비 절차](docs/AI_CONFIGURATION.md#oracle의-opencode-cli-준비)를 참고한다.
