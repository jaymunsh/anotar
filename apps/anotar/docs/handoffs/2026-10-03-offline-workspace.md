# 6.1-Sol xhigh 실행 인계 — leneu 오프라인 작업 공간

작성: 2026-10-03

## 설정

실행할 세션에서 모델 **GPT-6.1-Sol**, reasoning **xhigh**를 선택한다. 문서에 모델명을 쓰는 것만으로 현재 세션 모델이 변경되지는 않는다. 별도 모델/에이전트를 자동 실행해 둔 상태가 아니다.

현재 작업은 **설계지시서·실행 계획 작성까지**다. 앱 제품 코드·DB·서버 설정은 이 인계 작성으로 변경하지 않았다. 사용자가 아래 지시문으로 실행을 요청하면 이어서 진행한다.

## 읽는 순서

1. repo의 `AGENTS.md`, `CURRENT_IMPLEMENTATION.md`, `PRODUCT.md`, `DESIGN.md`.
2. [오프라인·온라인 설계지시서](../superpowers/specs/2026-10-03-offline-workspace-design.md).
3. [12개 Task 실행 계획](../superpowers/plans/2026-10-03-offline-workspace.md).
4. 존재하면 `.omo/evidence/offline-workspace/PROGRESS.md` — 이미 완료한 작업을 반복하지 않기.

## 확정 방향

- 모바일에서 급히 저장하는 메모가 첫 실사용 목표다. PC에서는 정리·문서 편집을 이어간다.
- IndexedDB 우선 저장 + 불변 outbox + 단일 서버 SQLite 동기화.
- v1 페이지는 전체 JSON 버전 검사와 충돌 사본 보존. **Yjs/자동 병합은 후속 실험**, v1 작업에 섞지 않는다.
- A 메모/Task/앱 실행 → B 보관 페이지/편집 → C 정리/AI/복원·운영 순서.
- 단일 모델 순차 구현이 기본이다. 다중 에이전트는 사용자/적용되는 필수 skill 지시가 있을 때만 사용한다.
- 원격 운영은 개인 HTTPS 접근 제어 검증 후. 현재 개인 API를 인터넷에 노출하지 않는다.

다음 설계와 실행 계획을 기준으로 Stage A부터 순서대로 구현해:

단계마다 같은 승인을 반복해서 묻지 말고, 실제 실패를 해결한 뒤 다음 단계로 넘어가.

컨텍스트가 바뀌어도 그 위치부터 계속해. 설계만 다시 쓰거나 UI 시안으로 끝내지 마.
로컬에서 가능한 Stage A/B/C와 자동 검증을 마무리해.
실기기나 원격 서버가 없으면 해당 검증만 미실시로 구분하고 수동 확인 절차를 남겨.
배포나 커밋은 별도 요청 전에는 하지 마.

## 첫 실행에서 남길 기록

- 실제 cwd, git status, Node/패키지 버전, 이미 실행 중인 서비스/점유 포트.
- 기존 자동 저장/첨부/공유/AI 경로의 보존 목록.
- 적용한 schema 변경과 최초 실패 테스트 로그.
- 사용자 DB를 수정하지 않았다는 확인.

## 금지하는 완료 보고

- PWA 아이콘 설치만 하고 오프라인 완료라고 하기.
- localStorage 초안만 남기고 동기화 완료라고 하기.
- HTTP timeout마다 새 UUID로 요청해서 중복 만들기.
- 같은 페이지의 나중 도착한 전체 사본으로 조용히 덮어쓰기.
- 자동화 브라우저 성공을 iPhone/Android 설치앱·OS 강제종료 검증으로 확대하기.
- 사용자의 실제 첨부/페이지를 재시드해서 데모 화면만 맞추기.

## 검토 포인트

사용자가 검토할 핵심은 세 가지다: v1은 안전한 충돌 선택 방식이라는 점, 모바일 PWA를 닫은 동안의 상시 동기화를 보장하지 않는 점, 최초 온라인 준비/선택 자료 보관이 필요하다는 점. 나머지 기술 선택·한도·테스트 기준은 설계에 고정했다.
