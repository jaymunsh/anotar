네트워크와 접속

  • 들어오는 웹 요청은 전부 Cloudflare tunnel. 서버의 anotar-tunnel.service(cloudflared, systemd DynamicUser, 토큰은 LoadCredential 파일로 전달)가 Cloudflare로 나가는 연결을 열어 두고, 요청은 그 연결로 들어옵니다. 그래서 서버 방화벽에서 80/443을 열지 않습니다. TLS 인증서도 Cloudflare가 처리합니다.
  • 앱 포트는 모두 127.0.0.1에만 묶임. 8787·8790·8792는 docker-proxy가 loopback에만, harukan 8794는 network_mode: host로 loopback에만 엽니다.
  • 방화벽. 호스트 iptables는 established·ICMP·loopback·22번(SSH)만 받고 나머지는 거부합니다. OCI 보안 목록도 같은 원칙(22만).
  • SSH. 키 로그인만(PasswordAuthentication no). 키 파일 경로·사용자·IP는 로컬 .env.oracle-server(0600, git 제외)에만 있습니다. root 로그인은 막음(/etc/ssh/sshd_config.d/60-no-root.conf, 2026-10-20).
  • DNS. 도메인 leneu.store는 가비아에서 샀고 네임서버만 Cloudflare(Free 플랜)로 돌렸습니다.

자동 배포의 재시도 규칙 (oracle-poll.py, 두 앱 같음)

  • GitHub API로 main의 해당 workflow(oracle.yml / harukan.yml) 최신 성공 실행을 봅니다. 서버는 GitHub을 보러 갈 뿐이라 들어오는 연결·배포 키가 없습니다.
  • 이미 배포된 커밋이면 아무것도 안 합니다("Verified release already deployed").
  • 새 커밋이면 최대 3번 시도하고, 시도 사이 대기는 5분 → 15분 → 1시간. 3번 다 실패하면 새 커밋이 오거나 사람이 고칠 때까지 멈춥니다. 상태 파일 /var/lib/<앱>-deploy/state.json.
  • 종료 코드 65(그 사이 main이 바뀜)·75(다른 배포 진행 중)는 실패로 세지 않고 다음 주기에 다시 봅니다.
  • 성공하면 텔레그램 "🟢 완료 · <앱> 배포"(커밋과 제목). 실패하면 "배포 실패, 이전 버전 유지" 한 번, 다음 성공에 "복구" 한 번. GitHub 조회가 3번 연속 안 되면 경고.

백업에 없는 것

  • 서버 .env의 AUTH_SECRET_KEY. 로그인용 TOTP 비밀값은 이 키로 암호화돼 DB에 들어갑니다. 백업만 있고 키가 없으면 복원한 DB로 로그인할 수 없습니다. 키는 백업과 따로, 서버 밖에도 보관합니다.
  • 정적 호스팅 사이트 파일. DB와 다른 폴더에 있고 따로 백업하지 않습니다.
  • 공유 서버가 읽는 공개 폴더(공유 스냅샷). 개인 DB에서 다시 만들어지는 사본입니다.

보안 패치와 자동 재부팅

  1. 설치: Ubuntu unattended-upgrades가 매일(apt-daily-upgrade, 약 15:00 KST) noble-security 패치를 깝니다. 대부분은 재부팅 없이 끝나고 아무 알림도 없습니다.
  2. 재부팅이 필요한 패치(커널 등): /run/reboot-required가 생기고, 자동 재부팅 설정(52leneu-reboot)에 따라 다음 03:50 KST 재부팅이 예약됩니다(/run/systemd/shutdown/scheduled). 03:50이면 1–2분 안에 올라와 04:00 anotar 백업과 겹치지 않습니다.
  3. 감지: leneu-service-watch가 5분마다 두 파일을 읽어 /var/lib/leneu-host/status.json에 적고, 텔레그램으로 바로 알립니다. AI나 외부 조회는 없습니다.
  4. 사용자 안내: harukan이 그 파일을 읽기 전용으로 읽어, 재부팅 1시간 전부터 로그인한 사용자 화면에 붉은 안내 한 줄을 보여 줍니다(X로 12시간 숨김, 설정 화면은 항상). anotar는 본인만 쓰므로 안내하지 않습니다.
  5. 재부팅 뒤: 컨테이너(restart: unless-stopped)·tunnel·타이머가 저절로 다시 뜨고, 다음 감시에서 🟢 복구 알림. 서버가 안 올라오면 healthchecks oracle-watch가 15분 뒤 알립니다.
  6. 그 밖의 업데이트(보안 아닌 noble-updates, Docker 저장소)는 자동이 아닙니다. 가끔 sudo apt-get update && sudo apt-get upgrade.

기록: 설치 /var/log/apt/history.log·/var/log/unattended-upgrades/, 재부팅 last reboot, 알림은 텔레그램 자체가 기록입니다. 2026-10-20에 밀린 커널(6.17 → 7.0)과 일반 업데이트를 손으로 적용하고 재부팅했습니다.

비용: 0원을 지키는 장치

계정은 PAYG라 실수하면 돈이 나갈 수 있습니다. 그래서 여러 겹으로 막습니다. 어느 것도 "결제를 원천 차단"하지는 않는다는 점이 중요합니다.

  1. 할당량 정책 leneu-free-compute-storage. 컴퓨트·블록 스토리지·오토스케일링을 테넌시 전체 0으로 막고, 오사카 AD-1에만 A1 2 OCPU / 12GB, 블록 스토리지 200GB, 볼륨 백업 5개를 허용합니다. 지금 A1은 2/2, 12/12를 다 써서 더 만들 수 없습니다.
  2. 할당량 정책 leneu-unused-services-disabled. Database·Load Balancer·File Storage·Object Storage를 0으로.
  3. 예산 leneu-zero-cost-watch. 월 예산 1, 실제 지출이 1%(0.01)를 넘으면 이메일. OCI가 24시간마다 평가하므로 늦을 수 있습니다.
  4. 자동 정지 (AUTO_STOP_ENABLED=true). cloud-watch가 양수 COST 행, 2 OCPU/12GB 초과, A1이 아닌 shape·오사카 밖 자원, 디스크 합계 200GB·10 VPU 초과·복제·자동 튜닝, 백업 5개 초과·다른 리전을 확인하면 이 VM만 OCI STOP(guard.py, 즉시 전원 차단). 미집계·조회 실패만으로는 끄지 않습니다. 실제 STOP은 모의 응답으로만 시험했습니다.
  5. 정기 보고로 사람이 하루 두 번 봅니다.
STOP 뒤 다시 켜면 그 달의 양수 비용 행 때문에 또 꺼질 수 있습니다. 원인을 정리하고 설정을 확인한 뒤 손으로 켭니다. Hive 같은 외부 AI 요금, 도메인 요금은 OCI 비용에 안 잡힙니다. 비용 자료는 OCI 집계가 늦어 실제 발생보다 늦게 보일 수 있습니다.

실제 사용(2026-10): A1 1대 × 2 OCPU × 켜진 시간. 10월은 약 1,488 OCPU시간 예상으로 무료 3,000의 절반 정도입니다.

repo의 infra/에는 다음 구성이 이미 들어 있지만, 운영 서버는 아직 예전 구성입니다.

지금 운영repo의 다음 구성 (infra/)
개인 앱 주소anotar.leneu.store → 8787 바로 (위키 데이터도 anotar가 줌)anotar.leneu.store → Caddy(8780) → anotar·memory
개인 스택anotar 컨테이너 하나infra/personal: anotar + memory + Caddy, Caddy만 열림
공유 스택개인 데이터 폴더를 읽기 전용으로 붙임infra/public: 개인이 내보낸 공개 폴더만 읽음
harukan그대로: apps/harukan/compose.oracle.yaml, tunnel이 8794로 바로

이번 출시 순서(요약): tunnel에 새 주소 추가 → harukan 백업·새 버전 → 서버 배포 스크립트 갱신 → 개인 DB 백업을 서버 밖으로 받기 → main merge(자동 배포) → 개인 DB 새로 시작 → 자동 백업 켜기. infra/personal 스택으로 옮기는 것은 그 뒤 단계입니다. 자세한 절차와 확인 항목은 비공개 문서에 있습니다.
