데이터의 기준은 어디에 있나요?

  • 기기에는 작성 중인 내용과 전송 대기 자료가 IndexedDB에 남습니다.
  • 서버에는 동기화된 기록이 SQLite와 첨부 파일로 보관됩니다.
  • 페이지 원본은 블록 JSON입니다. Markdown은 가져오기·내보내기 형식입니다.
  • 검색은 SQLite FTS5, AI 대기열은 DB에 저장합니다.

공유 서버가 할 수 있는 일

유효한 공유 토큰으로 현재 페이지와 직접 참조한 첨부를 읽습니다. 댓글을 허용한 링크에서는 이름 기반 댓글을 남길 수 있습니다.

공유 프로세스의 DB·첨부 마운트는 읽기 전용입니다. 댓글 쓰기는 전용 Unix socket을 통해 개인 프로세스에서 다시 검사합니다. 개인 API·업로드·AI·검색은 공유 서버에 등록하지 않습니다.

Oracle 한 대에, 진입점 세 개.

Ampere A1 · 2 OCPU / RAM 12GB · Ubuntu ARM64를 기준으로 한 배포안입니다. VM 생성·운영 알림 설치는 운영 기록에 확인되어 있으며 앱 배포·성능 측정은 아직 남았습니다.

별도로 제작한 HTML·CSS·JS 사이트

별도 HTML 사이트에는 anotar DB나 첨부 폴더를 마운트하지 않습니다. 사이트별 Node 프로세스 없이 파일을 제공하는 구성입니다.

배포 전 남은 연결

  • 개인 접근 제한: 추가 사설 접근이나 게이트웨이는 운영 선택 사항입니다. 비밀번호·TOTP 인증은 구현되어 있습니다. HTTPS·쿠키·Origin을 실제 도메인에서 검증해야 합니다.
  • 실제 운영: VM·SSH는 확인됐습니다. 앱 ARM64 이미지 실행, DNS·HTTPS, 실제 복원 검증이 필요합니다.
  • 독립 HTML: 별도 정적 서버8792와 관리 목록은 구현됐습니다. 실제 DNS·TLS·파일 볼륨 배포를 연결합니다.
  • 운영 확인: CPU·메모리·디스크·오류 상태를 측정하고 원격 백업을 연결합니다.

연결이 끊겨도 원문이 먼저 남습니다.

기기 저장 → 전송 대기 → 서버 반영 → 다른 기기 조회. 버전 충돌은 두 사본을 보존합니다.

구현됨

저장 흐름입력 → IndexedDB → Outbox → Sync API
ACK가 오면 전송 상태를 갱신합니다.
충돌이 생기면 두 사본을 보존하고 확인을 요청합니다.

기기 저장 완료와 서버 동기화 완료는 별도의 상태입니다.옆으로 넘겨 전체 구조를 확인하세요.

오프라인에서 사용할 수 있는 범위

  • 기기에 저장한 메모·할 일, 본문을 보관한 페이지를 읽고 수정합니다.
  • 정적 앱 셸은 Service Worker, 원문·작업 큐·첨부는 IndexedDB가 맡습니다.
  • 새 기기의 첫 접속과 아직 내려받지 않은 자료에는 온라인 연결이 필요합니다.
  • AI 요청은 기기에 대기할 수 있지만 실제 실행은 서버 연결 이후입니다.

자동으로 처리하지 않는 것

충돌 문서를 자동으로 합치거나 덮어쓰지 않습니다. 서버 식별자·복원 epoch가 달라지면 전송을 멈추고 복구 확인을 요구합니다.

공유·댓글·지도 생성·관리 쓰기는 온라인 작업입니다. Service Worker는 API 응답과 공개 공유를 캐시하지 않습니다. 기기 검색은 보관한 자료 범위이며 서버 전체 검색과 다릅니다. 실제 iOS/Android의 종료·저장소 정리·키보드 환경 검증은 별도로 필요합니다.

코드는 어디에서 시작하나요?

브라우저·개인 서버·공유 서버는 서로 다른 진입점을 사용합니다. 화면의 저장 호출 이름이 API처럼 보여도 실제 HTTP 전송은 동기화 엔진을 거칠 수 있습니다.

브라우저 부팅

  1. HTML과 화면 모드index.html이 저장한 화면 모드 또는 시스템 설정을 적용하고 src/main.tsx를 불러옵니다.
  2. 개인 인증 확인src/auth/AuthBoundary.tsx → src/auth/state.ts가 인증 상태와 기존 기기 바인딩을 확인합니다. 잠겨도 편집기·초안을 삭제하지 않습니다.
  3. 공통 작업 공간src/main.tsx의 App이 경로, 사이드바, 검색, 빠른 입력, 도크와 설정을 조립합니다. React Router 대신 자체 경로 이동을 사용합니다.
  4. 필요한 화면만 로딩src/pages/PageWorkspace.tsx → src/pages/PageEditor.tsx 순으로 문서를 엽니다. BlockNote·Mermaid는 편집 화면 진입 시 지연 로딩합니다.
  5. 기기 저장과 전송src/sync/runtime.ts가 workspace를 바인딩하고 src/sync/engine.ts를 시작합니다. 원문을 IndexedDB에 먼저 남긴 뒤 서버와 동기화합니다.

개인 서버 부팅

  1. 설정·경로 결정server/index.mjs가 DATA_DIR, blobs, dist, 개인 포트와 공유 origin을 정합니다. 기본 개인 주소는 127.0.0.1:8787입니다.
  2. SQLite 연결과 이관server/store.mjs의 openStore가 storage.sqlite를 열고 WAL·외래키·검색 함수를 등록합니다. 기능별 테이블을 같은 연결에 초기화합니다.
  3. 개인 서버 내부 작업자AI·OCR worker, 지도·북마크 서비스, 자동 백업 스케줄러와 공유 댓글 socket broker를 만듭니다. AI 추론 서버나 Redis는 따로 띄우지 않습니다.
  4. 요청 검사와 분기server/privateRequests.mjs의 Origin 검사 → server/auth/routes.mjs의 개인 API guard → sync/기능 API → dist 정적 화면 순서입니다.
  5. 공유 서버는 별도 시작server/public.mjs가 같은 DB를 readOnly로 열어 127.0.0.1:8790에서 토큰 페이지와 허용 파일만 제공합니다.

파일 지도와 수정 진입점

기능을 수정할 때 화면 → 공통 계약 → 서버 저장 순서로 따라가세요. 순수 shared 함수에는 네트워크·DB·환경 변수 의존성을 넣지 않습니다.

사용자 동작은 어떻게 처리되나요?

화면의 성공 표시, 서버 저장과 외부 실행을 구분하는 것이 이 서비스의 핵심입니다.

메모 하나 저장

  1. 입력창은 텍스트·URL·선택한 첨부와 최초 requestId를 유지합니다.
  2. src/sync/runtime.ts의 workspaceFetch가 Capture·Blob·outbox를 기기에 저장합니다. 저장 완료는 서버 반영과 별도입니다.
  3. 엔진은 필요한 첨부를 고정 uploadId로 stage한 뒤 capture.create를 같은 operationId로 전송합니다.
  4. 서버는 workspace/epoch·버전·중복 영수증을 검증하고 원본/검색/피드/영수증을 함께 기록합니다.
  5. ACK는 해당 전송 사본만 정리합니다. 응답 뒤에 새로 쓴 초안을 지우지 않습니다.

문서 자동 저장과 충돌

  1. BlockNote 변경 → PageEditor.queueSave → persistLocalPage. 본문은 Markdown이 아닌 블록 JSON입니다.
  2. 현재 본문과 localRevision을 IDB에 보존하고 전송을 짧게 지연·병합합니다. 이미 전송한 payload는 바꾸지 않습니다.
  3. page.update는 baseVersion을 검사합니다. 오래된 저장은 최신 서버 문서를 덮지 못합니다.
  4. 동일 문서가 다른 기기에서 바뀌면 base/current/remote 사본을 남기고 사용자 확인을 기다립니다.
  5. 같은 원격 값 재조회는 변경 알림을 만들지 않습니다. 불필요한 저장/조회 루프를 피합니다.

문서 이력은 서버 저장 버전이고 기기 초안 복구와 별개의 기능입니다. 실시간 공동 편집·CRDT는 현재 구현이 아닙니다.

AI 요청과 결과 반영

  1. 미리보기는 외부 요청을 실행하지 않습니다. 제출할 때 템플릿·입력·선택 블록·버전 사본을 고정합니다.
  2. 기기 workflow가 원본 저장 ACK를 기다린 뒤 ai.submit을 전송합니다. 서버는 UUID로 작업을 한 번 등록합니다.
  3. 단일 worker가 리서치 자료를 수집하고 지정 HTTP gateway 또는 Devin adapter를 실행합니다.
  4. 검증한 Markdown·출처·usage를 ai_jobs에 보관합니다. 원문 메모/Page는 자동으로 바꾸지 않습니다.
  5. 사용자가 결과를 추가/교체/하위 문서 또는 할 일로 채택하면 버전·UUID를 확인해 명시 반영합니다.

Hive 환경 변수는 선언되어 있지만 현재 provider adapter는 미구현입니다. HTTP gateway는 Hive Chat Completions의 본문/응답과 다른 자체 계약을 사용합니다.

읽기 전용 공유와 이름 댓글

  1. 개인 앱은 저장된 페이지의 공유 범위를 확인하고 만료/댓글 허용과 함께 토큰 링크를 발급합니다.
  2. 방문자는 별도 public 프로세스의 /s/:token을 엽니다. 매 요청마다 토큰·만료·폐기·활성 페이지를 확인합니다.
  3. 공유 HTML에는 해당 문서와 직접 참조한 첨부만 포함합니다. 하위 문서/메모/개인 댓글을 자동 공개하지 않습니다.
  4. 허용된 이름 댓글은 전용 Unix socket으로 개인 프로세스에 전달됩니다. 다시 검증한 뒤 별도 공유 댓글 테이블에 씁니다.
  5. 작성자 받은함은 guest sequence와 읽음 marker를 따로 관리합니다. 표시 이름은 인증된 신원과 다릅니다.

지도 이미지와 일정

  1. 일정 JSON의 날짜·시간·활동·장소·좌표를 저장합니다. 여행 준비 관계는 별도 private 테이블입니다.
  2. 개인 화면의 지도 이미지 생성 버튼만 Geoapify를 호출합니다. 페이지를 읽거나 스크롤해서 생성하지 않습니다.
  3. UUID·입력 사본·저장 버전을 확인한 PNG를 자산으로 보관합니다. 바뀐 방문 순서에는 오래된 이미지 안내를 표시합니다.
  4. 공유와 오프라인 사본은 저장 이미지를 재사용합니다. 지도 키·SDK·타일 요청을 포함하지 않습니다.
  5. Google 장소/경로 링크는 외부에서 실제 길찾기를 엽니다. 핀 사이 화살표는 방문 순서이며 도로 경로가 아닙니다.

수정본·템플릿·오프라인 사본

  1. 문서 저장 때 서버 수정본과 첨부 참조를 함께 보존합니다. 최신 100개 이력을 조회합니다.
  2. 수정본 복원은 기존 것을 덮어쓰는 대신 새 버전을 만들며 페이지 계층은 유지합니다.
  3. 페이지 템플릿은 사용자 문서 사본입니다. documentBlueprint는 에이전트/사용자가 쓰는 작성 규격, promptTemplate은 AI 요청문입니다.
  4. ZIP 내보내기는 현재 직접 첨부·정적 HTML/CSS/JS만 포함합니다. 개인 댓글·작업·연결 문서 전체를 재귀 내보내지 않습니다.

서버 DB, 기기의 미전송 원문, 정적 앱 캐시는 목적이 서로 다릅니다. 어느 한쪽을 지우면 다른 쪽의 역할을 대신할 수 없습니다.

정적 앱 캐시 · Service Worker

해시가 맞는 index·JS/CSS·지연 편집기 chunk와 이 아키텍처 HTML을 보관합니다. /api/*와 /s/*는 shell fallback으로 처리하지 않습니다. 원문/파일은 IndexedDB 경로입니다.

바꾸면 안 되는 저장 계약

  • 원문과 summary·검색/피드는 각 저장 계층의 같은 transaction에서 갱신합니다.
  • 응답 유실 재전송은 같은 operationId와 최초 payload입니다. 중복 실행을 새 UUID로 우회하지 않습니다.
  • 서버 ACK가 최신 localRevision보다 오래되면 이후 입력을 보존합니다.
  • 서버 복원/교체로 epoch가 바뀌면 전송을 멈추고 자료 확인·내보내기 후 명시 복구합니다.
  • 기기 충돌을 데이터 삭제·캐시 초기화로 해결하지 않습니다.

로컬 실행·빌드·서버 운영

명령은 leneu-storage/에서 실행합니다. 아래 예시에는 실제 토큰·도메인·IP·개인 데이터 경로가 없습니다.

로컬 개발

# Node.js 24 이상 · 처음 설치 시
npm ci
# 실제 키는 .env에만 저장
cp .env.example .env
# 화면 5173 + 개인 API 8787
npm run dev
# 공유 화면 필요 시 별도 터미널
npm run start:public

이미 .env가 있으면 복사 명령을 다시 실행하지 않습니다. 개발 proxy는 Host를 보존합니다. 브라우저는 상대 /api 경로로 요청하며 별도 CORS를 열지 않습니다.

배포용 실행

npm run build
# tsc → Vite dist → hash manifest/worker
npm start
# 빌드된 화면 + API: 8787

# 최초 개인 계정: 대화형 입력
npm run auth:setup
# 비밀번호/TOTP를 argv에 넣지 않음

설정이 없는 외부/production은 개인 API를 fail closed로 보호합니다. .env와 원본은 배포 이미지에 복사하지 않습니다. HTTPS·Secure cookie·Origin을 함께 확인합니다.

Docker에서의 실제 분리

  • storage: 화면+개인 API, DB·첨부 쓰기, AI/OCR/백업·댓글 broker. 호스트 127.0.0.1:8787에만 publish합니다.
  • share: 같은 이미지의 public.mjs를 실행, /data와 socket readonly, root 파일 시스템 readonly·/tmp tmpfs. 127.0.0.1:8790에 publish합니다.
  • comment-ipc: 댓글 전용 Unix socket 볼륨입니다. 별도 일반 개인 API 네트워크 proxy가 아닙니다.
  • 지속 데이터: /data·/backups는 컨테이너와 독립적인 호스트 볼륨. share에는 백업·AI·지도·인증 비밀을 주지 않습니다.

Oracle·도메인·Vercel의 현재 위치

2026-10-04 운영 기록에는 Osaka A1 2 OCPU/12GB·Ubuntu ARM64 VM과 SSH 확인, Cloudflare zone/네임서버 연결, 읽기 전용 Python 사용량/비용 조회와 한국시간 09·21시 Telegram timer 설치가 있습니다. 앱의 실제 Oracle 배포, 서비스 DNS/TLS, Vercel의 화면/API 연결은 아직 실행되지 않은 단계입니다.

이는 저장된 운영 기록의 요약이며 이 문서를 열 때 실시간 Cloud Console을 조회하지 않습니다. Telegram과 OCI 예산은 알림이며 비용 초과 시 앱을 자동 정지/삭제하는 장치가 아닙니다. 앱 백업 디렉터리의 파일과 OCI 볼륨 백업은 별개입니다.

Vercel을 화면 호스트로 선택해도 SQLite·업로드·장시간 worker·Unix socket은 Oracle 서버에 둡니다. 현재 클라이언트는 상대 /api와 same-origin cookie 계약이므로 인증된 HTTPS proxy/라우팅이 필요합니다. URL만 다른 출처로 바꾸는 배포는 현재 계약과 맞지 않습니다. 독립 HTML 사이트는 별도 정적 루트로 앱 DB와 분리합니다.

백업과 복원

# 목적지는 새 경로를 사용 · 아래 값은 예시
npm run backup -- create /path/to/data /path/to/new-backup
npm run backup -- verify /path/to/new-backup
npm run backup -- restore /path/to/new-backup /path/to/new-restored-data
