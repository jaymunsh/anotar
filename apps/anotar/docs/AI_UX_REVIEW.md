# AI 요청 UI/UX 검수 및 반영안

2026-10-05. 현재 화면과 소스를 확인한 단일 검수 기록이다. UI 수정은 아직 반영하지 않았다. 실행기 방향은 사용자 확인대로 Oracle 서버의 Hive 기본 + Devin CLI 선택이며, Codex·Claude·OpenCode·PC 연결 프로그램은 이번 범위에서 제외한다.

## 확인한 화면

- /ai 작업 목록 → 기존 결과 열기 → 새 AI 요청 → 설정의 작업 공간.
- Chromium 1440px·390px 라이트, 320px 다크 작업 목록·결과.
- 저장된 실제 결과를 읽었으며 새 AI 요청은 전송하지 않았다. 합성 터치, 실제 휴대폰, 전 상태 접근성·대비·성능 측정은 하지 않았다.
- 증거: `.omo/evidence/ai-review/`의 activity/result/request/settings 스크린샷과 텍스트.
- Impeccable 정적 탐지: 주요 규칙 위반 0, 디자인 문서와 폰트 크기·반경 차이 advisory 10. 이 결과는 접근성 통과나 UX 품질 보증이 아니다. 기존 14px 본문과 보조 UI의 개별 값은 현재 화면의 밀도 문제와 함께 검토한다.

## 이미 있는 것

- 결과는 기본 Markdown 읽기 보기이며 원문 모드로 전환할 수 있다.
- 사용한 템플릿 이름·버전과 추가 지시가 결과에 표시된다.
- Devin 실행 결과에는 실행기·모델 라벨이 표시된다.
- 요청 미리보기, 입력 글자 수·첨부 제외 안내, 작업 상태·실행 이력이 있다.

이를 다시 만들 필요는 없고 화면에서 드러나는 위치를 바꾸는 것이 우선이다.

## 우선 반영할 문제

### P1 — 결과를 열어도 원본 메모 화면으로 이동한다

근거: AI 목록의 결과 링크가 메모 상세로 연결된다. PC에서는 사이드바 + 메모 목록 + 상세의 3영역이 차지한다. 상세 위에는 이전/다음, 검색 범위 밖의 메모, 원본 날짜·입력문이 먼저 나오고 그 아래에 결과가 시작한다. 1440px 캡처에서 결과 제목은 대략 y=660부터 보인다.

제안: AI 작업에서 열었을 때 결과를 기본 본문으로 표시한다. 상단은 결과 제목·상태, 바로 아래 작은 실행 정보 한 줄, 그 다음 결과 본문이다. 원본과 요청 설정은 접는 패널로 두고 필요할 때 펼친다. ‘검색 범위 밖의 메모’는 AI 결과 진입에는 표시하지 않는다. PC 읽기 영역을 넓히고 모바일은 독립된 결과 화면을 쓴다.

진입점: src/main.tsx 메모 상세 분기, src/ai/AiJobPanel.tsx, src/ai/AiResultContent.tsx.

### P1 — 설정에서 실행기·모델을 관리할 수 없다

근거: 설정의 작업 공간에는 프롬프트·웹 호스팅·백업·휴지통만 있다. 서버는 환경변수로 실행기를 하나 고른다. CLI 실행 파일 존재만으로 enabled가 true가 되므로 인증·실호출 성공과 구분해야 한다.

제안: 설정에 ‘AI’ 항목을 둔다. 기본 실행기는 Hive, 선택 실행기는 Devin CLI만 노출한다. 각 카드에 모델·구성 상태·최근 연결 확인을 표시한다. 상태를 미설정 / 설치 확인 / 로그인 확인 필요 / 사용 가능으로 구분하고 마지막 확인 시각을 둔다. 정적 설정 확인과 실제 유료 테스트 실행은 별도 버튼이다.

키·CLI 로그인은 서버에서 관리하고 웹에는 설정 여부만 보인다. 브라우저에서 임의 실행 경로나 셸 인자를 입력하게 하지 않는다. 기본 실행기 선택은 서버에 저장해 기기 간 동일하게 쓴다. 실패 시 다른 실행기로 자동 전환하지 않는다.

진입점: src/settings/WorkspaceSettings.tsx, server/ai/runner.mjs, AI 상태 API.

### P1 — 요청 전에 실제 사용할 모델이 분명하지 않다

근거: AiConnectionSummary의 라벨은 현재 서버 전역 실행기 정보다. HTTP는 임의 연결 라벨이고 요청별 선택·확정된 모델 계약은 없다.

제안: 요청 버튼 옆에 `Hive · 설정된 모델 ▾`를 표시한다. Devin을 선택하면 `Devin CLI · swe-2-high`처럼 즉시 바뀐다. 설정이 비어 있으면 모델 이름을 추정하지 않고 ‘모델 설정 필요’로 표시한다. 제출 시 실행기·모델·템플릿 버전을 작업 사본으로 고정한다. 대기 중 설정이 바뀌어도 이미 제출한 작업의 모델은 조용히 변경하지 않는다.

진입점: src/prompts/AiRequestFields.tsx, src/ai/AiConnectionSummary.tsx, shared/aiRequests.ts, server/ai/jobs.mjs.

### P2 — 모바일 요청 폼이 길고 같은 안내가 반복된다

근거: 빠른 메모 입력 뒤 AI 체크, 연결 상태와 설명, 입력 요약, 템플릿, 추가 요청, 템플릿 설명·관리, 미리보기, 저장·첨부 안내가 쌓인다. 연결 불가 상태에서도 버튼 이름은 ‘저장하고 AI 요청’이다.

제안: AI 전용 요청 진입에서는 제목을 ‘AI 요청’으로 하고, 내용 → 작업/템플릿 → 실행기 → 요청 순으로 구성한다. 추가 지시·최종 요청문은 펼쳐보기로 둔다. 첨부 제외·저장 설명은 한 곳에서 짧게 설명한다. 실행 불가 시 ‘요청문 저장’과 ‘설정 열기’를 제공해 즉시 실행과 보관을 구분한다. 일반 빠른 메모 흐름은 유지한다.

진입점: src/prompts/AiRequestFields.tsx, src/main.tsx, src/prompts/prompts.css.

### P2 — 작업 목록만으로 결과를 구분하기 어렵다

근거: 목록에 입력 일부·템플릿·상태·요청/완료 시각은 있지만 실행 모델이나 결과 첫 문장이 없다. 페이지 작업에서는 템플릿 위치에 원본 제목이 쓰인다.

제안: 제목, 상태, 템플릿·실행기·모델 한 줄로 통일한다. 완료 시 결과의 짧은 미리보기를 보여 주고 원문/출처는 열어서 확인한다. 모델과 템플릿은 현재 설정이 아닌 저장 당시 값을 쓴다. 과거에 기록이 없으면 ‘정보 없음’으로 둔다.

진입점: src/ai/AiActivity.tsx, server/ai/jobs.mjs의 목록 응답.

### P2 — 여행 전용 AI 프롬프트가 남아 있다

근거: 새 요청 템플릿 선택에 ‘여행 계획 초안’이 남아 있다. 여행 페이지·작성 블록의 분리와 AI 프롬프트 목록은 별도다.

제안: 해당 기본 프롬프트를 보관 상태로 바꿔 새 요청에서 숨긴다. 기존 요청에 저장된 템플릿 사본·결과는 유지한다. 요약·생각 정리·할 일 추출 중심으로 노출 순서를 정리한다.

## 요청 화면의 최소 구성

```text
AI 요청
[처리할 내용을 입력]
[생각 정리 ▾]  추가 지시

[Hive · 설정된 모델 ▾]   [요청하기]
요청문 미리보기 ▸
```

## 결과 화면의 최소 구성

```text
결과 제목                                 완료
생각 정리 v2 · Hive · 모델명

결과 본문

[복사] [페이지에 정리] [할 일로 가져오기]
요청 원문·실행 정보 ▸
```

현재 결과의 Markdown 읽기·할 일 채택·페이지 정리 기능을 재사용한다. 실행 중/실패/오프라인에서는 상태와 가능한 다음 행동을 먼저 보여 준다.

## 반영 순서와 검증

1. 서버 실행 프로필·Hive 어댑터·Devin 선택과 불변 작업 사본.
2. 설정 AI 항목과 요청 버튼 옆 모델 표시.
3. 결과 중심 읽기 화면과 원문/요청 정보 접기.
4. 모바일 요청 폼·목록 정보 정리, 여행 프롬프트 보관.

검증: 기존 요청/결과 보존, 제출 후 모델 변경, 인증 실패·한도 초과·취소, 응답 유실 재시도, 첨부/개인 참조 전달 경계, 키의 웹 응답 노출 방지, 320/390/PC 라이트·다크 및 키보드 흐름. 실호출은 합성 입력으로 별도 확인한다.

## 이번에 반영한 Devin 범위

Devin 임시 XDG 저장 경로 격리와 종료 후 정리, 로컬 .env 및 .env.example의 Devin 프로필 값 준비. UI·Hive 어댑터·Oracle 설치/로그인은 완료로 표시하지 않는다. 서버 접속 주소 요청은 대기 중이다. 상세는 DEVIN_RUNNER.md.
