# 메모·페이지 휴지통 구현 계획

> **For agentic workers:** superpowers:executing-plans로 현재 공유 작업 공간에서 순차 구현한다. 기존 변경을 보존하고 자동 커밋하지 않는다.

**Goal:** 메모·페이지의 휴지통 이동·되돌리기·복원과 하위 문서/첨부 보존을 제공한다.

**Architecture:** nullable 삭제 열과 SQLite 묶음·작업 기록으로 논리 삭제를 처리한다. 활성 조회/참조 계약을 같은 저장 계층에서 적용하고 새 휴지통 화면은 지연 로딩한다.

**Tech Stack:** React·TypeScript·Vite, Node 24 SQLite. 새 의존성 없음.

**Spec:** `docs/superpowers/specs/2026-09-29-trash-design.md`.

## Review Focus

1. 삭제/복원 응답 유실과 지연된 이전 요청: 같은 UUID가 새 생명주기를 다시 변경하지 않는다.
2. 활성 페이지의 첨부 재사용: 소유 메모를 삭제해도 연결 파일이 유지되며 사용하지 않는 휴지통 첨부는 조회되지 않는다.
3. 별도 하위 묶음과 삭제된 부모: 한 묶음의 복원이 다른 삭제를 되돌리지 않고 삭제된 부모 아래에 활성 문서를 숨기지 않는다.
4. 오래 열린 편집기·미저장 초안: 휴지통/복원 후 저장을 거절하고 작성 내용을 보존한다.
5. 50개 이후 목록·필터·예시 재실행: 누락/복제/자동 복원 없이 관리한다.
