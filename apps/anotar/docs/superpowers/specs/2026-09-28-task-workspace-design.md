# 홈 투두 패널과 할 일 관리 설계

작성: 2026-09-28
상태: **직접 관리 첫 단계 구현.** 홈 패널·전체 보기에서 직접 추가·내용/기한 수정·완료·되돌리기·버전 충돌·실패 재시도를 제공한다. **PC의 오른쪽 연두색 안내 카드 자리를 투두 패널로 바꾸는 위치는 사용자 확인을 받았다.** 1160px 이하에서는 입력란 다음에 배치한다. 아래의 원문 연결·체크리스트 가져오기·AI 후보 등록은 후속 설계이며 아직 구현되지 않았다. 실행 규격은 [현재 구현](../../../CURRENT_IMPLEMENTATION.md)을 따른다.

## 목적과 기능의 관계

빠른 메모는 자료를 보관하고, 투두는 실제로 해야 할 일을 관리한다. AI를 사용하지 않아도 할 일을 직접 추가·수정·완료할 수 있다. 메모와 AI 결과에서 할 일을 가져오더라도 Task는 독립된 기록으로 남는다. AI 요청과 프롬프트 관리는 [별도 설계](2026-09-28-ai-request-harness-design.md)를 따른다.

성공 기준은 다음과 같다.

1. 홈에서 현재 할 일을 보고 체크하거나 한 줄로 추가할 수 있다.
2. 메모 저장·검색과 할 일 체크가 서로의 처리를 기다리지 않는다.
3. 화면을 다시 열어도 할 일·완료 상태·기한이 남고, 다른 탭의 늦은 수정이 최신 상태를 덮지 않는다.
4. 모바일과 좁은 화면에서도 투두가 숨겨지지 않으며 빠른 기록 동선이 유지된다.
5. AI 제안과 페이지 체크리스트가 사용자 선택 없이 Task로 등록되지 않는다.

## 홈 배치

| 배치                         | 특징                                                       | 판단             |
| ---------------------------- | ---------------------------------------------------------- | ---------------- |
| **오른쪽 안내 카드 자리**    | 입력·최근 보관 목록을 유지하면서 실제 할 일을 함께 봄      | 데스크톱 추천    |
| 입력란과 최근 보관 목록 사이 | 좁은 화면에서도 한 열로 보이지만 최근 기록을 아래로 밀어냄 | 좁은 화면 배치   |
| 별도 할 일 화면만 제공       | 많은 작업을 다루기 편하지만 홈에서 바로 보이지 않음        | 전체 보기로 병행 |

```text
빠른 입력                           할 일             +
메모·URL·이미지·파일                 □ 항공권 날짜 확인
                                    □ 숙소 주소 저장    오늘
최근 보관한 것들                    □ 공항 이동 방법 찾기
메모와 원본 자료                     + 할 일 추가
                                    완료 2 · 전체 보기
```

기존 `info-column`은 1160px 이하에서 숨겨진다. 그 CSS를 그대로 재사용해 업무 데이터를 숨기지 않는다. 투두 전용 컴포넌트를 만들어 넓은 화면에서는 오른쪽, 1160px 이하에서는 입력란 다음·최근 목록 전에 배치한다. 화면마다 독립 복사본을 만들지 않고 같은 상태를 재사용한다.

- 패널 제목은 `할 일`, 오른쪽에 전체 보기, 아래 진행 중·완료 탭에 개수, 목록 아래에 한 줄 추가를 둔다.
- 최초 홈 목록은 최대 5개다. 기한이 지난 항목·오늘 기한을 먼저 보여주고 나머지는 사용자가 정한 순서를 따른다. 기한이 없는 항목을 `오늘`에 넣지 않는다.
- 한 항목은 체크박스, 제목, 필요한 경우 기한을 담는다. 긴 제목은 말줄임표로 줄이고 누르면 같은 행에서 전체를 편집한다. 원문 링크는 후속 단계다.
- `+ 할 일 추가`에서 제목을 입력하고 Enter로 추가한다. 첫 입력에 기한·우선순위를 강요하지 않는다.
- 완료하면 체크와 취소선을 즉시 보여준 뒤 완료 묶음으로 옮긴다. 완료 목록에서 체크를 해제해 되돌릴 수 있다.
- 모바일은 기본적으로 미완료 3개와 `더 보기`를 보여준다. 기존 하단 빠른 기록 도크를 유지하고 투두 조작으로 작성 시트를 열지 않는다.
- 빈 상태에는 `작은 일부터 하나씩.`과 한 줄 추가를 둔다. 장식 카드나 가짜 예시 작업으로 채우지 않는다.

별도 `/tasks` 전체 보기와 사이드바 `할 일` 항목을 제공한다. 진행 중·완료 보기를 나누고 제목·기한을 수정할 수 있다. 목록은 50개 단위 더 보기로 이어지고 연결 원문은 후속 단계다. 큰 칸반·반복 일정·알림·프로젝트 분류는 첫 범위에 넣지 않는다.

## 등록 방식

1번은 구현됐고 2~4번은 후속 단계다.

1. **직접 추가:** 홈 패널 또는 전체 보기에서 한 줄 제목을 저장한다.
2. **메모에서 추가:** 상세의 `할 일로 추가`가 선택한 문장 또는 직접 고친 제목을 Task로 만든다. 길고 자유로운 메모 전체를 자동으로 작업 제목으로 만들지 않는다.
3. **체크리스트 가져오기:** 메모나 AI 결과에 명시적인 Markdown 체크리스트가 있으면 후보를 보여주고 선택한 항목만 등록한다. 이 읽기는 형식 변환이며 AI 호출을 하지 않는다.
4. **AI를 사용한 추출:** 사용자가 사이트에 자유 프롬프트를 만들어 메모를 체크리스트로 정리할 수 있다. 생성된 목록도 후보 확인과 명시적 등록을 거친다. 앱에 필수 고정 AI 추출 작업을 다시 추가하지 않는다.

페이지의 체크리스트는 여전히 해당 페이지 내용이다. Task를 만들었다고 페이지 블록의 체크 상태가 자동 동기화되지 않는다. 후속으로 명시적인 Task 참조 블록을 만들 때만 같은 Task ID를 공유한다.

## 저장과 변경 계약

`Task`의 현재 필드는 `id`, `title`, `status(open/done)`, 선택적 `dueDate`, `position`, `createdAt`, `updatedAt`, `completedAt`, `version`이다. 출처는 후속 단계에 추가한다. 제목은 500자까지, 기한은 한국 날짜 기준의 `YYYY-MM-DD`다. 일반 생성·수정 시각은 기존처럼 UTC ISO로 저장한다. 첫 버전에서 세 단계 진행 상태나 날짜 없는 항목의 추정 기한을 추가하지 않는다.

후속 출처 연결은 Capture 또는 AI 결과의 ID·버전과 원문 발췌를 기록한다. 원본을 나중에 수정해도 Task 제목은 그대로 유지되며 사용자가 변경한다. 출처가 없거나 조회할 수 없으면 Task 자체는 계속 관리할 수 있다. 복사 등록은 파일 바이트를 복제하지 않는다.

변경 요청은 `expectedVersion`을 검사한다. 홈 체크는 화면에 먼저 반영하되 서버 실패 시 복원하고 해당 항목에 재시도 안내를 둔다. 같은 항목의 빠른 연속 체크는 저장을 직렬화해 마지막 선택을 유지하고 늦은 응답이 화면을 되돌리지 못하게 한다. 성공 전 상태를 영구 저장 완료로 표시하지 않는다. 제목 편집 충돌은 초안을 보존하고 최신 내용과 비교할 수 있게 한다.

후속 여러 후보의 등록은 요청 UUID와 안정적인 원본 후보 키로 중복을 막는다. 같은 후보를 다시 누르면 이미 등록된 Task를 보여준다. 사용자가 직접 새 Task를 만드는 경우 같은 제목이라는 이유만으로 합치지 않는다.

초기 API는 개인용 실행 모드에만 제공한다.

- `GET /api/tasks?status=open&limit=50&cursor=`: 상태별 목록과 전체 개수·다음 커서. 홈 PC 5개·모바일 3개, 전체 보기 50개를 요청한다.
- `POST /api/tasks`: 제목·선택적 기한·선택적 요청 UUID로 직접 추가. 같은 UUID 재시도는 같은 항목을 반환한다.
- `GET /api/tasks/:id`: 할 일 하나 조회.
- `PATCH /api/tasks/:id`: 제목·기한·완료 변경과 버전 검사. 순서 변경 UI/API는 후속 단계다.
- **후속** `POST /api/tasks/imports`: 선택한 체크리스트 후보를 한 트랜잭션으로 중복 없이 등록.

홈은 필요한 건수와 미완료 수만 조회한다. 전체 보기를 열 때만 상세 목록을 불러온다. Task UI에 블록 편집기나 AI 실행기를 의존성으로 넣지 않는다.

목록 커서는 조회 위치·변경 번호·필터·한국 날짜를 함께 보존한다. 추가·수정·완료로 목록이 바뀌거나 한국 날짜 경계가 지나면 다음 더 보기 요청은 첫 페이지와 `reset: true`를 반환한다. UI는 기존 누적 목록을 교체해 앞쪽 페이지 변경으로 남은 항목이 빠지지 않게 한다.

## 검증 시나리오와 순서

1. 직접 추가·수정·완료·되돌리기 뒤 재시작해 저장 상태를 확인한다.
2. 느린 저장과 서버 실패에서 체크 복원, 재시도, 중복 제출 방지를 확인한다.
3. 다른 탭의 완료·제목 수정과 충돌해도 최신 상태와 편집 초안이 보존되는지 확인한다.
4. 0개·1개·5개·많은 작업, 긴 한국어 제목, 기한 없는 항목·오늘·지난 기한을 확인한다.
5. 320px·390px 모바일 및 중간 폭에서 투두가 숨겨지지 않고 기록 도크와 겹치지 않는지 확인한다. 밝은·어두운 화면에서 완료·기한·포커스를 점검한다.
6. 선택한 체크리스트만 등록되며 반복 등록으로 중복되지 않는지 확인한다. 페이지 체크리스트와 연결 원문은 자동 변경되지 않아야 한다.

Task 저장·직접 추가와 홈 패널·전체 보기는 구현됐다. 이후 메모에서 명시적 등록 → 체크리스트·AI 결과 가져오기 순서로 진행한다. 첫 단계만으로도 매일 쓸 수 있는 투두를 제공한다.
