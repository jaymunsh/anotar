# 메모·페이지 휴지통

## 사용자 목적

쌓인 메모·페이지를 정리하고 잘못 옮긴 기록을 다시 살린다. 기존 `/memo`와 직접 편집 흐름을 유지한다. 이번 범위는 휴지통 이동·복원이며 통합 검색·AI 실행은 다음 단계다.

## 동작

- 메모 상세와 페이지 정보 메뉴에 **휴지통으로 이동**을 제공한다. 메모는 단일 기록, 페이지는 현재 활성 하위 페이지 전체를 같은 묶음으로 이동한다. 페이지 메뉴에서 하위 문서 수를 확인하고 실행한다.
- `/trash`는 메모·페이지 탭, 전체 개수, 50개씩 더 보기, 각 묶음의 복원을 제공한다. 목록은 제목/원문 미리보기, 유형·하위 개수, 휴지통 이동 시각을 표시한다.
- 이동 성공 후 **되돌리기**를 제공한다. 메모는 현재 목록, 페이지는 `/memo`로 돌아간다. 화면에 따라 서버 상태를 다시 조회한다.
- 복원은 같은 묶음만 되살린다. 먼저 별도로 휴지통에 보낸 하위 문서는 다른 묶음으로 남긴다. 원래 상위 페이지가 활성 상태면 같은 위치에 복원하고, 없거나 휴지통에 있으면 최상위에 복원한다.
- 생성·최종 수정 시각, 내용·AI 요청 사본, 첨부 바이트는 보존한다. 이동·복원마다 편집 버전은 증가해 오래된 편집기가 복원된 내용을 덮지 못한다.
- 활성 목록·개수·페이지 제목 검색·가져오기 대상·연결된 페이지 목록에서 휴지통 기록을 제외한다. 일반 직접 조회/수정도 거절한다.
- 활성 페이지의 기존 원본 참조는 유지하고 원본이 휴지통에 있으면 누락 안내를 보여준다. 기존 첨부가 활성 페이지에 사용 중이면 열 수 있다. 활성 소유 메모나 활성 페이지 참조가 없는 휴지통 첨부의 일반 조회는 거절한다. 바이트는 복원을 위해 보존한다.
- 저장 중·미저장 복구·충돌 상태의 페이지는 휴지통 이동을 막고 안내한다. 메모 편집 중에는 수정 종료 후 이동한다. 실패 시 내용·선택을 보존하고 한국어 안내·동일 요청 재시도를 제공한다.
- 영구 삭제·자동 비우기는 이번 범위에 추가하지 않는다.

## 저장·요청

- `captures`·`pages`에 nullable `deleted_at`, `trash_id`를 추가한다. 기존 행은 활성 상태로 유지한다.
- `trash_batches`는 이동 묶음/복원 시각, `trash_operations`는 UUIDv4와 정규화한 요청·응답을 기록한다. 같은 UUID/같은 요청은 재실행하지 않고 다른 요청은 409다. 지연된 이동 재시도가 복원된 기록을 다시 삭제하지 않는다.
- 이동은 `{operationId, expectedVersion}`, 복원은 `{operationId}`를 받는다. 버전 충돌 409, 잘못된 입력 400, 없는 대상 404다. SQLite 저장과 계층 묶음 이동/복원은 한 트랜잭션으로 처리한다.
- 예시 재실행은 휴지통 예시를 다시 만들거나 자동 복원하지 않는다. 기존 특별 임시 문서 역시 중복 생성하지 않는다.

## 화면과 검증

기존 종이·숲색/차콜·세이지의 Operate 화면을 확장한다. 휴지통은 편집기를 불러오지 않는다. 모바일 복원 버튼은 최소 44px, 긴 원문/제목은 말줄임표와 전체 title로 처리하고 오류는 해당 기록에 둔다. 320/390px·PC·두 테마에서 확인한다. 임시 저장소에서 이동/복원·서버 재시작·응답 유실·오래된 편집·첨부 참조·별도 하위 묶음·예시 보존을 검증한다.
