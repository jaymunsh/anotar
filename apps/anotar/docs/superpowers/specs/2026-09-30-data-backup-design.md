# 개인 데이터 백업·복원 설계

## 범위

운영 중인 SQLite WAL DB의 일관된 사본과 그 사본의 `assets.storage_key`가 참조하는 첨부 바이트를 하나의 백업 디렉터리로 만든다. 원본 `data/`는 읽기만 한다. 복원은 기존 데이터 디렉터리를 덮지 않고 새 디렉터리에만 수행한다. 일반 페이지 버전 이력과 자동 일정은 별도 단계다.

## 형식과 절차

- 백업 디렉터리: `storage.sqlite`, `blobs/<storage_key>`, `manifest.json` (`schemaVersion: 1`, 생성 시각, DB SHA256, 각 파일 크기·SHA256).
- `node:sqlite` 온라인 백업 API로 WAL까지 반영된 DB 사본을 준비 디렉터리에 만든다. 준비 DB의 무결성을 검사하고, 그 사본의 `assets` 행에서 고유 파일 목록을 읽는다. 업로드 중이라 DB에 아직 없는 임시 파일은 포함하지 않는다. 등록된 첨부 키는 난수 이름이며 현재 서버는 등록된 바이트를 덮어쓰거나 일반 삭제하지 않는다.
- 파일 복사·크기·SHA256 검사 후 DB와 파일 목록을 다시 확인한다. 모두 통과했을 때만 준비 디렉터리를 최종 이름으로 바꾼다. 실패하면 준비 디렉터리를 제거하고 완료 백업을 남기지 않는다.
- 복원은 원본 백업을 먼저 검증하고 새 대상의 준비 디렉터리에 복사한 후 다시 검증한다. 최종 대상은 존재하지 않아야 한다. 기존 운영 `data/`를 직접 교체하지 않는다.
- 백업 대상이 원본 데이터 디렉터리 안쪽이거나 같은 경로면 거부한다. 저장 키는 단일 파일명이어야 하고 심볼릭 링크 파일은 거부한다.

## 검증

- 원본 DB 연결이 열린 상태에서 백업하고 새 디렉터리로 복원한다. 메모·페이지·프롬프트·파일이 다시 조회된다.
- 누락 첨부·변조된 백업·이미 있는 복원 대상은 실패하고 기존 데이터는 바뀌지 않는다.
- 첫 버전의 백업은 명시적 CLI 실행이다. 일정 실행과 원격 보관은 N100 배포 단계에서 운영체제 스케줄러·별도 디스크/원격 위치를 연결한다.
