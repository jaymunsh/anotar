# 키워드 리서치 확장 설계

## 목적과 사용 흐름

URL뿐 아니라 주제·키워드로 자료를 찾아 같은 AI 요청에 결과와 출처를 보관한다. 메모에 `N100에서 SQLite FTS5를 쓰는 장단점`처럼 적고 AI를 체크해 **키워드 리서치** 템플릿을 선택한다. 저장을 먼저 확인하고 비동기로 검색·본문 수집·정리를 진행한다. 결과는 `/memo?view=ai`의 원본 상세에서 확인한다.

기존 `kind: research`와 불변 요청 사본을 유지한다. `input.url`이 있으면 URL 본문 하나를 읽는 기존 경로, URL 없이 글이 있으면 키워드 검색 경로다. 자유 요청은 검색하지 않는다. 템플릿 관리의 종류 이름은 **리서치**로 넓히고 URL 템플릿 이름·사용자 수정본은 유지한다.

## 실행 구조

- 설치된 Devin CLI의 `web_search`로 검색 후보를 찾고, 앱의 기존 공개 URL collector로 본문을 수집한다. 별도 검색 서버·검색 API 키·상주 모델은 추가하지 않는다.
- `runner.discover({job}, signal)`은 검색 후보 `{url, title}[]`를 반환하는 선택적 capability다. HTTP adapter에는 이 capability가 없으므로 키워드 요청은 `research_search_unavailable`로 실패하고 원문을 보존한다. `/api/ai/status`에 `researchModes`를 추가한다.
- 검색 프롬프트는 원문 주제와 추가 요청만 데이터로 받는다. 웹 검색 한 번, 240자 이하 질의, 최대 5개 후보를 지시한다. 파일·셸·Fetch·MCP·하위 에이전트는 금지한다. 다른 에이전트 설정 가져오기·자동 업데이트를 끈다.
- Devin의 ATIF export에서 실제 `web_search` 호출 1개와 그 호출 ID에 연결된 결과의 `URL:` 줄을 확인한다. 최종 JSON의 후보는 이 결과에 나온 URL이어야 한다. 추가 도구 호출·검색 없는 답변·조작된 출처·1MiB 초과 export·256KiB 초과 출력은 거부한다. 이것은 호출 후 검증이며 제공자의 과금 상한이나 OS 샌드박스 보장은 아니다.
- 후보는 URL을 정규화해 중복을 제거하고 최대 5개까지 순차 수집한다. 사설 IP·DNS·redirect·주소 고정·10초/2MiB 수집 제한은 기존 collector를 따른다. 접근 실패 후보는 건너뛰고 서로 다른 최종 URL 최대 3개를 사용한다. 각 본문 16,666자, 전체 49,998자 이내다. 확인한 본문이 하나도 없으면 `research_no_sources`로 실패하고 요약 호출은 하지 않는다.
- 요약은 기존 도구 없는 Devin 실행으로 진행한다. 이 단계는 `web_search`도 명시적으로 금지한다. 검색 후보 수·확인 본문 수를 프롬프트에 포함하고 일부 수집 실패가 있으면 결과 앞에 앱이 수집 안내를 붙인다. 결과 출처는 실제 가져온 본문으로만 검증한다.
- 키워드 작업은 검색·요약의 네이티브 호출 2개이며, 작업 전체 동시 실행 1개·120초 한도를 공유한다. 중단 시 프로세스 그룹 종료·실제 close·정리·drain 완료 후 다음 작업을 진행한다. 재시도는 명시 조작으로만 한다.

## 템플릿과 호환성

`research-keyword` 기본 템플릿을 추가한다. 변수는 기존 `{{content}}`를 쓰고 핵심 3줄·근거/출처·추가 확인점을 요청한다. 이미 운영 중인 라이브러리에도 누락된 기본값만 추가하며 존재하는 ID의 수정·보관 상태·불변 이력을 덮지 않는다. 템플릿 200개가 찬 DB에서는 추가를 건너뛰고 시작을 방해하지 않는다. 사용자는 기존 템플릿을 리서치 종류로 편집할 수 있다.

Capture·페이지·파일·작업 DB 스키마와 UUID 제출/재시도 계약은 바꾸지 않는다. 이전 URL 작업과 직접 자유 요청은 동일하게 동작한다. 기본 실행기는 비활성이며 현재 사용자 승인으로 켜 둔 로컬 Devin 설정은 유지한다.

## UI와 검증

기존 선택란·설명·요청문 미리보기와 결과 출처 영역을 사용한다. 추가 화면이나 입력함의 초기 JS 의존성을 만들지 않는다. 색·글꼴·간격·NEW/날짜 위치를 유지한다.

모든 자동 테스트·브라우저 QA는 임시 데이터만 사용하고 외부 유료 호출을 금지한다. 실제 연결 확인은 공개 SQLite 주제의 명시적 별도 smoke로 구분하고 실제 사용자 기록을 보내지 않는다. URL/자유 요청 회귀, 일부/전체 수집 실패, 위조 검색 증거, 중단/정리, 템플릿 이관/200개 한도와 모바일 선택 동선을 확인한다.
