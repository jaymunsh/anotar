# leneu 페이지 편집 설계

작성: 2026-09-26
상태: 블록 편집·메모 가져오기·첨부 재사용/직접 업로드·단일 페이지 복제·사용자 템플릿·선택 블록 이동·일정 지도·최신 100개 수정 이력·로컬 읽기 전용 공유 구현. 방문자 댓글·본인 인증·공개 도메인과 N100 운영은 후속 단계다.

## 2026-09-30 화면 업데이트

주요 도구는 공유·댓글·AI·더보기 한 줄이다. 더보기에 되돌리기·다시 실행·Mermaid·Markdown·출처·휴지통·페이지 복제·파일 첨부·템플릿·선택 블록 이동·수정 이력과 넓게 보기·작은 글씨를 둔다. 보기 설정은 브라우저에 저장하며 문서 버전에 영향을 주지 않는다. 목차는 제목 블록을 따라 갱신되는 보조 패널이고 AI와 서로 배타적으로 연다. PC 오른쪽 패널·좁은 화면 하단 패널을 사용하며 지도 좌표 편집은 위치 수정 안에 접는다. 현재 화면 규격은 [DESIGN.md](DESIGN.md)를 따른다.

## 1. 목적과 경계

메모, 스크린샷, 조사 결과를 모아 여행 일정이나 계획처럼 다시 읽고 공유할 수 있는 글로 편집한다. 편집은 Notion처럼 블록을 삽입·이동하는 방식으로, 일반 글은 Markdown 단축키로 빠르게 작성한다. 현재 페이지는 열자마자 직접 편집할 수 있고 제목에서 Enter로 본문에 진입한다. 공개 뷰는 별도 읽기 전용 서버에서 제공하며 실제 외부 주소 연결은 후속 단계다.

빠른 입력은 단순한 `Capture` 원본으로 저장한다. 현재 메모 상세에서 정리할 내용·첨부 또는 완료 AI 결과를 선택하고 기존 `Page`나 새 페이지·새 하위 페이지에 담는다. 필요하면 일반 페이지 하나를 정리 공간으로 사용할 수 있다. 원본 링크 또는 선택한 내용의 편집 가능한 복사본을 넣는다. 페이지를 수정해도 원본은 바뀌지 않는다. 한 입력은 여러 페이지에 연결할 수 있다.

## 2. 페이지에서 하는 일

| 동작   | 전체 설계의 목표                                                              |
| ------ | ----------------------------------------------------------------------------- |
| 만들기 | 빈 페이지를 만들거나 입력함의 Capture·AI 제안에서 선택한 내용으로 시작        |
| 쓰기   | 문단, 제목 1~6, 글머리/번호 목록, 체크리스트, 인용, 코드, 구분선, 표          |
| 연결   | 외부 URL, 다른 페이지, 입력 항목, 이미지, 파일을 블록 또는 인라인 링크로 연결 |
| 정리   | 블록 순서 변경, 들여쓰기, 페이지 사이 이동, 제목 변경, 하위 페이지 만들기     |
| 찾기   | 페이지 제목·본문을 기존 검색에 포함; 페이지 목록과 상위 페이지 경로 제공      |
| 공유   | 현재 저장된 페이지를 읽기 전용으로 표시; 파일·이미지는 공유 허용 목록 검사    |

PC에서는 `/` 메뉴와 블록 이동 핸들, 입력 단축키(`#`, `-`, `- [ ]`, `>`, `"`, 코드 울타리)를 제공한다. `>`는 노션처럼 접을 수 있는 목록을, `"`는 인용을 만든다. 붙여넣은 Markdown의 `>` 문단은 계속 인용으로 변환한다. `/` 메뉴에는 접을 수 있는 목록·제목, 목차, 페이지, 이모지 항목이 있고 `:` 입력으로도 이모지를 고른다. 어느 블록이든 `Tab`/`Shift+Tab` 또는 드래그 손잡이 메뉴로 다른 블록 안쪽에 둘 수 있다. 점 6개 손잡이를 눌러 메뉴를 여는 동안에는 해당 블록 영역 전체가 옅은 녹색으로 강조된다. 목차 블록은 연한 배경 영역 안에 제목을 자동으로 모아 보여주고 항목을 누르면 이동한다. `/` 메뉴의 페이지 항목은 새 하위 페이지를 만들어 링크 블록을 넣고, 링크를 누르면 그 페이지로 이동한다. 하위 페이지는 `parentId`를 저장해 사이드바에서 상위 아래에 들여져 보이고, 링크 블록과 목록에는 대상의 대표 이모지가 함께 표시된다. 페이지 대표 이모지는 제목 위의 아이콘 버튼에서 고르거나 지운다. 사이드바 목록은 새 페이지가 끝에 붙는 생성 순서를 기본으로 하고, 행을 드래그해 순서를 바꾸거나 다른 페이지 안에 넣을 수 있다(`PATCH`로 `position`·`parentId` 저장). 드롭 위치는 경계면 파란 실선, 안쪽이면 옅은 파란 배경으로 표시한다. 모든 행이 접기 화살표를 가진다 — 하위가 있는 행은 접고 펴고, 잎 행을 펼치면 '하위 페이지 없음'을 보여준다. 문서 상단에는 `parentId`를 따라 만든 상위 경로·저장 상태·작은 아이콘 도구를 보여준다. 생성일·최종 수정일은 제목 아래에 표시하고 입력 도움말은 **페이지 정보**에 접어둔다. 데스크톱 공통 상단바를 없애고 화면 모드는 사이드바 로고 오른쪽 같은 줄에, 한국 날짜 `YYYY-MM-DD (요일)`는 그 아래 줄에 오른쪽 정렬한다. 모바일 메뉴 줄은 48px다. `/pages`·`/temp`의 이전 목록 주소는 `/memo`로 연결한다. 메모와 AI 요청은 해당 관리 화면에서 구분하고 개별 블록 문서는 `/pages/:id`에 남는다. 임시 문서를 새로 자동 생성하지 않고 기존 문서는 일반 페이지로 보존한다. Capture 담기는 메모 상세에서 기존 페이지·새 하위 페이지를 골라 참조·내용 사본·선택 첨부를 원자적으로 추가한다. 선택 블록은 더보기에서 다른 페이지 끝으로 원자적으로 옮긴다. 부모와 자식을 함께 선택해도 중복 이동하지 않으며 두 문서 버전을 검사한다. 사이드바 검색과 `⌘K`는 통합검색을 열어 메모·AI 요청·페이지 제목/본문·파일명을 찾는다. 모바일에서는 터치로 누를 수 있는 블록 추가·이동 메뉴를 제공해 드래그에만 의존하지 않는다. 붙여넣은 URL은 우선 링크로 보존하고, 요약·조사는 사용자가 별도로 요청한다.

Mermaid는 일반 코드와 구분한 다이어그램 블록으로 편집·미리보기한다. Markdown의 `mermaid` 코드 울타리로 내보내고 다시 붙여넣을 수 있어야 한다. HTML이 있는 붙여넣기는 안전한 구조만 블록으로 변환하고, Markdown 텍스트는 제목·목록·체크리스트·코드 울타리를 블록으로 변환한다. 원문을 덮어쓰는 전체 문서 가져오기는 명시적인 동작으로 둔다.

페이지 체크박스는 처음에는 글의 일부다. 전체 할 일 목록에서 관리할 때만 `Task`로 등록하고, 이후 연결된 블록은 `Task` 상태를 표시·수정한다. 같은 할 일을 여러 페이지에 넣어도 `Task` 한 건을 참조한다. 체크박스를 누르는 것만으로 새 전역 할 일을 만들지 않는다.

## 3. 저장 형식과 이동성

- 기준 데이터는 `schemaVersion`이 있는 블록 JSON이다. `Page`는 `id`, `parentId`, `position`, 제목·아이콘, 문서 JSON, 편집 버전, 작성·수정 시각을 가진다. 각 블록에는 안정적인 ID가 있다.
- 이미지·파일 블록은 `Asset` ID를 참조한다. 저장 JSON에는 디스크 경로, 일회성 공유 URL, 원격 AI 제공자의 URL을 넣지 않는다. 외부 링크는 정규화한 원래 URL을 보존한다.
- 서버는 저장 때 허용된 블록 유형·속성·참조 ID와 문서 크기를 검사한다. 검색용 평문과 `PageReference(pageId, blockId, targetType, targetId)` 색인을 문서에서 다시 만든다.
- Markdown은 입력·가져오기·내보내기 형식이다. 전용 파일 블록과 내부 참조 등은 Markdown으로 완전히 왕복되지 않을 수 있다. 변환 전 미리보기와 손실 안내를 제공한다.
- 백업은 페이지 JSON과 `Asset` 파일을 함께 보존한다. 현재 Markdown 보기·복사는 파일 바이트를 포함하지 않는다. `page.md`와 첨부 파일의 묶음 내보내기는 후속 목표이며 전체 백업은 DB와 등록된 첨부를 함께 보존한다.

## 4. 자동 저장과 복구

입력 후 짧은 대기 시간에 자동 저장하고 화면에 `저장 중`, `저장됨`, `저장 실패`와 마지막 저장 시각을 표시한다. 저장 요청에는 읽은 편집 버전을 포함한다. 다른 탭이나 기기에서 먼저 바뀌었다면 서버는 충돌을 돌려주고 현재 입력을 보존한 채 비교·복사·다시 적용할 방법을 제공한다. 연결이 끊긴 동안의 미저장 입력은 브라우저 초안으로 복구를 제안한다.

DB 트리거는 페이지 생성과 버전 변경마다 `page_revisions`에 제목·아이콘·본문·기록 시각을 보관하고 페이지별 최신 100개를 유지한다. 기존 문서는 최초 이관 당시 현재 버전부터 기록한다. 내용을 읽기 전용으로 확인한 뒤 현재 `expectedVersion`과 UUID로 복원하며 현재 계층·정렬 위치를 유지한 새 버전을 만든다. 남아 있는 개인 수정본·템플릿의 첨부는 복구용으로 접근을 유지하지만 공유 파일 권한은 현재 본문의 직접 참조만 검사한다. 영구 파일 삭제는 제공하지 않는다.

### 페이지 도구와 일정

**페이지 복제**는 현재 문서만 같은 상위 아래 복사하며 하위 문서 트리를 제외한다. 본문의 기존 페이지 링크와 첨부를 재사용하고 블록 ID는 새로 만든다. **템플릿**은 저장 당시 제목·아이콘·본문 사본으로 새 문서를 만드는 사용자 페이지 템플릿이며 AI 프롬프트 템플릿과 별개다. 템플릿 삭제는 이미 만든 문서를 바꾸지 않는다.

**파일 첨부**는 Capture 없이 Page 소유 자산을 본문 끝에 넣는다. 최대 8개·개별 25MB·총 100MB다. 복제·템플릿 저장/생성·첨부·선택 블록 이동·수정본 복원은 최초 UUID/요청/응답으로 중복 재시도를 처리하고 버전 충돌은 거절한다. 미저장·오류·미해결 초안이나 결과 확인 대기 중에는 문서를 덮지 않는다.

`itinerary`는 한국시간 날짜·시간·일정·장소·좌표·링크·메모를 최대 50개까지 하나의 검증된 JSON 자료로 보관한다. 시간표와 지도는 같은 항목 ID를 선택하며 지도 펼치기 때만 Leaflet 1.9.4·OSM 타일을 불러온다. 방문 순서 점선은 실제 길찾기로 표현하지 않는다. 기존 표·단일 지도 문서를 유지하고 공개 뷰도 같은 자료를 사용한다. 자세한 계약은 [현재 규격](CURRENT_IMPLEMENTATION.md#일정-블록)과 [보존 설계](docs/superpowers/specs/2026-09-30-plan-page-preservation.md)를 따른다.

## 5. AI 결과와 공유의 경계

AI 결과는 편집기 밖에서 제안으로 표시한다. 사용자가 `페이지에 넣기`를 선택하면 선택한 문장·할 일·출처만 새 블록으로 삽입하고, 기존 블록은 별도 확인 없이 바꾸지 않는다. 원본 `Capture`와 `DerivedContent` ID는 비공개 출처 정보로 연결한다.

공유 페이지는 저장된 문서를 허용 블록만으로 읽기 전용 렌더링한다. 임의 HTML은 그대로 출력하지 않는다. 공개 HTML에는 편집 기능·비공개 출처 ID·원본 파일 경로를 넣지 않는다. 이미지·파일은 현재 공유 페이지 본문에 `asset` 블록으로 들어간 경우에만 토큰이 적용된 다운로드 경로로 해석한다. 비공개 내부 페이지와 하위 페이지는 자동 공개하지 않으며 링크를 눌러도 내용을 가져오지 않는다. 발급 화면은 현재 첨부 범위를 보여주고 발급된 링크로 방문자와 같은 뷰를 확인한다. 기존 공유 링크에는 이후 저장한 페이지 글과 새로 배치한 첨부 블록이 반영된다.

## 6. 편집기 후보와 채택 검증

[BlockNote](https://www.blocknotejs.org/docs)를 React 블록 편집기 후보로 둔다. 기본 블록·`/` 메뉴·한국어 UI·파일 업로드 연결을 제공한다. 공식 문서는 [블록 JSON 저장을 권장](https://www.blocknotejs.org/docs/foundations/supported-formats)하며 Markdown 변환은 일부 정보가 빠질 수 있다고 설명한다. 기본 라이브러리는 [MPL 2.0](https://www.blocknotejs.org/pricing)이고, 유료 또는 별도 라이선스 조건이 붙는 XL AI 기능은 사용하지 않고 앱의 기존 AI 작업 흐름을 연결한다.

구현 전 작은 검증에서 한국어 IME 입력, 모바일 붙여넣기·블록 이동, 이미지 업로드 후 재열기, 자체 `Asset` ID 저장, 읽기 전용 공유 렌더링, Markdown 왕복에서 생기는 손실을 확인한다. 이 조건을 충족하지 못하면 같은 블록 계약을 유지한 채 다른 편집기를 검토한다.

## 7. 수락 시나리오

1. 휴대폰에서 여행 페이지를 만들고 제목·체크리스트·외부 링크·사진을 넣은 뒤 PC에서 이어서 편집한다.
2. 입력함에 스크린샷을 빠르게 저장한 뒤 계획의 필요한 부분만 페이지로 옮긴다. 페이지에서 문장을 고쳐도 원본을 다시 볼 수 있다.
3. 페이지를 공유할 때 사진과 파일의 공개 범위를 선택한다. 방문자는 허용된 것만 읽고, 비공개 내부 페이지는 열지 못한다.
4. 두 기기에서 같은 페이지를 편집하면 뒤늦은 저장이 먼저 저장된 내용을 덮지 않는다. 연결이 끊겨도 미저장 입력을 복구할 수 있다.
5. 현재 Markdown을 복사하고 전체 백업에서 블록 문서와 첨부를 복원한다. Markdown과 첨부의 묶음 내보내기는 후속 수락 시나리오다.

## 8. 현재 구현 범위

첫 구현은 입력함과 같은 앱 화면에서 사이드바를 공유하며 모바일에만 작은 메뉴 줄을 둔다. 페이지 목록은 입력함에서도 같은 사이드바에 항상 나타나고, 이전 `/pages`·`/temp`는 `/memo`로 연결하고, 개별 문서는 `/pages/:id` 가운데 영역에서 제목 수정·문단·제목·접을 수 있는 제목·목록·체크리스트·접을 수 있는 목록·인용·코드·구분선·표·Mermaid·목차·하위 페이지 링크·이모지·블록 중첩(Tab과 드래그 메뉴)·되돌리기/다시 실행·Markdown 붙여넣기/보기/복사·자동 저장을 다룬다. 화면을 전환해도 작성 중인 빠른 입력은 남고, 모바일의 하단 바로 기록하기는 페이지에서도 사용할 수 있다. 입력함 초기 번들에는 편집기 코드를 넣지 않는다. 페이지 URL은 안정적인 ID를 사용하고, 서버는 블록 JSON을 버전과 함께 저장해 다른 탭의 늦은 저장을 거절한다. 브라우저 초안은 복원 선택 전까지 새 입력으로 덮지 않는다. 입력 항목 연결·첨부 재사용은 구현했으며 원본 참조·파일 블록은 앱 전용 ID를 저장한다. Markdown 보기·복사는 설명·ID를 포함하고 파일 바이트는 제외한다. 단일 페이지 복제·사용자 템플릿·직접 첨부·선택 블록 이동·최근 100개 수정 이력·일정과 지도도 구현했다. 로컬 읽기 전용 공유 링크는 현재 Page와 그 본문 첨부만 공개한다. 사이드바 백업에서는 기본 꺼짐의 한국시간 일일 예약·수동 실행·검증 후 보관 정리를 제공하며 복원은 CLI의 새 경로만 사용한다. 방문자 댓글·본인 인증·공개 도메인 운영은 후속 단계다. 현재 문서·직접 첨부의 오프라인 ZIP과 개인 댓글 저장은 구현했다.
