# leneu: 제품 설계와 단계별 개발 계획

작성: 2026-09-26
상태: 전체 제품의 목표 계획. 입력함·블록 페이지·개인 통합검색·메모 정리 완료/복귀·선택적 메모/페이지 AI·명시적 결과 반영과 제한된 되돌리기·로컬 읽기 전용 공유·일정 지도·페이지 도구·수정 이력·자동 백업은 구현되었으며, 지금 실행되는 API·저장·날짜·업로드 규격은 [현재 구현 규격](CURRENT_IMPLEMENTATION.md)을 따른다. 본인 인증·실제 공개 주소 연결·미니PC 운영·OCR·원격 백업은 후속 목표다.

## 1. 목표와 운영 전제

leneu는 개인이 일상적으로 보내 놓는 메모, 스크린샷, URL, 계획, 조사 주제, 파일을 빠르게 수집하고 다시 쓰기 좋은 형태로 정리하는 웹 공간이다. AI는 원본을 대체하지 않고 OCR, 할 일, 계획, 요약, 조사 결과를 제안한다. 사용자는 필요할 때 정리한 페이지 또는 지정한 파일만 읽기 전용 링크로 공유한다.

가장 중요한 제품 품질은 **빠른 입력과 즉각적인 반응**이다. 자주 여는 입력함을 가볍게 유지하고, 블록 편집·AI 처리·파일 미리보기는 필요한 화면이나 작업에서만 불러온다.

- 주 사용자는 한 명이다. 공개 회원가입, 팀 권한, 공동 편집은 설계 범위에 넣지 않는다.
- 공유받은 사람은 계정이나 로그인 없이 링크로 읽기만 한다. 업로드와 편집은 할 수 없다.
- 본인은 휴대폰과 PC의 브라우저에서 입력·검색·편집한다.
- 개발은 현재 로컬 컴퓨터의 Docker 환경에서 시작하고, Linux 미니PC로 옮겨 운영한다. 같은 코드와 Compose 구성을 사용하되 호스트 CPU에 맞는 이미지를 빌드한다.
- N100·16GB RAM·512GB SSD 미니PC는 웹 앱·DB·파일·작업 상태를 운영한다. 생성형 LLM의 상시 실행은 기본 구성에서 제외하고, 사용자가 요청하면 설치된 에이전트나 외부 AI API로 처리한다. 한국어 OCR 등 작은 로컬 처리기는 실제 입력과 장비에서 검증한 뒤 선택적으로 추가할 수 있다.

구체적인 프로세스 구성, 에이전트/API 연결 계약, 도메인 없는 공개 주소 대안은 [기술 아키텍처](TECH_ARCHITECTURE.md)에 정리한다.

### 완료 기준

1. 휴대폰에서 메모·URL·스크린샷을 빠르게 저장하고 최근 목록과 검색에서 원본을 다시 연다.
2. 여행/계획 블록 페이지를 만들고 입력 항목을 연결하며 다른 기기에서 이어서 편집한다.
3. 스크린샷 원본, 인식한 텍스트, 제안된 할 일을 한 화면에서 확인한다.
4. URL 원문과 추출한 제목을 보존하고 출처가 연결된 3줄 요약을 확인한다.
5. 여행 페이지를 공유할 때 선택한 파일만 노출하고, 링크를 폐기하면 방문자가 더 이상 열 수 없다.
6. 새 호스트에서 백업한 DB와 파일을 복원하여 위 내용과 공유 상태를 확인한다.

## 2. 제품 흐름

2026-09-28 제안에서는 **독립적인 투두**, **사이트에서 관리하는 프롬프트**, **URL 리서치·자유 AI 요청**을 나눈다. 아래의 고정 OCR·추출·정리 작업은 이전 전체 구상이며 초기 AI 구현에 강제하지 않는다. 최신 초안은 [투두 설계](docs/superpowers/specs/2026-09-28-task-workspace-design.md)와 [AI·프롬프트 설계](docs/superpowers/specs/2026-09-28-ai-request-harness-design.md)를 따른다. 투두와 서버 프롬프트 관리·안전한 이관은 구현했다. Capture→Page·파일 참조와 AI 작업 큐·URL/키워드 수집·상태/결과/이력·명시적 재요청까지 구현했다. 주제는 메모에 적고 AI 체크·키워드 리서치 선택·저장 후 AI 탭 상세에서 결과와 확인 출처를 읽는다. URL이 있으면 URL 경로를 우선하고 자유 요청은 검색하지 않는다. 실행기는 기본 비활성이며 Devin CLI 또는 HTTP 게이트웨이를 설정한다. 키워드 검색은 OpenCode·Devin이 지원하고 Hive/HTTP는 URL 리서치만 지원한다. 검색·요약 CLI 2회와 수집은 작업 전체 120초·동시 작업 1개 한도를 공유하고 실패는 원본을 보존하며 자동 재실행하지 않는다. 현재 계약은 [AI 실행 설계](docs/superpowers/specs/2026-09-29-ai-execution-design.md), [키워드 확장 설계](docs/superpowers/specs/2026-09-29-keyword-research-design.md)와 [현재 규격](CURRENT_IMPLEMENTATION.md#ai-요청-실행)을 따른다.

`빠른 입력 → 비공개 원본 저장 → 검색·다시 찾기 → 필요할 때 페이지 정리 또는 AI 처리 → 선택적 공유`

### 입력함

- 첫 화면은 블록 편집기와 별개의 간단한 입력 영역이다. `텍스트 / URL / 이미지·파일`을 빠르게 저장하고, 붙여넣기와 모바일 파일 선택을 우선한다.
- 저장 시 동작을 고른다: `보관만`, `할 일 추출`, `계획 정리`, `3줄 요약`, `조사하기`. 입력 유형에 맞는 선택지만 표시한다.
- 저장은 AI 처리보다 먼저 완료한다. 처리 중·완료·실패 상태와 재시도 버튼을 항목에 표시한다.
- 현재 홈은 빠른 입력·할 일·정리 전 일반 메모 최근 3개, `/memo`는 종류별 필터·검색·상세 수정을 제공한다. 메모 AI 요청은 `/memo?view=ai`의 별도 탭이며 **입력함 / 정리 완료**를 선택한다. 기본 목록·개수·통합검색에는 정리 완료 메모를 포함하지 않는다.
- 입력 항목은 `Capture` 원본으로 남는다. 메모·AI 요청과 결과는 `/memo`에서 관리하고, 블록 문서는 `/pages/:id`에서 직접 편집한다. 선택한 자료·검토한 완료 결과를 기존 페이지나 새 페이지·새 하위 페이지에 담으면 원본은 정리 완료가 되고 **입력함으로 되돌리기**로 복귀한다. 원문·첨부·요청/결과 이력은 보존하며 본문에 원본 메모 카드·태그를 자동으로 넣지 않는다. 새 출처와 기존 가져오기·참조 출처는 개인 페이지 정보에서 확인한다. 기존 원본 블록은 숨기되 저장된 JSON을 보존하며 이전 문서를 일괄 변경하지 않는다. 하나의 임시 문서를 필수 단계로 두지 않는다. 기존 임시 문서는 보존하며 `/pages`·`/temp` 진입은 `/memo`로 연결한다. 선택 블록 이동은 두 문서 버전을 검사하는 페이지 도구로 구현했으며 선택한 AI 결과의 Task 채택도 구현했다.
- 첫 화면은 입력 영역과 최근 항목만 먼저 보여준다. 블록 편집기, AI 도구, 전체 이미지 원본은 처음부터 내려받지 않는다. 저장 성공은 서버 확인 후 표시하고 처리 작업은 그 뒤에 시작한다.

### AI 정리 규칙

- **스크린샷:** OCR 텍스트를 기록하고, 행동 문장으로 판단된 내용만 할 일 후보로 추출한다. 날짜·담당자·우선순위가 분명하지 않으면 추측해 확정하지 않는다.
- **자유 형식 계획:** 목적, 단계, 선행 관계, 할 일 후보, 미정 사항으로 구조화한다. 원문과 구조화 결과를 함께 보여준다.
- **URL:** 원본 URL, 가져온 시각, 제목, 사이트 이름, 추출한 본문 또는 추출 실패 이유를 보존한다. 요약은 핵심·근거/맥락·다음 행동의 3줄로 만든다. 원문에 없는 사실은 추가하지 않는다.
- **조사 주제:** 질문을 명시하고 출처 URL이 있는 결과만 모아 요약한다. 현재 URL 없는 리서치는 Devin 검색 후보 최대 5개를 순차 수집해 고유 최종 URL의 본문 최대 3개만 요약한다. 검색 미지원·확인 본문 없음은 한국어 실패 안내로 남기고 부분 수집은 결과에 표시한다. 무제한 웹 탐색·예약 리서치는 후속 범위다.
- AI 결과는 제안이다. 원본 수정과 할 일 확정은 사용자가 한다. 어떤 입력과 처리 설정에서 생성됐는지 기록해 재생성·비교할 수 있게 한다.
- 현재 **결과를 페이지로 정리**는 선택한 완료 작업의 결과·출처 전체를 블록으로 담고 원본은 정리 완료로 보관한다. 기본은 새 페이지이며 기존 페이지·새 하위 페이지도 선택할 수 있다. 제출 시 Markdown parser를 지연 로드하고 Page는 `schemaVersion: 1` 블록 JSON으로 저장해 바로 편집·전체 Markdown 보기·복사를 제공한다. 원본 Capture·AI 요청 사본·작업 결과는 보존한다. 문서·참조·출처·정리 상태·영수증은 원자적으로 저장한다. 제출 UUID·작업 ID·변환 문서·대상·선택을 고정해 응답 유실 뒤 같은 요청을 확인하며 새로운 UUID로 명시적으로 다시 담을 때만 새 블록 ID를 만든다. 이전 UUID 재전송으로 입력함에 복귀한 원본을 다시 정리하지 않는다. [결과 페이지 정리 설계](docs/superpowers/specs/2026-09-29-ai-result-page-design.md)와 [수명 주기·Page AI 설계](docs/superpowers/specs/2026-09-29-memo-page-lifecycle-design.md)를 따른다.
- 현재 Page AI는 저장된 전체 문서 또는 선택한 편집 가능 블록을 서버에서 64,000자 이내 Markdown으로 만든다. 제목·전체 블록 문서·버전·선택 루트·요청문은 고정하고 참조 대상 본문·첨부 바이트는 자동으로 보내지 않는다. 실행 중 문서는 계속 편집한다. 완료 결과는 **본문 아래 추가 / 선택한 블록 교체 / 새 하위 페이지**로 명시 반영하며 교체는 비어 있지 않은 선택과 요청 버전이 유지된 경우만 가능하다. 적용/되돌리기는 현재 버전을 검사하고 추가·교체 직전 문서를 원자적으로 보존한다. 반영 후 편집은 되돌리기로 덮지 않는다. 하위 Page는 기존 휴지통으로 되돌린다. 일반 수정 이력은 별도로 최근 100개를 읽기 전용으로 확인하고 현재 계층을 유지한 새 버전으로 복원한다.
- Page 요청·반영·되돌리기의 UUID와 최초 본문은 브라우저에 보존해 이동·새로고침·응답 유실에도 재사용한다. 확인 대기 중 새 AI 제출을 막고 반영/되돌리기는 Page 편집도 잠근다. 이전 영수증 확인 뒤 최신 Page를 조회해 늦은 응답이 새 편집을 덮지 않게 한다. 미저장·충돌·미해결 초안 복구 상태에서는 저장 문제를 먼저 해결한다. 기존 메모 작업 이관은 요청·결과·ID·재시도 관계를 보존한다.
- **현재 메모로 다시 요청**은 최신 저장 원문과 처음 보관한 템플릿·추가 지시를 사용하고 **실패한 요청 그대로 재시도**는 실패한 작업의 사본을 사용한다. **요청 당시 입력·프롬프트**에서 선택한 작업의 기준을 확인한다. Devin CLI는 실행기이며 앱이 설정한 모델(기본 `swe-2-high`)을 명시적으로 전달한다. 모델 설정과 미보고 사용량 `null`을 유지하며 비용을 추정하지 않는다.
- 에이전트 실행 또는 외부 AI API 호출을 선택한 작업에만 필요한 내용을 전달한다. 앱이 보유하는 API 키는 서버 비밀값으로 보관한다.

### 페이지와 할 일

- 페이지는 제목과 순서를 바꿀 수 있는 블록으로 구성한다. 문단·제목·목록·체크리스트·인용·코드·구분선·이미지·파일·외부 링크·내부 페이지/입력 항목 링크를 첫 범위에 둔다.
- `#`, `-`, `[]` 같은 Markdown 입력 단축키와 `/` 블록 메뉴를 제공한다. Markdown 가져오기·내보내기를 지원하되, 블록 데이터가 원본이며 변환 과정에서 전용 블록 정보가 빠질 수 있음을 표시한다.
- 입력 항목의 선택한 내용을 블록으로 복사해 편집할 수 있다. 원본 항목과의 출처 관계는 본문 밖에 유지하고 AI 결과는 사용자가 명시적으로 반영한다.
- 페이지 안의 체크리스트는 그 페이지의 내용이다. 전체 할 일 목록에 올릴 때만 `Task`로 명시적으로 등록해 중복 작업 생성을 막는다.
- 페이지는 자동 저장 상태와 마지막 저장 시각을 표시하고, 다른 탭·기기의 동시 수정은 버전 충돌로 감지해 어느 쪽도 조용히 덮어쓰지 않는다.
- AI가 추출한 할 일은 먼저 제안으로 보관한다. 사용자가 제목과 기한을 확인해 확정하면 실제 할 일이 되고 `진행 전 → 진행 중 → 완료` 상태를 가진다.
- 현재 통합검색은 메모 원문·URL, 준비된 AI 요청의 불변 사본, Page 제목·평문 본문·링크·표·Mermaid, 첨부 파일명을 찾는다. OCR 텍스트·완료 AI 결과·Task도 검색한다. 일반 URL 수집 아카이브 본문 검색은 후속 목표다. 현재 파일 본문·공개 검색은 포함하지 않는다.

블록 편집기의 저장 형식·파일 참조·공유 렌더링·복구 동작은 [페이지 편집 설계](PAGE_EDITOR_DESIGN.md)에 구체화한다. 빠른 입력은 `Capture`, 정리한 글은 `Page`로 구분한다.

## 3. 권한과 공유

아래는 운영 단계의 후속 목표다. 현재는 루프백의 개인 API와 별도 토큰 검사 공유 서버를 제공한다. 본인 인증과 공개 도메인 연결은 아직 없다.

- 개인 화면과 API는 Tailscale Serve로 tailnet 안에서만 제공한다. 첫 버전에는 별도의 앱 비밀번호·가입 화면을 만들지 않고, Serve가 전달한 본인 Tailscale 로그인 식별자만 허용한다. 식별자가 없거나 다른 사용자면 거부한다.
- 개인 서비스는 호스트의 루프백에만 바인딩한다. 개발 환경에서 인증을 생략할 때도 로컬호스트에서만 동작하게 하고, 운영 설정에서는 개발용 우회를 허용하지 않는다. 쓰기 요청은 출처/CSRF 검사를 한다.
- 방문자는 난수 토큰이 포함된 `/s/...` 링크만 연다. 토큰은 서버에서 해시로 보관한다.
- 공유 대상은 `페이지` 또는 `단일 파일`이다. 기본값은 비공개이며, 공유 화면에서 읽기 전용 링크를 생성·복사·만료·폐기한다.
- 공유용 공개 주소는 개인 서비스와 다른 진입점에 연결한다. 공유 서비스는 읽기 전용 공유 페이지·파일 경로만 제공하고 개인 API, 검색, 업로드, AI 실행, 관리 기능을 등록하지 않는다.
- 공유 페이지에서 보이는 첨부 파일은 사용자가 공유 대상으로 포함한 파일만이다. 내부 링크가 다른 비공개 페이지로 이어지더라도 방문자는 열 수 없다.
- 공유 미리보기는 실제 방문자 권한으로 렌더링한다. 검색 엔진 색인 방지 헤더를 붙이지만, 링크를 가진 사람이 복사할 수 있다는 전제로 UI에 공유 범위를 보여준다.
- 공유 방문자에게 업로드, 편집, AI 실행, 검색, 계정 기능은 제공하지 않는다.

Tailscale Serve는 개인용 연결과 사용자 식별을 맡고, Cloudflare Tunnel은 공유용 공개 연결만 맡는다. 공개 주소의 접근 권한은 앱의 공유 토큰으로 판정한다. `개인용 주소를 다른 서브도메인으로 적는 것`만으로 개인 서비스가 보호되지는 않으므로 공개 Tunnel은 개인 서비스를 가리키지 않는다. 제3자에게 Tailscale 또는 Cloudflare Access 계정을 발급할 계획은 없다.

## 4. 데이터와 파일 저장

첫 버전은 단일 호스트의 SQLite DB와 로컬 파일 저장소를 사용한다. 여러 사용자의 동시 대량 쓰기가 없는 현재 요구에 맞고 설치·이전·백업이 단순하다. 파일 내용은 DB에 넣지 않는다.

아래 개념 표는 OCR·공유·일반 변경 이력까지 포함한 목표다. 현재 Capture에는 제목·영구 체크섬 필드가 없다. Page는 AI 반영 직전의 제한된 되돌리기 외에도 모든 저장 버전의 최근 100개 일반 수정본을 보관한다. 사용자 페이지 템플릿·작업 영수증과 Page 직접 첨부도 구현했다. 정리 상태·`page_origins`·AI 반영/되돌리기 영수증의 실제 테이블은 [현재 데이터 규격](CURRENT_IMPLEMENTATION.md#데이터-규격)을 따른다.

| 개념                                      | 책임                                                            |
| ----------------------------------------- | --------------------------------------------------------------- |
| `Capture`                                 | 입력 유형, 원문·URL, 제목, 생성 시각, 처리 상태, 원본 파일 연결 |
| `Asset`                                   | 파일 식별자, 저장 키, 크기, MIME 유형, 체크섬, 원래 파일명      |
| `ProcessingJob`                           | 작업 종류, 입력 버전, 상태, 시도 횟수, 실패 원인                |
| `DerivedContent`                          | OCR·요약·계획 등 결과, 원본 연결, 생성 설정·버전                |
| `Task`                                    | 확정된 할 일, 상태, 기한, 원본 연결                             |
| `Page` / `PageRevision` / `PageReference` | 버전이 있는 블록 문서, 복구 이력, 명시적 첨부·내부/외부 링크    |
| `ShareGrant`                              | 공유 대상, 토큰 해시, 만료·폐기 상태                            |

- 파일은 `/data/blobs` 아래 불투명한 저장 키로 둔다. 사용자 파일명은 표시용 정보로만 보존한다. 공개 URL에 디스크 경로를 직접 노출하지 않는다.
- 업로드는 임시 파일에 스트리밍한 뒤 크기·유형·체크섬을 확인하고 저장소로 옮긴다. DB 등록 실패 등으로 생긴 고아 파일은 정리한다.
- 파일 다운로드는 항상 앱을 거쳐 Tailscale에서 확인한 본인 또는 유효한 공유 권한인지 검사한다.
- 검색 색인은 DB에서 재구축할 수 있는 파생 데이터다. 현재 NFC·소문자·리터럴 기호의 한국어 부분 검색은 두 코드 포인트 이상 단어 하나를 요구하며 `교토 3` 같은 혼합 한 글자 조건을 지원한다. 원본과 같은 트랜잭션에서 갱신하고 최초 backfill·v2 이관 뒤 정상 재시작에는 재색인하지 않는다.
- 현재 수동/자동 백업 단위는 일관된 DB 스냅샷과 그 DB가 참조하는 `/data/blobs` 파일이다. 미등록 임시/고아 파일은 제외한다. 파일 크기·SHA256과 DB 무결성을 확인하고 새 경로에 복원한다. DB만 복사하는 백업은 완료로 보지 않으며 일일 한국시간 예약·수동 실행·검증 후 보관 정리는 구현했다. 기본은 꺼짐·04:00·7개 보관(1~60개)이며 원격 보관은 운영 단계에서 붙인다.
- 다른 호스트로 옮길 때 Compose 설정, 비밀값, 백업 데이터만 있으면 복원할 수 있게 한다.

## 5. 앱 구조와 처리 흐름

```text
브라우저 ──> 웹 앱/API ──> SQLite
                 │            └── 작업 상태·검색·공유 권한
                 ├────────> /data/blobs
                 └── 작업 요청 ──> 백그라운드 작업자
                                   ├── OCR/AI 제공자
                                   └── URL 본문 추출
공유 방문자 ──> 공유 전용 진입점 ──> /s/... ──> 앱의 공유 권한 검사
```

- 웹 요청은 업로드와 조회를 처리하고, 오래 걸리는 OCR·요약·조사는 지속성 있는 작업 큐에 넣는다. 현재 작업자는 재시작 시 대기 작업을 보존하고 미완료 실행은 interrupted 실패로 남긴다. 비용이 드는 호출은 자동 재실행하지 않는다.
- 동일한 작업 요청의 중복 실행으로 할 일이 여러 번 생성되지 않게 입력 버전과 작업 종류를 기준으로 결과를 관리한다.
- OCR, 요약, 계획 정리, 조사는 공통 작업 계약을 쓴다. 사용자가 실행을 요청하면 작업자가 설치된 에이전트를 호출하거나 설정된 외부 AI API를 호출한다. 어느 쪽도 준비되지 않았으면 실행 불가 상태를 보여주고 원본 저장·검색·공유는 계속 가능하다. 현재 작업별 시각·오류·보고받은 토큰 사용량을 기록하며 미보고는 null이다. 외부 비용 집계는 후속 목표다.
- URL 수집은 HTTP/HTTPS 공개 주소만 허용하고, 내부망·로컬 주소와 위험한 리다이렉트를 차단한다. 가져오기 시간·크기에 제한을 둔다. 가져온 본문은 AI 명령이 아니라 분석할 데이터로 취급한다.
- 외부 사이트가 차단하거나 본문 추출에 실패하면 URL 원본은 남기고 이유를 보여준다.

### 기술 선택 초안

- 현재 입력함: React·TypeScript·Vite 화면과 Node 24 HTTP API·단일 비동기 AI 작업자를 하나의 서버 프로세스/DB로 실행한다. 작업자 별도 서비스 분리는 후속 설계다. 기본 Docker 이미지에는 Devin CLI·인증이 없다.
- DB: SQLite. 통합검색은 같은 contentless FTS5 안의 위치 인코딩 두 글자 토큰·고유 문자 열로 구현했다. 별도 검색 서비스·LLM·새 패키지는 추가하지 않는다. 20개 결과·변경 번호 커서·리셋과 기존 LIKE/제목 선택기 계약은 [현재 규격](CURRENT_IMPLEMENTATION.md#통합검색)을 따른다.
- 파일: 호스트 영속 볼륨. S3 호환 저장소가 필요해질 때만 저장 어댑터를 추가한다.
- 후속 배포: Docker Compose의 개인 웹·공유 웹·작업자·영속 볼륨과 선택적 에이전트 실행기·`cloudflared` 서비스. 개인 웹은 Tailscale Serve가 연결하는 루프백 포트만 열고, 공개 Tunnel은 공유 웹만 가리킨다. 공개 웹과 개인 웹의 컨테이너 네트워크도 분리한다. DB 포트는 공개하지 않는다.
- 첫 입력함의 프레임워크와 저장 계층은 [현재 구현 규격](CURRENT_IMPLEMENTATION.md)에 확정했다. Devin CLI·HTTP 게이트웨이 계약은 구현했고 배포 대상의 실행기 설치·인증·제공자 선택은 별도로 확인한다.

## 6. 배포와 운영

개인/공유 서비스 분리는 로컬 Compose에 적용했다. 자동 백업은 개인 `/backups`와 별도 `./backups:/backups` 볼륨에 구현했다. Tailscale 인증·공개 Tunnel·원격 보관은 후속 계획이다. N100 운영 검증도 아직 수행하지 않았다.

- 로컬에서는 Compose로 개인·공유 화면을 각각 `localhost` 포트에서 개발하고, 실제 공유 권한을 두 주소에서 검증한다. DB·업로드 파일은 영속 볼륨에 두고 코드·이미지에 호스트 경로와 도메인을 고정하지 않는다.
- 미니PC로 옮길 때는 대상 CPU용 이미지를 빌드하고 Compose 설정·비밀값·DB와 파일의 일관된 백업을 복원한다. 복원 확인 뒤 Tailscale Serve를 개인 웹에, 본인 도메인의 Cloudflare Tunnel을 공유 웹에 연결한다.
- 개인 주소는 미니PC의 `*.ts.net` Serve 주소를 쓰면 별도 개인용 도메인이 필요 없다. 공유 주소는 예를 들어 `share.example.com` 같은 공개 서브도메인을 쓴다. 도메인 구매 전 공개 공유 시범 운영에는 Tailscale Funnel을 공유 전용 서비스에만 연결할 수 있다.
- 개인 업로드는 Tailscale Serve를 지나므로 Cloudflare 무료 요금제의 요청당 100MB 제한을 받지 않는다. 단일 파일 90MB는 초기 구상이었고 현재 구현 상한은 25MB다. 사용량을 보고 조정한다. 공개 공유 진입점에는 업로드 기능이 없다.
- 앱 업데이트 전 백업, DB 마이그레이션, 실패 시 복원 절차를 문서화한다. 주기적 백업은 다른 디스크나 원격 위치에 보관한다.
- 로그에는 원문 메모·AI 입력·공유 토큰·비밀값을 남기지 않는다. 실패 원인과 작업 ID는 기록한다.

## 7. 순차 개발 계획

2026-09-30 현재 구현과 남은 독립 작업의 구체적인 순서·완료 기준은 [개인 작업 공간 완성 순서](docs/superpowers/plans/2026-09-30-solo-workspace-roadmap.md)를 따른다. 페이지의 [블록 댓글 미리보기](docs/superpowers/specs/2026-09-30-block-comments-preview-design.md)는 당시 UI 시안 기록이다. 현재 개인 댓글은 서버에 저장하며 공개 링크에서는 댓글을 표시하거나 저장하지 않는다. 로컬 읽기 전용 공유 범위는 [공유와 계획 페이지](SHARING_AND_PLANS.md)에 정리했다. 요청한 1·2·3의 일정/지도·페이지 도구·수정 이력/자동 백업은 [보존 설계](docs/superpowers/specs/2026-09-30-plan-page-preservation.md)와 [구현 계획](docs/superpowers/plans/2026-09-30-plan-page-preservation.md)에 따라 구현했다. 프롬프트 수정본 조회·초안 복원, OCR 게이트웨이와 오프라인 ZIP도 구현했다. 방문자 댓글 정책·실제 실행기 연결과 외부 운영은 후속 범위다.

각 단계는 실제로 사용할 수 있는 상태로 끝낸다. 뒤 단계의 데이터 구조를 고려하되, 기능은 순서대로 붙인다.

첫 구현 결과물은 **화면 열기 → 한 줄 메모 또는 스크린샷 붙여넣기 → 저장 확인 → 최근 목록에서 다시 열기**까지 실제 SQLite·파일 저장을 통과하는 흐름이다. 첫 화면과 항목 상세만 먼저 만든 뒤 블록 페이지로 확장한다.

| 단계                | 구현 범위                                                                                             | 완료 확인                                                             |
| ------------------- | ----------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 0. 로컬 기반        | Compose 앱 골격, SQLite·파일 저장, 개인/공유 실행 모드, 기본 백업·복원, 성능 계측                     | 로컬에서 메모·파일이 재시작 후 남고 공유 모드에 개인 경로가 없음      |
| 1. 빠른 입력        | 텍스트·URL·스크린샷·파일 저장, 최근 목록·상세·검색, 모바일 붙여넣기                                   | 휴대폰에서 저장 후 원본을 바로 다시 찾고 입력 화면 성능 목표를 확인   |
| 2. 블록 페이지      | 가벼운 편집기 후보 검증, 기본 블록·Markdown 단축키, 자동 저장·복구, Capture→Page 연결, 첨부·외부 링크 | 여행/계획 페이지를 PC·모바일에서 만들고 수정·재접속·충돌 후 내용 보존 |
| 3. AI 처리          | 지속성 작업 큐, 설치형 에이전트 실행기, 선택적 API, OCR·할 일·계획·URL 요약 결과 계약, 실패·재시도    | 저장 속도에 영향 없이 버튼 실행부터 제안 검토까지 확인                |
| 4. 공유             | 페이지·파일 읽기 전용 링크, 명시적 첨부 범위, 만료·폐기·미리보기                                      | 로컬 공유 모드에서 비공개 내용 누출 없이 열고 폐기 후 접근 거부       |
| 5. 미니PC 이전·운영 | N100용 이미지, 백업 복원, Tailscale Serve·공유 Tunnel, 출처 있는 조사, 자동 백업·상태 확인            | N100에서 같은 자료·권한·응답성을 확인하고 장애 복구 연습              |

### 응답성 목표와 확인 방법

개인 통합검색의 이전 확장은 2026-09-29 구현·독립 리뷰(UI ship, 코드 승인·조합 Escape minor M1)·문서화를 마쳤다. 당시 저장소/API 전체 77/77 테스트·빌드·scoped/full Chrome QA와 6장 화면 증거는 [검증 기록](.omo/evidence/unified_search.md)에 있다. 이 기록은 메모 수명 주기·Page AI의 최종 테스트 수가 아니며 운영·공유·자동 백업·OCR 완료를 뜻하지 않는다. 네이티브 OS IME 전체 시퀀스는 미검증이다.

- 퀵 입력 화면은 페이지 편집기와 AI SDK를 번들에 포함하지 않는다. 편집기는 페이지 진입 시에만 불러오고, 이미지는 목록에서 작은 미리보기만 요청한다.
- 실제 사용할 휴대폰에서 입력 화면의 LCP 2.5초 이하, INP 200ms 이하를 목표로 한다. 화면은 터치·키 입력에 즉시 반응하고, 저장 중/완료/실패를 분명히 표시한다. 이 수치는 75번째 백분위의 웹 성능 지표이며 실제 로컬·Tailscale 환경에서 별도로 측정한다.
- 작은 텍스트 메모의 서버 저장 응답은 로컬 네트워크에서 p95 300ms 이하를 초기 목표로 둔다. 파일 업로드·AI 실행은 이 수치와 분리해 측정한다. 수치가 맞지 않으면 측정 결과를 보고 병목을 고친다.
- 최근 목록은 필요한 건수만 읽고, 페이지는 샘플 데이터 1,000개·블록 100개 수준에서 실제 기기로 확인한다. 현재 통합검색은 임시 1만·10만 혼합 자료의 저장소 호출·색인 크기·RSS를 Apple M1 Max에서 측정했다. [v2 보고서](.omo/evidence/search-benchmark-v2.json)의 수치를 N100·HTTP·브라우저 지연으로 환산하지 않으며 대상 장비에서 다시 측정한다. AI가 느리거나 실패해도 원본 저장·검색·편집은 계속 동작해야 한다.

### 범위 밖에서 시작할 것

다중 사용자 권한, 협업 편집, 공개 가입, 메신저 자동 수집, 캘린더 자동 수정, 모든 파일 형식의 미리보기, 무제한 웹 탐색 에이전트는 지금 설계의 필수 기능으로 두지 않는다. 실제 사용 패턴이 확인되면 별도 단계로 추가한다.

## 8. 결정 사항과 구현 직전 선택

1. **AI 처리:** 생성형 정리·요약·조사는 사용자가 요청할 때 설치형 에이전트 또는 외부 AI API 중 준비된 경로를 호출한다. 두 방식의 결과 형식은 같다. 한국어 OCR과 소형 로컬 모델은 품질·속도·메모리 검증을 통과할 경우에만 별도 처리기로 추가한다. 에이전트 제품과 인증 방식은 구현 직전에 선택한다.
2. **파일 크기:** 초기 구상은 단일 파일 90MB였으나 현재 구현은 25MB다. 실제 사용량을 보고 배포 전 상한을 다시 결정한다. 분할 업로드는 수요가 생길 때 추가한다.
3. **개인 접근:** 첫 버전은 Tailscale Serve의 본인 식별과 tailnet 접근 정책을 사용하고 앱 비밀번호는 두지 않는다. Tailscale 계정 문제는 연결된 로그인 제공자에서 복구하고, 미니PC의 로컬 콘솔/관리자 접속으로 Serve 재설정이나 데이터 복원이 가능하게 한다.
4. **공개 주소:** 개인은 `*.ts.net` Serve 주소, 공유는 전용 공개 서브도메인을 쓴다. 도메인 구매 전에는 공유 전용 서비스에 한해 Tailscale Funnel로 시범 운영할 수 있다.
5. **입력과 페이지:** 빠른 입력은 간단한 `Capture`로 저장하고 필요할 때 선택한 내용·첨부·AI 결과를 블록 `Page`로 정리한다. 성공한 원본은 정리 완료로 보관하고 복귀할 수 있다. 출처는 본문 밖에 남기며 저장 Page AI 결과는 버전 검사 후 명시 반영한다. 블록 문서는 기준 데이터로 저장하고 Markdown은 입력·교환 형식으로 사용한다.
