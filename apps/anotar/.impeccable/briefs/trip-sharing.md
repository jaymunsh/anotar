# 여행 공유서의 읽기 구조

## 목적과 사용자

모드: Read. 한국 출발 여행을 공유받은 사람이 예약 전 준비부터 당일 이동·지연 대안까지 파악한다. 편집자는 동일한 문서에서 노션형 블록과 시간표를 바로 수정한다.

## 방향

- 기존 종이/숲색·차콜/세이지·한 열 지도와 목록 목차를 유지한다.
- 짧은 날짜·미예약 안내 → 기존 목록 목차 → 날짜별 동선·마감/대안·지도·시간표 → 출발 전 예약·준비 → 예산 상세·교통/도움말·출처 순서. 전체 동선·예산 가정은 예산 영역의 참고 토글에 보존한다.
- 미발권 후보/예약 확인 전과 계획 시간을 분명히 표시한다. 실제 가격·예약 상태를 임의로 확정하지 않는다.
- 주요 교통 행은 노선/환승/소요/비용·주의 문장을 줄로 구분한다. 설명을 접어 숨기지 않는다.
- `노선 · 내용`처럼 명시한 속성은 PC의 라벨/본문 열, 모바일의 라벨 다음 줄로 읽는다. 저장된 메모에서 사실이나 값을 자동 추론하지 않는다. 일반 문장·URL·시간별 지시는 그대로 보존한다.
- 일정 외곽 카드 테두리·안쪽 여백을 제거하고 행 구분선과 시간축을 쓴다. 일정 본문 14px, 제목 PC 15px/모바일 14px. 문서 H2 24px/H3 20px와 본문 줄 간격 1.65를 공유 화면에도 맞춘다.
- 직접 편집 중 Tab/Shift+Tab은 현재 값을 검증·반영한 뒤 다음/이전 보이는 속성을 연다. 오류면 현재 입력을 유지한다. 설명 편집 시작 시 읽기 높이를 최소 높이로 유지한다. 사용법은 일정 설정 메뉴에서 확인한다.
- 준비사항이 있을 때만 본문에 실제 제목·체크박스를 표시한다. 빈 0/0·준비 버튼을 반복하지 않는다. 개인 관계 관리와 공유 opt-in은 행 ··· 메뉴에서 한다.
- 기존 블록 ID·57개 항목 ID/시간·4개 지도 asset/source/input·출처 URL·댓글 앵커를 보존한다.
- 무관한 예시 Task는 문서의 관계만 해제하고 원본 Task를 보존한다. 문서 저장은 원문 사본과 expectedVersion을 사용한다.
- PC1440·모바일390/320과 공개 읽기 뷰를 같은 자료로 확인한다. 공개 링크 신규 발급이나 실제 지도/AI API 호출은 하지 않는다.
