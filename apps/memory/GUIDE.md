## 이 위키가 하는 일

내가 AI(Claude Code, Codex, opencode)와 한 작업을 자동으로 모아서 **무엇을 했고, 무엇을 정했고, 무엇이 남았는지** 정리해 준다. 대화를 다시 읽지 않아도 프로젝트 상태와 지난주에 한 일을 바로 볼 수 있다.

## 내가 할 일

| 언제 | 할 일 | 걸리는 시간 |
|---|---|---|
| 매일 또는 며칠에 한 번 | 터미널에서 `daily.sh opencode` 실행 (아래 "로컬에서") | 새 대화 1개당 1분쯤, 무료 |
| 주 1회 | 위키 **홈**에서 주간 회고 읽기. 남은 일 중 할 것은 **+ 할 일**로 anotar 할 일에 보내기 | 5분 |
| 가끔 | 홈의 **위키로 옮길 후보** 중 오래 남길 것을 골라 에이전트에게 정리시키기 | 하나에 몇 분 |
| 이상한 프로젝트가 보일 때 | `projects.json`에서 숨기거나 이름 합치기 | 1분 |

이것 말고는 손댈 것이 없다. 요약, 회고, 화면 갱신은 `daily.sh`가 한다.

## 로컬에서

```sh
cd ~/Documents/Service/anotar/data/memory
../../apps/memory/daily.sh opencode     # 가져오기 → 요약 → 주간 회고 → 빌드 → 커밋·push
```

화면으로 보려면 다른 터미널에서:

```sh
cd ~/Documents/Service/anotar/apps/anotar
AUTH_MODE=disabled npm run dev          # 로그인 없이 로컬에서만
```

그리고 `http://127.0.0.1:5173/wiki`를 연다. `daily.sh`를 다시 돌리면 새로고침만 하면 된다.

## 작동 원리

1. **모으기** — 이 Mac에 남아 있는 AI 대화 기록을 읽어 대화만 추려 둔다. 원본은 이 Mac에만 있고 git에 올라가지 않는다(비밀값이 섞일 수 있어서).
2. **요약하기** — 대화 하나마다 무료 AI(deepseek)에게 "무엇을 했고, 정했고, 남았나"를 정해진 형식으로 쓰게 한다. 이게 **AI 기록**이다. 이미 요약한 대화는 다시 하지 않는다.
3. **회고 쓰기** — 한 주의 AI 기록을 모아 AI가 프로젝트별로 정리한다. 이게 **주간 회고**다. 원본 대화가 아니라 요약만 읽으니 가볍다.
4. **위키로 옮기기** — 오래 남길 지식만 사람이 골라서 주제 페이지로 만든다. 자동으로 하지 않는다(자동으로 만들면 금방 품질이 흐려진다).
5. **묶기** — 위 결과를 화면이 읽는 파일 하나(`data.json`)로 묶는다.
6. **보기** — anotar의 위키 화면이 그 파일을 읽어 보여 준다.

AI를 부르는 것은 2·3·4뿐이고 모두 이 Mac에서 한다. 요약과 회고, 위키 페이지는 비공개 GitHub repo(`memory-data`)에 올라가서 그게 곧 백업이다.

## 화면 읽는 법

| 탭 | 무엇을 보나 |
|---|---|
| 홈 | 이번 달 숫자, 6개월 활동, 최근 주간 회고, 남은 일, 멈춘 프로젝트, 위키 후보 |
| 위키 | 정리해 둔 주제 페이지 |
| AI 기록 | 대화별 요약. **주별**로 보면 주마다 회고가 맨 위에 붙는다 |
| 프로젝트 | 6개월 타임라인과 프로젝트별 남은 일·정한 것 |
| 구조 | 이 시스템이 어떻게 만들어졌는지(파일, 규칙, 단계별 개수). 고칠 때 본다 |
| 가이드 | 이 페이지 |

- 히트맵의 칸 하나 = 하루, 세로 한 줄 = 한 주. 진할수록 AI 기록이 많은 날이다. 한 주를 누르면 그 주 기록으로 간다.
- 프로젝트 이름 앞 초록 점 = 2주 안에 기록이 있음(진행 중).
- 회고의 **✓ 정함**은 그 주에 정한 것, **! 막힘**은 실패했거나 확인하지 못한 것.

## 이럴 땐 이렇게

| 하고 싶은 것 | 방법 |
|---|---|
| 시험용 프로젝트를 안 보이게 | 데이터 repo `projects.json`의 `hide`에 이름(또는 `test*` 같은 패턴) 추가 → `build.py` |
| 같은 프로젝트가 두 이름으로 보임 | `projects.json`의 `alias`에 `"옛 이름": "새 이름"` 추가 → `build.py` |
| 요약 하나가 마음에 안 듦 | `sessions/<그 이름>.md`를 지우고 `summarize.py sessions` |
| 한 주 회고를 다시 쓰게 | `digests/<월요일>.md`를 지우고 `summarize.py weekly <월요일>` |
| 요약·회고 형식 자체를 바꾸고 싶음 | 데이터 repo `AGENTS.md`의 sessions·weekly 절을 고친 뒤 위 방법으로 다시 만들기 |
| 위키 후보를 페이지로 | Claude Code를 데이터 repo에서 열고 "`sessions/<이름>.md` ingest 해 줘" |

명령은 모두 `data/memory`에서 `python3 ../../apps/memory/<파일>`로 실행한다.

## 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 위키 화면이 "불러오지 못했어요" | 개발 서버가 떠 있는지, `data/memory/site/data.json`이 있는지(`build.py`) |
| 새 작업이 안 보임 | `daily.sh`를 돌렸는지. 화면 오른쪽 위 "갱신 …전"이 마지막 빌드 시각이다 |
| `FAIL`이 찍힘 | 그 파일은 건너뛰었을 뿐이다. 다음 실행 때 다시 시도한다. 계속 실패하면 덤프가 비었거나 너무 긴 경우 |
| "90초 안에 답하지 않아 멈춤" | 무료 모델이 한도에 걸렸거나 장애다. 몇 시간 뒤 다시 돌리거나 `MEMORY_MODEL=opencode/glm-5.3-flash-free`처럼 다른 무료 모델로 |
| 요약이 한참 멈춰 있음 | 파일 하나(묶음)에 최대 5분이면 넘어간다 |
| 운영 anotar 위키가 비어 있음 | 아직 서버로 올리는 단계가 없다. 지금은 로컬에서만 본다 |
