# 계획 태그 기반 일간 타임박싱 — 설계

2026-10-13. 로컬 전용. 운영 배포·커밋 없음.

## 의도
핵심은 간편한 **일간 타임박싱 표**(24시간×10분). 분기/연간 계획에서 만든 목표·세부 계획을 일간 활동에 **태그처럼 붙여** 시간이 계획별로 쌓이는 것을 수치로 본다. 대상은 학습·자기계발 개인(1순위)이며 프리랜서·직장인도 같은 엔진(프로젝트/업무 = 계획)으로 쓴다. PC·모바일 병행.

## 원칙
- 이행 체크 없음. 잡은 시간은 기본적으로 한 것으로 본다. 예외만 표시: 미이행·취소·수정(기존 status `missed/cancelled/deferred/partial`).
- 실제 시간 = 잡은 시간 − `missed`·`cancelled` 시간. 자동 완료율/성과율·자동 판정 없음.
- 새 테이블·집계 저장·추가 API 없음. 합계는 이미 불러온 일지에서 읽을 때 계산.
- 칸반 보드 화면 없음. 계획 상태 `준비/진행중/완료`는 사용자가 직접 정하는 작은 표시.
- Task·루틴 부활 금지. 작동하지 않는 버튼 금지.

## 이름
일지 문서의 `plans`는 시간표 활동, `Entry.planId`는 활동 참조다. 계획표 항목을 가리키는 새 필드는 혼동을 피하려 **`planningId`** (활동 `Plan`에 선택 항목).

## 단계
1. **연결**: 활동에 `planningId` 추가(서버 검증: 같은 소유자의 계획만, 계획 삭제 시 활동은 남고 연결은 stale로 무시). 활동 모달에 계획 선택, 시간표 칸에 계획 표시.
2. **수치·빠른 입력**: 접힌 "이번 기간 계획"을 펼쳐 계획별 시간 합계, 줄마다 `시간 잡기`(해당 계획이 붙은 활동 작성). 세부 계획 시간은 상위 목표에 합산. 계획 상태 표시.
3. **작성·모바일**: 분기/연간 칸에서 제목만 Enter로 추가(기간 자동), 모바일은 시작+길이 칩 입력.

## 완료 기준(1단계)
빌드·`npm test`·`qa-planning-board`·`qa-planner-navigation` 통과. 다른 사용자 계획 ID 거부, 계획 삭제 후 활동 보존, 기존 일지 문서 호환(필드 없는 문서 정상).
