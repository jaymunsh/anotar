# Anotar 시간관리 확장안

작성: 2026-10-12. 조사와 설계 제안이며 아래 신규 기능이 구현되었다는 의미는 아니다.

## 참고한 내용

[타임트래커 스타터팩 상품 설명](https://www.timetracker.kr/shop_view/?idx=129)은 목표 설정과 피드백을 핵심으로 설명한다. 상세 내지에는 분기 목표를 월별로, 월 목표를 주차별로 나누는 구성과 하루의 계획·실제 기록 비교, 주간·월간 피드백이 있다.

- [분기·월 목표와 월간 피드백 내지](https://cdn.imweb.me/upload/S2022092080be0931165d0/1f55f93fc8f56.png)
- [하루·주간 시간 기록과 피드백 내지](https://cdn.imweb.me/upload/S2022092080be0931165d0/f530be6b47358.png)

상품 설명의 고객 수·효과·성과 수치는 서비스 성능의 근거로 사용하지 않는다. 도서 전체나 유료 가이드북은 열람하지 않았다. 아래 화면·데이터·단계 제안은 Anotar를 위한 설계다.

## 제품의 중심

내가 중요하게 생각한 일에 실제로 시간을 썼는지 확인하고 다음 계획을 조정한다.

로그인 직후에는 기존 오늘 일지와 24시간 × 10분 시간표를 유지한다. 분기·월 목표 입력은 필수가 아니며 오늘 계획만으로도 사용할 수 있다. 긴 문서와 다층 페이지를 먼저 만드는 사용 흐름은 요구하지 않는다.

## 연결할 흐름

목표 → 이번 주 할 일 → 오늘 시간 배치 → 실제 수행 확인 → 회고 → 다음 계획.

예시: 이번 달 책 한 권 읽기 → 이번 주 1~3장 읽기 → 오늘 09:00~09:30 읽기 → 실제 09:10~09:35 기록 → 시작이 늦어진 이유 기록 → 다음 읽기 시간을 정한다.

읽은 분량은 목표의 결과이고 독서 시간은 투입이다. 독서 시간이 쌓였다는 이유로 책 한 권 읽기가 자동 완료되지는 않는다.

## 화면 역할

| 화면 | 역할 | 추가 제안 |
| --- | --- | --- |
| 오늘 | 시간 배치와 실행 | 이번 주 집중 목표 한 줄, 계획·실제 비교, 완료·일부·미이행 간편 표시 |
| 주간 | 다음 일주일 준비와 점검 | 이번 주 중요 작업 최대 3개, 날짜별 기록, 시간 분포, 짧은 회고 |
| 월간 | 목표 진척과 월 회고 | 목표별 결과 진척, 관련 시간, 지난달 대비 변화 |
| 할 일 보관함 | 날짜 없는 작업과 여러 날 이어갈 작업 | 주간 목표 연결, 오늘·다른 날짜에 배치 |
| 지난 일지 | 이전 기록 탐색 | 날짜·활동·회고 검색, 기존 일지 열기 |

분기는 월간 안에서 기간을 선택하는 방식으로 나중에 추가한다. 초기 상단 메뉴 수를 늘리지 않는다.

## 오늘 화면

- 현재 첫 화면의 시간표·우선순위·세 메모 칸을 유지한다.
- 이번 주 집중할 목표는 접을 수 있는 한 줄로만 표시한다.
- 계획은 옅은 면, 실제 시간은 구분되는 채움으로 표시하는 비교 보기를 제안한다. 모바일에서도 같은 자료를 쓴다.
- 완료 표시는 실행 상태를 뜻한다. 실제 기록을 만들 때는 시작·종료 시간을 확인하게 한다.
- 같은 활동을 우선순위와 계획에 연결해 중복 입력을 줄인다. 여러 계획 구간이 연결될 수 있으므로 일부 구간 완료가 전체 작업 완료를 자동 의미하지 않도록 한다.
- 회고 질문은 선택 사항: 잘된 점 / 계획이 달라진 이유 / 다음에 바꿀 한 가지. 기존 자유 메모는 보존한다.
- 미완료 항목은 사용자가 선택한 날짜로 다시 계획한다. 원래 날짜의 기록은 남긴다.

## 주간 점검

첫 버전은 완료 수, 계획·실제 기록 시간, 활동별 시간 분포만 제공한다.

- 할 일 완료율: 이번 주 대상으로 선택한 할 일 중 직접 완료한 비율. 일정 구간의 수행률과 섞지 않는다.
- 일정 수행 상태: 완료·일부 수행·미이행·아직 확인하지 않음을 구분한다. 취소는 수행률 분모에서 제외한다.
- 실제 시간: 기록된 구간만 계산한다. 전체 실제 시간은 중첩 구간을 합쳐 이중 집계를 피한다.
- 미기록 시간: 알 수 없는 시간으로 표시한다. 자동으로 낭비 시간이나 실패로 분류하지 않는다.
- 사용자가 선택한 업무·학습·생활·휴식 분류를 사용할 수 있게 한다. 휴식은 낭비로 취급하지 않는다.
- 회고: 계속할 것 한 가지 / 바꿀 것 한 가지 / 다음 주 집중할 일.

## 데이터와 저장

기존 날짜 문서의 plans, entries, notes, priorities 및 Task ID를 보존한다. 화면마다 별도 복사본을 만들기보다 기존 계획·실제 기록·작업을 ID로 연결한다. 기존 개인 서비스 자료를 새 계정에 자동 복사하지 않는다.

후속 목표는 사용자 소유의 별도 Goal 레코드로 추가한다. 제안 필드는 제목, 기간, 선택적 상위 목표 ID, 결과 목표·현재 값·단위, 상태, 버전이다. 같은 사용자 소유 목표·작업만 연결할 수 있게 서버에서 검사한다.

주간·월간 집계는 저장된 기록으로 계산한다. 회고에는 기간별 별도 버전이 필요하다. 기존 900ms 저장 대기, 충돌 시 기기 초안 보관, 내보내기와 사용자별 자료 격리를 이어받는다.

## 권장 구현 순서

1. **일간 실행 흐름:** 할 일 배치와 완료 표시를 연결하고 실제 기록 입력을 간단하게 한다. 현재 메뉴·저장·모바일 조작을 유지한다.
2. **주간 계획과 회고:** 이번 주 중요 작업, 기본 집계 세 가지, 짧은 회고를 추가한다.
3. **월 목표:** 주간 작업과 연결하는 선택적 목표를 추가하고 결과 진척을 표시한다.
4. **사용 습관 지원:** 반복 일정, 하루 기본 틀, 선택적 알림, PDF 내보내기를 검토한다.
5. **분기 확장:** 월간 사용 흐름이 안정된 뒤 목표를 분기로 묶는다.

## 구현 후 확인할 기준

- 새 사용자가 목표 설정 없이 오늘 할 일을 쓰고 시간표에 배치할 수 있다.
- 완료 표시, 실제 시간, 장기 작업 완료의 차이를 화면에서 이해할 수 있다.
- 기존 기록이 새 연결 기능 때문에 삭제·변형되지 않는다.
- PC 첫 화면의 시간표와 메모 배치를 유지하고 모바일에는 같은 조작이 있다.
- 집계가 원본 기록과 일치하며 취소·중첩·미기록 시간이 명확하다.
- 이번 주 회고에서 다음 계획으로 자연스럽게 이어진다.

실제 사용자 검증에서는 첫 시간 배치 성공, 하루 수행 확인, 주간 재사용, 입력 부담을 본다. 자동 수집을 도입한다면 수집 항목과 개인정보 안내를 먼저 확정한다.
