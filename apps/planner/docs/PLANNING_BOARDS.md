# 분기·연간 계획표 — 현재 로컬 구현

2026-10-13. 운영에는 배포하지 않았다.

## 화면

- 연간: 집중할 목표 행 × 네 분기 열. 목표 기간에 해당하는 칸에서 세부 계획을 추가하고 수정한다. 분기 제목을 누르면 해당 분기를 연다.
- 분기: 집중할 목표와 세 달의 실행 계획. 월 제목에서 월간 일지로 이동한다. 기간에 걸친 세부 계획은 여러 달에 같은 ID로 표시한다.
- 모바일: 연간은 목표별 2×2 분기 격자, 분기는 월을 세로로 배열한다.
- 일간·주간·월간: 해당 기간과 겹치는 저장된 목표·계획을 접힌 참고 요약으로 표시한다. 계획이 없으면 빈 요약 구역을 추가하지 않는다.
- 모든 보기의 PC 제목 24px, 위 여백 16px, 탭 위/아래 간격 6px/8px로 통일했다.
- 날짜와 보기 선택은 주소에 반영하므로 새로고침해도 같은 보기를 유지한다. 분기·연간은 연도·분기를 직접 선택한다.

## 작성과 연결

목표와 세부 계획은 간단한 기본 모달로 작성한다. 결과 제목, 시작 월, 마칠 월이 기본 입력이다. 세부 계획의 목표 연결은 선택이며, 메모은 추가 설정에 둔다. 저장 전 닫기·Escape·새로고침에서 작성한 변경을 보호한다.

목표와 세부 계획은 완료율을 자동 계산하지 않는다. 연결된 할 일의 상태는 기존 할 일의 상태이며, 시간표에 배치했다고 작업 전체를 완료하지 않는다.

월 제목은 해당 월의 일정으로 이동한다. 목표와 세부 계획은 현재 기간·메모·상위 목표만 관리하며, 개별 계획의 일정 배치 연결은 후속 범위다.

목표를 삭제해도 연결된 세부 계획과 할 일은 남는다. 세부 계획은 독립 계획으로 바뀌고 저장 버전이 증가한다.

## 저장 구조

SQLite의 planning 테이블에 사용자별 JSON 계획과 버전을 저장한다. 사용자 ID와 계획 ID가 복합 키이며 사용자 탈퇴 시 외래 키로 함께 삭제한다.

- id: 변경되지 않는 계획 ID
- kind: goal 또는 step
- title: 결과 제목, 최대 200자
- startMonth / endMonth: YYYY-MM 기간
- note: 선택 메모, 최대 2,000자
- parentId: 세부 계획의 선택적 상위 목표
- version: 수정 충돌을 확인하는 저장 버전

세부 계획의 기간은 연결한 목표 기간 안에 있어야 한다. 다른 사용자 목표는 연결할 수 없다. 목표와 세부 계획을 합쳐 사용자별 300개까지 보관한다. 기존 일지 document는 유지한다. 독립 할 일은 종료했다.

API는 GET /api/planning, PUT·DELETE /api/planning/:id다. 로그인·Origin·CSRF와 버전을 검사한다. 충돌 시 입력을 남기고 최신 계획을 다시 불러오는 동작을 제공한다. 계정 JSON 내보내기에 planning도 포함한다. SQLite 전체 백업에도 함께 포함된다.

## 2026-10-13 화면 이동 정리

상단은 일정(`/app`)·계획(`/app/plans`)·되짚어보기(`/app/review`)이다. 일정 내부는 일간/주간/월간, 계획 내부는 분기/연간이다. 기존 `/app?view=quarter|year|review` 링크는 현재 주소로 정규화하고 선택 날짜를 유지한다. 계획의 월간 링크는 일정으로 이동하며 상단 선택 표시도 갱신한다. 데이터/API 저장 구조는 변경하지 않는다. 로컬 전용이며 운영 배포하지 않았다.
