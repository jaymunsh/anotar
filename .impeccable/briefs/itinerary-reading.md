# 일정·여행 문서 읽기

Mode: Read / 여행 중 Operate. 기존 leneu의 따뜻한 종이 면·숲색·서체를 유지한다.

## 사용자의 목적

공유받은 사람이 예약 준비부터 당일 이동·식사·귀환까지 따라갈 수 있어야 한다. 많은 사실을 모았다는 이유로 첫 화면과 시간표를 길게 늘리지 않는다. 사용자는 기존 문서의 가독성과 시간표 완성도가 부족하다고 지적했다.

## 읽는 순서

짧은 여행 개요·미예약/인원 가정 → 날짜와 준비 영역 목차 → 날짜별 핵심 주의·실제 지도·시간표 → 예산/예약 체크 → 펼치는 참고 자료.

## 시간표 규칙

- 시작/끝/소요시간은 고정폭 숫자로 왼쪽에 모으고, 높이를 본문에서 독립시켜 불필요한 공백을 만들지 않는다.
- 실제 방문 번호와 이동 아이콘을 얇은 시간축으로 잇는다. 저장된 방문 순서와 지도 핀은 바꾸지 않는다.
- 제목·활동 유형·장소가 먼저 보이고, 설명은 전체를 한 번만 표시한다. 일정 지시는 접거나 줄 수로 잘라 숨기지 않는다. 명시된 줄바꿈과 시간별 수속 단계를 읽기 쉽게 분리한다.
- 긴 수속 단계는 새 여행 페이지에서 큰 행동으로 묶되 목표 시각을 기본으로 보이는 설명에 보존한다. 기존 다른 문서의 데이터를 자동 병합하지 않는다.
- 일반 문서는 기존 목록 목차를 사용한다. `tableOfContents.props.compact: true`인 문서만 2열 목차를 쓴다.
- 공유 HTML의 목차는 실제 제목 앵커로, 참고 토글은 HTML details/summary로 작동한다. 오프라인 ZIP에도 같은 CSS를 포함한다.
- PC 시간 14px·제목 15px·메모 14px, 모바일 시간 13px·제목/메모 14px·메타 11px. 모바일 링크·준비 항목 조작은 44px. 일정 바깥 테두리는 제거하고 행 구분선과 시간축을 유지한다.

## 보존

공식 출처·가격/날씨/예약의 미확인 조건·비상 대안·원래 블록 ID를 보존한다. 사실 조사와 계획 추정은 계속 구분한다. 지도 생성은 반복하지 않고 저장 자산을 사용한다. 다른 사용자 페이지·메모·댓글을 수정하지 않는다.

블록/일정 선택은 바깥 여백 클릭으로 바로 해제한다. 댓글 입력과 도구 메뉴 작업에는 대상 선택을 보존한다.

사용자 피드백에 따라 간사이 여행 페이지는 기존 연한 배경·한 열·구분선·우측 화살표의 목록 목차를 사용한다. compact 속성을 임의로 켜지 않는다.
