# anotar 문서 작성 기능 안내

빈 페이지에서 시작해도 되고, 목적에 맞는 템플릿으로 뼈대를 만든 뒤 내용을 채워도 됩니다. 이 안내는 현재 작성 화면을 기준으로 합니다. 여행 지도·일정은 별도 서비스용으로 분리했습니다.

공유 링크는 페이지 오른쪽 위 **공유**를 열어 확인합니다. 상단에서 기존 활성 링크를 복사하거나 열 수 있고 만료일도 표시됩니다. 새로고침이나 다른 기기에서도 서버에서 같은 주소를 가져옵니다. 새 링크 발급은 이전 링크를 즉시 끊습니다. 이전 방식으로 만들어 해시만 남은 링크는 주소를 복원할 수 없으며, 새로 발급한 링크부터 다시 확인할 수 있습니다.

## 1. 목적에 맞게 시작하기

읽기만 할 때는 오른쪽 위 **더보기(···) → 페이지 잠금**을 켭니다. 제목·아이콘·본문과 블록 서식 수정을 막으며, 목차 이동·다이어그램 확대·복사·공유·댓글 읽기는 계속 사용할 수 있습니다. 상단 잠금 아이콘 또는 더보기의 **페이지 잠금 해제**로 편집을 다시 시작합니다. 잠금은 페이지별로 서버에 저장되어 다른 기기에도 적용되며 하위 페이지에 자동 적용되지 않습니다. 아직 서버에 반영되지 않은 변경이 있으면 먼저 저장을 기다려 주세요.

오프라인에서는 마지막으로 확인한 잠금 상태를 유지합니다. 다른 기기의 잠금은 연결된 상태에서 페이지를 다시 열거나 화면으로 돌아올 때, 또는 최대 30초 간격으로 확인합니다. 그 사이 들어온 수정 요청도 서버에서 차단하고 기기의 변경은 보관했다가 잠금 해제 후 다시 전송합니다. 잠금은 실수로 인한 수정 방지이며 별도 사용자 권한이나 공유 비밀번호 설정은 아닙니다.

사이드바는 페이지를 펼쳐도 이모지를 유지하고, 옅은 점선과 배경으로 하위 목록과 열린 상태를 표시합니다. 모바일의 **페이지 이동**은 문서를 연 뒤 더보기에서 사용합니다.

- 리서치: 질문 → 결론 → 근거 → 비교 → 미확인 사항 순으로 정리합니다. 독자가 결론과 확실성부터 알 수 있게 씁니다.
- 회의: 안건 → 논의 → 결정 → 담당자와 후속 행동을 남깁니다. 발언을 모두 받아 적기보다 결정과 이유를 보존합니다.
- 개발 기록: 현상 → 재현 → 원인 → 수정 → 검증 → 남은 위험을 기록합니다. 실제로 확인한 범위만 완료로 표시합니다.
- 내 템플릿: 반복해서 쓰는 페이지를 템플릿으로 저장합니다. 다음 작성은 새 페이지로 시작하므로 기존 기록을 덮지 않습니다.
- 복제: 내용을 포함한 비슷한 문서가 필요할 때 사용합니다. 템플릿은 반복할 구조, 복제는 재사용할 완성 문서에 적합합니다.

## 2. 기본 글쓰기와 서식

- 문단과 제목: 일반 문장, 제목 1~4단계를 사용합니다. 제목 4도 본문보다 큽니다. 슬래시 메뉴 또는 Markdown 입력으로 시작합니다. 새로 가져오는 5·6단계 제목은 제목 4로 변환하고, 기존 저장 문서는 자동 변경하지 않습니다.
- 글자 서식: 굵게, 기울임, 취소선, 밑줄, 인라인 코드, 링크, 글자색·배경색을 사용합니다. 강조는 결론과 핵심 숫자에만 제한하면 읽기 쉽습니다.
- 목록: 글머리, 번호, 체크 목록을 사용합니다. Tab으로 하위 블록을 넣고 Shift+Tab으로 꺼냅니다.
- 접기: 접는 목록과 접는 제목으로 보충 설명을 접어 둡니다. 결론까지 접어 숨기지는 않습니다.
- 인용과 구분선: 인용은 출처가 있는 문장, 구분선은 큰 주제 전환에 사용합니다.
- 들여쓰기: 편집·공유 화면 모두 자식 묶음 옆에 옅은 1px 점선을 보여줍니다. 인용문의 실선과 구분되며 내용이나 목록 단계는 바꾸지 않습니다.
- 블록 이동: 왼쪽 손잡이로 순서를 바꿉니다. 여러 블록을 선택하면 다른 페이지로 옮기거나 AI 요청에 사용할 수 있습니다.
- 이어 쓰기: 본문 아래 빈 공간을 누르면 마지막 빈 문단에서 입력을 이어 갑니다.

본문 크기와 제목 비율은 **설정 → 화면 → 페이지 글자 크기와 비율**에서 조절합니다. **작게·보통·크게**를 선택하거나 제목 1·2·3·4의 크기를 따로 맞추고 미리보기로 확인할 수 있습니다. 기본값은 **작게(본문 14px)**입니다. 크기 선택 오른쪽의 **기본값으로 설정**을 누르면 본문 크기·제목 비율·줄간격·문단 간격을 모두 처음의 작게 설정으로 되돌리고 저장합니다. 공유 화면 상단의 **글자 크기**에서도 같은 세 가지를 고를 수 있고 기본값은 작게입니다. 편집·공유의 선택은 각 브라우저에서 유지되며 문서 내용은 바꾸지 않습니다.

## 3. 정보를 구조화하는 블록

- 콜아웃: /콜아웃으로 만듭니다. 투명 배경·테두리 또는 배경색을 선택하고 아이콘을 바꿀 수 있습니다. 박스 안에서 글과 링크를 편집합니다. 왼쪽 점 메뉴의 **콜아웃 아이콘 → 아이콘 없음**으로 아이콘과 빈자리를 없애고, 같은 메뉴에서 다시 선택할 수 있습니다.
- 표: 블록 왼쪽 점 손잡이 메뉴의 **본문 너비에 맞추기**로 현재 본문 폭에 열을 균등 배치합니다. 열 경계를 끌어 다시 조절할 수 있고, 좁은 화면에서는 표 안에서 가로로 스크롤합니다. 비교 기준, 담당자, 상태처럼 열의 의미가 일정한 정보에 사용합니다. 데이터베이스의 필터·수식 기능은 제공하지 않습니다.
- 코드 블록: 코드와 명령을 일반 문장과 구분합니다. 언어를 지정하고 실행 전에 내용을 확인합니다. 오른쪽 **복사** 버튼으로 줄바꿈·공백을 유지한 코드 원문만 복사합니다. 공유·오프라인 HTML에서도 같은 버튼을 사용하며 실패하면 직접 선택해 복사하도록 안내합니다.
- Mermaid 다이어그램: Markdown의 mermaid 코드 울타리로 흐름과 구조를 표현합니다.
- 목차: 블록 메뉴에서 **대표 제목만 목차에 표시 / 소제목까지 목차에 표시**를 선택할 수 있습니다. `#`는 큰 장, `##`는 장 안의 주제, `###`는 세부 절에 사용합니다. 제목을 모아 문서 안의 해당 위치로 이동합니다. 제목을 고치면 목차도 바뀝니다.
- 이모지·페이지 아이콘: 본문의 이모지와 제목 위 대표 아이콘을 사용할 수 있습니다.

## 4. 링크·페이지·파일 연결

- 외부 URL 하나를 빈 줄에 붙여넣으면 일반 링크 또는 북마크를 고릅니다. 북마크에는 제목·설명·대표 이미지 사본이 들어갑니다. 가져오지 못하면 일반 링크로 남길 수 있습니다.
- 기존 페이지는 더보기의 페이지 링크 복사 후 다른 문서에 붙여넣습니다. 일반 링크 또는 페이지 링크를 선택합니다.
- /페이지는 새 하위 페이지를 만듭니다. 사이드바에서도 부모 아래에 표시됩니다. 기존 페이지로 이동하는 링크와 새 하위 페이지 만들기를 구분하세요.
- **/이미지**, **/파일**, 더보기의 파일 첨부, 파일 끌어놓기나 이미지 붙여넣기로 이미지·파일을 넣습니다. 새 파일은 온라인에서 업로드하고 본문 끝에 추가합니다. 메모의 내 페이지에 정리로 보관한 내용과 첨부를 가져올 수도 있습니다.
- 이미지는 이미지와 중앙 정렬 캡션만 표시하고, 마우스를 올리면 설명 편집·자르기·원본 보기·내려받기를 사용할 수 있습니다. 모바일에서는 이미지 우측 메뉴에서 엽니다. 파일은 한 줄의 파일명·크기·다운로드로 표시합니다. 자르기는 표시 영역만 바꾸고 원본은 보존합니다. 캡션과 자른 영역은 공유 화면에도 반영됩니다. 페이지를 잠그면 이미지 설명·자르기를 수정할 수 없습니다.
- 메모에서 가져온 본문은 편집 가능한 사본입니다. 원본 관계는 페이지 정보의 원본 메모에 남습니다.
- 개인 페이지 링크는 공개 권한을 주지 않습니다. 다른 사람에게 보여 줄 때는 공유 주소를 따로 발급합니다.

## 5. 템플릿으로 만든 글을 잘 마무리하기

- 첫 문단: 무엇을 다루며 독자가 무엇을 알게 되는지 두세 문장으로 씁니다.
- 결론: 가장 중요한 판단을 먼저 둡니다. 사실, 해석, 제안을 섞지 않습니다.
- 근거: 출처 링크와 확인한 날짜, 검증 범위를 적습니다. 확인하지 않은 수치나 결과를 채워 넣지 않습니다.
- 후속 행동: 할 일·담당자·완료 기준을 구체적으로 씁니다. 일정이 미정이면 미정이라고 남깁니다.
- 보충 설명: 접는 블록이나 문서 끝으로 옮깁니다. 한 문단에는 한 가지 주제만 둡니다.

## 6. AI 요청

문서 전체 또는 선택한 블록을 입력으로 요청을 만들 수 있습니다. 요청 템플릿과 입력 내용을 확인한 뒤 실행하세요. 결과는 검토하고 명시적으로 문서에 적용합니다.

링크 대상의 본문과 첨부 파일 바이트가 자동으로 함께 전달되는 것은 아닙니다. 요청에 필요한 근거는 입력에 직접 포함하세요. AI가 쓴 출처와 사실은 확인해야 합니다. 실행기와 모델의 현재 지원 범위·설정은 [AI 설정 안내](AI_CONFIGURATION.md)를 참고하세요.

## 7. 저장·수정 이력·공유

- 기기 저장과 서버 반영은 서로 다른 상태입니다. 공유에는 서버에 반영된 내용만 나타납니다.
- 충돌 안내의 **변경 내용 비교**를 열면 서버본·기기본과 달라진 블록을 확인합니다. 내용 변경과 위치 이동을 구분하며, 반영할 내용을 고른 뒤 **선택한 내용 적용**을 누릅니다. 비교 전에는 양쪽 사본을 그대로 보관합니다.
- 페이지 수정 이력에서 이전 내용을 확인·비교·복원합니다. 휴지통에서는 지운 페이지를 복원할 수 있습니다.
- 공유는 해당 페이지와 그 본문에 배치한 첨부를 공개합니다. 연결된 개인 페이지 본문이 함께 공개되지는 않습니다.
- Markdown 보기·복사로 텍스트를 옮기고, 오프라인 HTML 사본으로 읽을 수 있는 형태를 보관합니다. 완전한 복구에는 DB와 첨부 백업이 필요합니다.

## 8. Markdown으로 옮길 때의 한계

원본은 Markdown 파일이 아니라 블록 JSON입니다. Markdown은 텍스트를 교환하는 형식이며 모든 모양을 보존하는 백업이 아닙니다.

콜아웃은 인용문으로 바뀌며 색·아이콘·테두리는 사라집니다. 목차와 원본 메모 관계는 Markdown에 포함되지 않습니다. 페이지 링크·첨부 ID는 다른 서비스에서 그대로 열리는 파일이 아닙니다. 밑줄·글자색, 각주·수식·MDX·임의 HTML의 왕복 보존도 보장하지 않습니다.
