# 오프라인 작업 공간 사용 안내

2026-10-03. 개인 웹/PWA의 기기 저장·동기화 안내. 공개 공유 화면의 댓글·관리 기능과는 별개다.

## 처음 사용할 때

1. PC나 휴대폰에서 **같은 개인 HTTPS 주소**에 연결한다. 개발 PC의 localhost도 테스트할 수 있다.
2. 입력함이 열리고 앱의 정적 파일 준비가 끝날 때까지 기다린다. 모바일에서는 브라우저의 홈 화면 추가/앱 설치를 사용한다.
3. 오프라인에서 필요한 페이지를 열어 `··· → 오프라인 보관`을 선택한다. 본문과 직접 참조한 첨부만 내려받는다. 하위 페이지는 각각 보관한다.
4. 설정의 **기기 저장소**에서 준비/부분 보관과 누락 첨부를 확인한다. 부분 보관은 연결 중 재시도한다.

주소·포트·브라우저 프로필이 다르면 기기 저장소도 다르다. 서버 백업이 브라우저의 미전송 사본까지 포함하지 않는다. 처음부터 인터넷 없이 접속하거나 한 번도 보관하지 않은 페이지를 여는 것은 지원하지 않는다.

## 기기에 저장됨과 동기화 완료

| 표시 | 의미 |
|---|---|
| 기기에 저장됨 / 전송 대기 | IndexedDB 트랜잭션 완료. 아직 다른 기기나 공유 화면에 반영되지 않을 수 있다. |
| 동기화 완료 | 현재 기기의 대기 작업이 서버에 반영됨. |
| 변경 확인 필요 | 다른 변경과 충돌했거나 서버 복원/작업 공간 변경을 확인해야 함. |
| 기기에 저장하지 못함 | 용량·브라우저 저장 제한 등으로 저장 실패. 입력을 복사하고 문제를 해결한다. |

메모 저장은 기기 원문/첨부를 저장한 뒤 입력을 비운다. 할 일 추가·수정도 기기 저장을 먼저 한다.

- **페이지**: 입력 즉시 복구 초안을 남기고, 입력 중에도 약 **250ms** 간격으로 최신 내용을 IndexedDB와 전송 대기열에 함께 저장한다.
- **일지**: 입력 변경마다 기기에 저장한다. 핵심 할 일의 체크와 계획 추가·시간 변경은 기기 저장 후 바로 동기화를 요청한다.
- **텍스트 서버 전송**: 마지막 입력 후 **1초**, 계속 입력하면 한 묶음의 시작부터 **최대 5초**에 동기화를 요청한다. 아직 전송하지 않은 요청은 최신 사본 하나로 합친다. 네트워크·접근·충돌 상태에 따라 실제 서버 반영은 더 늦어질 수 있다.

숨김/정상 화면 이탈/업데이트 시 최신 편집을 저장하고 전송을 요청한다. 기기에 저장 완료된 사본과 대기열은 다음 실행 때 이어가지만, 강제 종료 직전 아직 저장되지 않은 입력까지 보장하지는 않는다.

앱을 열어둔 상태에서 연결이 회복되면 재전송한다. 브라우저가 앱을 종료하거나 백그라운드 작업을 정지하면 다음 실행 때 이어간다. 백그라운드 동기화에 의존하지 않는다. 전송 중·재시도 중인 요청과 AI 요청이 참조하는 저장 사본은 변경하지 않는다. 응답 유실은 같은 작업 UUID/본문으로 재시도한다. 상위·하위 페이지가 서로 참조하면 생성 순서를 유지한 뒤 최신 내용을 후속 요청으로 보낸다. 한 기기의 여러 탭은 lease/fence로 전송을 조정한다.

## 페이지와 충돌

본문은 BlockNote JSON v1 하나의 문서로 저장한다. Markdown 입력/붙여넣기·표·Mermaid·일정·지도 이미지를 기존 편집기에서 사용한다. 자동 CRDT 병합은 없다.

동시에 다른 기기에서 편집하면 마지막 글로 덮지 않고 **기준·기기·서버 사본**을 보존한다. **변경 내용 비교**를 열면 서버본과 기기본을 확인하고 사본을 내려받을 수 있다. 페이지는 본문 변경, 서식·설정만 바뀐 블록, 위치 이동을 구분한다. 달라진 글자는 빨간 `−`/초록 `+`로 비교하고, 글자가 같은 블록은 서식·설정·위치 목록에 접어둔다. 이 목록에서 표 열 너비·링크 주소·서식 등의 서버 값 → 기기 값을 확인하고 같은 본문은 한 번만 펼쳐 볼 수 있다. 위치 수는 본문 또는 서식 변경 수와 겹칠 수 있다. 반영 방식은 기본 선택 없이 다음 중 하나를 고른 뒤 **선택한 내용 적용**을 누른다.

- 서버 내용 사용: 기기 사본은 복구 기록에 보존하고 서버 내용으로 전환.
- 내 변경으로 반영: 확인한 최신 서버 버전을 기준으로 새로운 작업을 제출. 그 사이 또 바뀌면 다시 확인.
- 새 페이지로 보관: 페이지/블록 UUID를 새로 만들며 별도 기기 사본 생성. 공유 토큰·댓글은 복제하지 않는다.

작성기가 추가하는 값 없는 기본 속성은 실제 JSON 저장 결과가 같으면 변경으로 세지 않는다. 서식·설정 값은 서버/기기 이름과 이전/변경 후 색으로 구분하며, 이동 위치는 상위 항목과 바로 앞 항목의 글자로 설명한다. 본문 외 변경이 3곳 이하면 처음부터 펼쳐 보여준다. 내용 없는 문단은 **빈 문단**으로 표시한다. 비교 결과가 같아도 충돌을 자동 해결하지 않으며 반영할 사본은 직접 선택한다.

서버에서 삭제한 자료를 자동 복원하지 않는다. 페이지는 새 사본으로 보관한다. 원본 충돌 해결로 무효가 된 AI/정리 의존 작업은 검토 상태로 남고 자동 실행하지 않는다. 요청 취소 후 원본을 다시 확인하여 새로 요청한다.

## AI 요청과 페이지 정리

메모 또는 페이지에서 요청하면 **요청 당시 원본·템플릿 수정본·추가 지시**를 고정해 기기에 보관한다. 미전송 원본의 저장이 먼저 완료되어야 요청을 제출한다.

- `기기에서 전송 대기`: 서버 작업이 아직 아니다. 전송 전·시도 0인 요청은 취소할 수 있다.
- 서버의 대기/진행/결과 준비/실패: 실제 서버 AI 실행 상태. `/ai`와 원본 상세에서 확인한다.
- 전송한 뒤 응답을 잃은 요청: 임의로 취소/다른 UUID 재제출하지 않고 기존 UUID로 먼저 확인한다.

단일 메모를 페이지로 정리하는 요청도 대기할 수 있다. 서버 성공 전 원본을 목록에서 없애지 않는다. 여러 메모 일괄 정리·정리 되돌리기·AI 결과 적용/되돌리기는 온라인 관리 동작이다. 공유 발급·댓글 등록·지도 생성·휴지통·페이지 도구·프롬프트 수정도 서버 연결 및 필요한 원본 동기화 후 사용한다.

## 검색·첨부·목록

오프라인 검색에는 **이 기기에 보관한 항목**이라고 표시한다. 기기의 메모/할 일, 본문을 열거나 보관한 페이지와 기기에 있는 파일명을 찾는다. 서버 전체 검색·미보관 페이지 본문·OCR/AI 결과 전문을 오프라인에서 다 찾는다고 보장하지 않는다.

메모 목록은 50개씩 이전/다음, 사이드바 페이지는 우선 50개와 추가 표시를 사용한다. 직접 열어 선택한 페이지와 상위 경로는 항상 보인다.

메모 첨부는 파일당 25MiB, 합계 100MiB, 최대 8개. 문서 본문은 1MiB, 전송 작업은 1100KiB. 기기 보관 예산은 기본 200MiB이며 브라우저 남은 용량도 확인한다. 용량이 부족하다고 미전송·충돌 자료를 자동 삭제하지 않는다. 보관 해제는 사용 중인 사본/다른 페이지가 필요로 하는 파일을 남긴다.

브라우저의 영구 저장 요청은 보조 수단이다. OS의 저장소 정리·사용자의 사이트 데이터 삭제·사생활 보호 모드에는 내구성을 보장할 수 없다. 중요한 미전송 자료는 ZIP으로 따로 내려받는다.

## 서버를 복원하거나 옮길 때

1. 기존 주소에서 모든 기기의 미전송 자료를 확인하고 가능하면 동기화한다.
2. 설정의 기기 저장소에서 **미전송 사본 ZIP**을 내려받는다. 원문/고정 요청/충돌 기록과 필요한 첨부·SHA256 목록을 포함한다.
3. 서버 백업을 검증하고 새 경로로 복원한다. 명시 복원은 동기화 `epoch`를 바꾼다. 정상 재시작은 바꾸지 않는다.
4. 기기에서 서버 변경 복구 안내를 확인한다. 최신 ZIP을 내려받고 확인 체크 후, 다시 반영할 변경을 직접 선택한다.
5. 이전 AI/정리 요청은 자동 재실행하지 않는다. 사본을 확인하고 필요한 요청만 새로 제출한다.

다른 workspace에는 기존 미전송 작업을 자동 재생하지 않는다. 돌아갈 workspace에도 오래된 epoch의 미전송 사본이 있으면 연결 변경을 거부하고 먼저 내보내기/복구를 요구한다. 원본은 이전 파티션/복구 기록에 남는다. 새로운 주소는 별도 브라우저 저장소이므로 ZIP을 열어 확인한 뒤 새 주소에서 필요한 자료를 작성/첨부한다. **ZIP 자동 가져오기는 이번 버전에 없다.**

## 앱 업데이트와 되돌리기

새 정적 파일의 다운로드/체크섬 확인이 끝나면 **새 버전 · 저장 후 새로고침**을 표시한다. 사용자가 누르면 기기 편집 저장이 완료된 뒤 활성화한다. 설치 실패 시 기존 준비된 캐시를 남긴다. 개인 API 응답/첨부는 서비스 워커 캐시에 넣지 않는다.

IndexedDB는 `leneu-offline-v1` 이름의 **버전 2**다. v1 → v2는 원본 저장소를 지우지 않고 목록용 `entitySummaries`와 인덱스를 추가한다. 다른 창이 업그레이드를 막으면 안내에 따라 창을 닫고 다시 연다. 구버전 코드로 되돌려 IDB 버전을 낮추거나 사이트 데이터를 삭제하지 않는다. 백업/기기 ZIP을 먼저 확보하고 서버와 클라이언트 호환 버전으로 복구한다.

## 실기기 확인 — 아직 미실시

개발 머신 Chrome 자동화는 통과했지만 아래 표는 실제 iOS/Android에서 각각 수행해야 한다.

| 시험 | 확인 절차 | 합격 기준 |
|---|---|---|
| 설치/재실행 | 개인 HTTPS에서 설치 → 종료 → 재실행 | 같은 작업 공간과 자료가 열림 |
| 잠금/강제 종료 | 저장됨 표시 확인 → 잠금/종료 → 재실행 | 저장 완료 원문과 첨부가 남음 |
| 비행기 모드 | 앱 재실행 → 메모/할 일/보관 페이지 편집 | 로컬 저장·대기 표시, 미보관 명확한 안내 |
| 사진 | 여러 사진 첨부·저장·재실행 | 파일명/크기/원본 bytes 보존, 제한 안내 |
| 네트워크 전환 | Wi-Fi/LTE/끊김 사이 전환, foreground 복귀 | 중복 없이 한 번 반영, 상태 정상 |
| 공유 수신 | OS 공유 메뉴로 URL/사진 전달 | 지원 브라우저에서 원문 수신, 일반 입력과 합침 |
| 충돌 | PC와 휴대폰 같은 페이지 오프라인 편집 | 양쪽 보존 및 명시 선택 |
| 키보드 | 한글 IME·표·슬래시·댓글 입력 | 조합 중 잘못 확정하지 않음, 화면 가림 점검 |
| 업데이트 | 편집 중 새 버전 준비 후 버튼 선택 | 최신 기기 저장 후 전환, 재실행 가능 |

iOS의 OS 공유 수신 지원은 Android와 같지 않을 수 있다. 지원되지 않는 환경은 URL/텍스트 붙여넣기와 파일 선택으로 사용한다. 실제 시험 전 모든 플랫폼에서 동일 지원한다고 광고하지 않는다.

## 최종 검증에서 보강한 동작

- 같은 기기의 두 창이 같은 본문을 수정하면 자동으로 덮지 않는다. 먼저 저장한 원문과 경쟁 사본을 보존하고, 두 번째 창에 원문 다운로드·재열기 안내를 표시한다.
- 전송 전 취소한 AI/정리 요청은 엔진이 오래된 후보를 가지고 있어도 부활하지 않는다. 전송된 요청은 접수 여부를 확인하기 전 새 UUID로 바꾸지 않는다.
- 보관 페이지의 새 버전에 추가 첨부가 있으면 **부분 보관**으로 바뀌고 마지막 완전 본문을 유지한다. 지도/첨부까지 최신으로 보려면 다시 보관한다.
- 서버가 저장 내용을 확정적으로 거부한 경우에는 원문을 고친 뒤 동기화 패널의 **고친 내용으로 다시 전송**을 선택한다. 이전 고정 요청은 기록으로 남고 의존 AI/정리 요청은 다시 검토한다.
- 복구 때 함께 선택한 부모·하위 페이지·본문 링크의 ID를 함께 변환한다. 선택 밖의 페이지가 서버에서 사라졌으면 누락을 알리고 이전 ZIP/복구 기록을 남긴다.
- ZIP에는 원문/불변 요청/충돌/복구 기록과 기기에 있는 필요한 첨부를 포함한다. 필요한 미전송 Blob/업로드 bytes가 없거나 체크섬이 다르면 성공 처리하지 않는다. 한 번도 보관하지 않은 **서버 첨부**는 `manifest.json`의 `complete: false`, `missingAssets`와 복구 화면 경고로 알린다. 이런 ZIP만으로 원격 첨부까지 복원할 수는 없으므로 원 서버 백업도 보관한다.
- 서버 변경 복구 중에는 다른 서버의 페이지·탐색·AI 이력을 기존 작업 공간 캐시에 넣지 않는다. 확인 전에는 이전 기기 사본만 읽는다.

전역 상태의 ‘동기화 완료’는 기기 저장과 대기열 등록 사이 약 500ms 동안 잠시 남아 있을 수 있다. 페이지의 기기 저장 확인과 원문 보존에는 영향이 없으며, 새로 열면 등록하지 못한 변경도 큐로 복구한다. 전역 상태 문구의 이 짧은 간격은 후속 개선 항목이다.

## 일지와 웹 호스팅

일지도 기기에 먼저 저장하고, 연결되면 같은 작업 공간의 서버에 반영한다. 앱을 온라인에서 준비한 뒤에는 `/journal`에서 오프라인 입력과 새로고침을 할 수 있다. 다른 기기에서 같은 날짜를 수정했다면 날짜별 양쪽 사본을 보존하고 동기화 상태에서 확인한다. 서버 SQLite 백업과 기기 복구 ZIP에도 일지가 포함된다.

예전 `anotar:journal:v1` 브라우저 일지는 원문을 남긴 채 한 번 이관한다. 기존 미전송 일지와 내용이 다르면 일지 상단에서 **현재 기기 내용 유지** 또는 **이전 일지로 사용**을 선택하고, 두 사본을 내려받을 수 있다. 다른 작업 공간으로 전환해도 이전 자료를 자동으로 다시 가져오지 않는다. 독립 디자인 프리뷰의 샘플은 실제 일지로 가져오지 않는다.

웹 호스팅의 폴더 등록·목록 조회·공개 상태 변경은 온라인에서 사용한다. 독립 HTML 사이트는 앱의 오프라인 보관 대상이 아니며, 원본 사이트가 사용하는 외부 CDN도 별도로 연결이 필요하다. 사이트 파일 백업은 SQLite 백업과 별도로 한다. [호스팅 안내](STATIC_HOSTING.md)를 참고한다.
