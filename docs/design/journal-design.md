## 사용 흐름

1. 한 달에 남긴 모든 기록을 한 흐름으로 읽는다. 날짜별로 구분하고 오래된 날을 위, 최근 기록을 아래에 둔다.
2. 처음에는 최근 기록 위치에서 시작한다. 위로 스크롤하면 이전 기록을 읽고, 앞선 달의 기록이 있으면 위에 이어 붙인다. 읽던 위치는 유지한다.
3. 아래 작성란에서 방금 한 일·진행 상황·생각을 짧게 적는다. 새 기록은 오늘 항목의 끝에 추가하고 그 위치로 이동한다.
4. 달력이나 월별 기록 목록은 날짜 위치로 이동하는 바로가기다. 다른 날짜의 기록을 숨기거나 작성 날짜를 바꾸지 않는다.
5. 과거 기록을 수정할 때는 작성란에 해당 날짜와 수정 상태를 표시한다. 저장·취소 뒤 작성 중이던 새 기록 초안을 복원한다.

PC는 작은 월별 달력과 연속 기록을 나란히 둔다. 모바일에서는 월 이동과 접을 수 있는 달력을 위에 둔다. 기록 영역만 스크롤하고 작성란은 화면 아래에 계속 보인다. 날짜 제목은 읽고 있는 그룹의 위에서 유지하고 시간·본문·얇은 구분선으로 읽는 순서를 만든다. **최근 기록** 버튼은 오늘의 마지막 기록 위치로 돌아간다.

달 이동은 선택한 달 전체를 보여준다. 이전 기록 보기는 읽는 흐름의 앞에 과거 달을 추가한다. 탐색 중에는 작성 초안을 바꾸지 않는다. 과거 달을 보고 있을 때도 새 기록은 오늘에 남기며 작성란에 날짜를 표시한다. 과거 기록 수정은 원래 날짜와 시간을 보존한다.

## 페이지와의 관계

일지는 짧은 텍스트를 여러 번 저장하는 독립 기록으로 만드는 방향을 권한다. 긴 글이 필요할 때 기존 페이지를 연결하거나 그날의 기록을 페이지로 정리한다.

실제 구현에서는 기록 ID, 업무 날짜, 본문, 생성·수정 시각, 버전과 선택적인 페이지 참조가 필요하다. 업무 날짜는 생성 시각으로 다시 계산하지 않는다. 실제 이력 조회는 커서로 과거 기록을 나누어 가져오고, 위에 추가할 때 보이는 기록의 위치를 유지해야 한다. 오프라인 저장은 기존 IndexedDB·outbox·충돌 보존 구조에 새 엔티티를 추가하는 별도 작업이다.

## 샘플의 범위

- 2026년 9~10월의 가상 업무 기록이다. 샘플에서 ‘오늘’은 2026-10-05로 고정했다.
- 기존 미리보기 저장 자료는 같은 전용 저장소에서 읽고, 없는 9월 예시 날짜만 추가한다. 제품 기록에 접근하지 않는다.
- 전체 달 읽기, 날짜 이동, 위로 이전 달 연결, 아래 새 기록 추가, 수정·삭제, 테마 변경을 체험할 수 있다.
- 기록은 `anotar:journal-design:v1` 브라우저 저장소에만 저장한다. 다른 브라우저·기기와 공유되지 않는다.
- 저장 실패 시 원래 기록과 작성 초안을 유지한다. 날짜 탐색과 과거 기록 수정·취소도 새 기록 초안을 지우지 않는다.
- 이력은 샘플 저장 자료에서 읽는다. 서버 페이지네이션·제품 API·수정 이력·서버 동기화·AI 요청은 연결하지 않았다.
- 실제 일지 메뉴와 저장 구조는 아직 제품에 추가하지 않았다.

검증 범위는 [월별 연속 기록 확인](../../.omo/evidence/journal-stream/REPORT.md)을 따른다.
