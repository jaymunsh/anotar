# URL 리서치·자유 요청과 프롬프트 관리 설계

작성: 2026-09-28
상태: 2026-09-28 사용자 의견을 반영한 설계 초안. 기존 네 가지 고정 AI 작업을 URL 리서치·자유 요청으로 바꾸고, 프롬프트를 사이트에서 관리하도록 분리한다. **AI를 체크한 채 저장하면 원본 저장 직후 작업을 시작한다**는 실행 시점은 사용자 확인을 받았다. 투두는 [별도 설계](2026-09-28-task-workspace-design.md)를 따른다. 현재 구현은 [현재 구현 규격](../../../CURRENT_IMPLEMENTATION.md)을 따른다.

## 2026-09-29 현재 구현 참고

이 문서의 아래 화면 시안·입출력 예시는 실행 연결 전의 설계 기록이다. 이후 **작업 큐·Devin/HTTP 실행기·URL 수집·결과·이력·명시 재요청**을 구현했다. 현재 실행 계약은 [AI 실행 설계](2026-09-29-ai-execution-design.md)와 [현재 구현 규격](../../../CURRENT_IMPLEMENTATION.md#ai-요청-실행), 설정·일반 검증/실호출 구분은 [README](../../../README.md#ai-실행기-설정)을 따른다.

현재 추가 요청은 1,000자, JSON 결과는 256KiB이고 잘못된 AI 설정은 전체 저장 400·원자적 롤백이다. 같은 요청 재시도는 이전 입력 사본을, 현재 내용 요청은 현재 원문과 보관한 템플릿을 사용한다. 첨부 전송·OCR·결과 채택·결과 검색·OS 격리는 후속 범위다. 아래의 초기 2,000자·aiError·별도 DerivedContent 등은 현재 API/스키마로 해석하지 않는다.

## 현재 확인할 수 있는 화면 시안

2026-09-29 현재 `/prompts`는 서버 SQLite의 템플릿·불변 수정본·브라우저 이관·JSON 교환을 제공한다. 입력함에서 AI를 체크하고 보관하면 Capture와 당시 템플릿·입력·추가 조건·조립 요청문을 함께 저장한다. `/memo?view=ai`에서 **실행 전** 요청을 읽고 복사한다. 원본·템플릿 수정으로 사본을 바꾸지 않는다. 최초 템플릿 조회 전에는 복구한 선택을 직접 요청으로 바꿔 저장하지 않는다. 사용자가 직접 요청을 명시적으로 선택하면 라이브러리 없이 보관할 수 있다.

**AI·URL 수집·작업 큐·결과 생성은 연결하지 않았다.** 아래의 작업 실행 계약은 이후 목표이며 현재 요청 사본을 대기 작업이나 실행 기록으로 취급하지 않는다. 상세한 현재 규격은 [현재 구현](../../../CURRENT_IMPLEMENTATION.md)과 [메모 관리 규격](2026-09-29-memo-library-design.md)을 따른다.

## 목적과 범위

사용자는 대부분 혼자 메모·URL·스크린샷을 빠르게 보관한다. AI는 URL에 저장된 리서치 프롬프트를 적용하거나 자유로운 요청을 수행한다. 프롬프트를 웹에서 관리해 반복 요청을 재사용한다. 할 일은 AI 결과와 독립적으로 직접 추가·수정·완료할 수 있어야 한다. N100·16GB RAM 환경에서 모델을 직접 실행하지 않고 설치형 에이전트 또는 선택적으로 연결한 외부 API를 호출한다.

성공 기준은 다음과 같다.

1. AI를 선택하지 않은 저장은 지금처럼 작동하고 외부 호출이 없다.
2. 체크하면 요청 설정 줄이 펼쳐진다. 저장 응답은 AI 완료를 기다리지 않는다.
3. 선택한 요청은 서버 재시작 후에도 남고, 네트워크 재제출로 중복 작업이 생기지 않는다.
4. 작업마다 요청 당시 원본·템플릿·실행기 버전이 고정된다. 최신 메모와 다른 결과를 구별할 수 있다.
5. 결과를 검증한 뒤 별도 제안으로 저장한다. AI 실행기에 Capture·Page 변경 권한을 주지 않는다.

첫 범위는 URL 리서치·자유 요청, 사이트의 프롬프트 관리, 영속 작업 큐, 요청·상태·결과 UI, 공통 실행기 계약이다. 실제 연결은 선택한 실행기 하나부터 검증한다. AI 결과가 없어도 투두를 쓸 수 있다. 이미지·일반 파일 이해는 실행기의 실제 지원을 확인해 추가하며, 지원되지 않는 AI 입력이라는 이유로 원본 업로드를 막지 않는다.

## 선택한 접근

| 접근                                       | 특징                                           | 판단                           |
| ------------------------------------------ | ---------------------------------------------- | ------------------------------ |
| 저장 HTTP 요청 안에서 AI까지 실행          | 서버가 결과를 받을 때까지 저장이 끝나지 않음   | 빠른 입력의 응답성에 맞지 않음 |
| **저장과 작업 등록 후 별도 작업자가 실행** | 원본·요청을 먼저 영속화하고 결과는 나중에 표시 | 채택                           |
| 저장 후 상세에서만 별도 실행               | 저장 뒤 한 번 더 눌러야 함                     | 기존 항목 재요청에 제공        |

별도 메시지 큐 서버는 추가하지 않는다. 현재 SQLite에 작업을 기록하고 작은 Node 작업자가 하나씩 가져온다. 브라우저에는 AI SDK나 에이전트 실행 코드를 넣지 않는다.

## 입력 화면

```text
메모 내용…

☑ AI 요청
  [URL 리서치 템플릿 ▾]  [프롬프트 보기]
  [중점적으로 볼 내용 — 선택]

                         [보관하고 AI 요청]
```

- 기본 체크는 꺼져 있다. 체크 자체는 실행하지 않고 설정만 펼친다.
- 데스크톱은 선택·추가 조건·프롬프트 보기를 한 줄에 둔다. 모바일은 두 줄로 배치하며 기존 입력 시트의 스크롤과 저장 동선을 유지한다.
- URL은 `URL 리서치`, 메모는 `자유 요청`을 처음 제안한다. 실행 가능한 다른 방식을 사용자가 고를 수 있고, 내용 분석으로 선택을 몰래 바꾸지 않는다.
- 리서치는 URL과 저장된 리서치 프롬프트를 받는다. 첫 기본 프롬프트는 핵심 내용·근거·확인할 점·출처를 정리한다. 3줄 요약 여부와 본문 구성은 프롬프트에서 정한다.
- 자유 요청은 `직접 요청` 또는 저장된 자유 프롬프트를 선택한다. `직접 요청`에서는 메모 본문이 요청문이다. 프롬프트를 고르면 메모를 입력 자료로 사용하며 추가 조건을 덧붙일 수 있다. 결과를 할 일·계획 같은 고정 형식으로 강제하지 않는다.
- 추가 조건은 선택 사항이며 초기 제안 상한은 2,000자다. 프롬프트 보기는 실제 요청문과 사용한 변수를 보여주고 프롬프트 관리 화면으로 이어진다.
- 첨부 전달은 사용자가 명시적으로 선택하고 실행기가 지원할 때만 가능하다. 첫 텍스트/URL 연결에서는 첨부를 자동으로 보내지 않는다.
- 일반 파일 또는 실행기에서 지원하지 않는 이미지 형식은 이유를 표시한다. AI 실행이 불가능해도 원본 보관은 가능하다.
- 저장 중 중복 제출을 막는다. 성공 후 제출한 스냅샷과 화면 입력이 같을 때만 입력과 AI 체크를 초기화해 전송 중 새로 쓴 내용을 지우지 않는다. 저장 실패 시 내용과 요청 설정을 유지한다.
- 작업 등록 성공 시 `보관했어요 · AI 정리를 요청했어요`를 표시한다. 원본은 저장됐지만 AI가 준비되지 않았다면 두 상태를 구분하고 원본을 다시 업로드하도록 유도하지 않는다.

기존 항목 상세에도 `AI 요청`을 두고 동일한 요청 설정을 재사용한다. 여기서는 `실행`을 눌러 현재 원본 버전으로 새 작업을 만든다. 메모를 수정하는 동작만으로 AI를 다시 실행하지 않는다.

## 사이트의 프롬프트 관리

공통 셸 안의 `/prompts`에서 프롬프트 목록·생성·수정·복제·보관을 제공한다. 초기 기본 프롬프트도 사이트에서 수정할 수 있다. 편집은 가벼운 일반 텍스트 입력으로 제공하며 BlockNote를 불러오지 않는다.

| 필드           | 동작                                                            |
| -------------- | --------------------------------------------------------------- |
| 이름·설명      | 목록과 실행 선택란에 표시                                       |
| 종류           | `research` 또는 `free`                                          |
| 프롬프트 본문  | Markdown 형태의 일반 텍스트. 초기 제안 상한 10,000자            |
| 입력 변수      | `{{url}}`, `{{content}}`, `{{memo}}`. 서버가 등록한 변수만 지원 |
| 버전·보관 여부 | 수정 저장마다 새 버전. 보관하면 새 요청 선택란에서 제외         |

`PromptTemplate`은 정체성과 표시 정보를, `PromptRevision`은 변경하지 않는 본문·종류·변수 정의를 가진다. 작업은 선택 당시의 Revision ID를 저장한다. 실행 중 프롬프트를 고쳐도 기존 작업의 내용은 바뀌지 않는다. 참조된 버전은 보존하며 영구 삭제 대신 보관한다. 다른 탭의 프롬프트 수정에는 버전 충돌 검사를 적용한다.

미등록 변수는 저장 시 오류로 표시한다. 치환은 등록 변수 토큰에 한 번만 적용하고, 메모나 URL 본문 안의 변수 표기를 다시 해석하지 않는다. 이름을 바꾸거나 기본 프롬프트를 보관해도 `직접 요청`은 사용할 수 있다.

## 리서치 하네스와 자유 요청

프롬프트는 요청 내용과 보고서 구성을 관리하고, 서버의 하네스는 입력 수집·출처·실행 범위·시간·결과 저장을 관리한다. 프롬프트 편집으로 서버의 실행 권한이나 제한을 바꾸지는 않는다.

- **URL 리서치:** URL을 검증하고 본문을 수집해 선택한 프롬프트에 전달한다. 첫 범위는 입력한 URL의 분석이다. 여러 사이트 검색은 실행기의 지원과 별도 작업 정책을 확인한 후 확장한다. 원문에 없는 사실은 구분하고 접근 실패·자료 부족을 결과에 남긴다.
- **자유 요청:** 직접 쓴 요청 또는 저장한 프롬프트와 메모를 전달한다. 일반 Markdown 응답을 받는다. 별도 작업 종류별 JSON을 강제하지 않으며, 앱 데이터에 반영할지는 사용자가 결정한다.
- **공통 결과:** 검증한 Markdown 본문, 출처 배열, 작업·입력 버전, 사용한 프롬프트 버전, 시각과 실행 메타데이터다. 리서치의 출처는 실제 수집 자료와 대조한다. 자유 응답의 링크를 수집으로 검증한 출처인 것처럼 표시하지 않는다.
- 출력 언어는 기본 한국어이며 프롬프트에서 바꿀 수 있다. 원문이 빈 경우나 URL 접근에 실패한 경우에는 아는 것처럼 보고서를 생성하지 않는다.

사용자가 자유 프롬프트로 `메모를 체크리스트로 정리해줘`를 저장할 수는 있다. 그것을 앱의 필수 AI 작업으로 고정하거나 AI 결과를 자동으로 투두에 등록하지 않는다.

## 원본 저장과 작업 등록

저장 요청에 선택적 `requestId`와 `aiRequest`를 추가한다. `requestId`는 제출할 초안의 UUID이며 응답을 잃은 재제출에도 유지한다. `aiRequest`에는 `mode`, 선택적 `promptRevisionId`, 추가 조건, 선택한 업로드 파일의 순번만 들어간다. 직접 요청은 본문의 스냅샷을 사용한다. 실행 명령과 파일 경로는 클라이언트에서 받지 않는다.

서버는 기존 원본·파일 검증을 먼저 적용한다. 원본 저장과 유효한 AI 작업 등록은 같은 SQLite 트랜잭션으로 기록하고 응답한다. 이 경로에서는 외부 접속·모델 실행을 하지 않는다. 실행기 미연결·기능 부족은 작업을 `failed`로 기록하고 원본은 성공 응답으로 돌려준다. 잘못된 템플릿 설정은 원본 저장 응답에 별도 `aiError`로 알려준다. 사용자는 기존 항목에서 AI 요청만 다시 시도할 수 있다.

`requestId`와 정규화한 텍스트·URL·파일 순서·파일 해시·AI 설정의 지문을 함께 보관한다. 같은 ID와 내용은 같은 Capture·작업을 반환하고, 같은 ID에 다른 내용은 409로 거절한다. 중복 요청에서 만들어진 임시 업로드는 지운다. 기존의 `requestId` 없는 저장 요청도 계속 허용한다.

## 작업과 결과 저장

| 기록                | 주요 값                                                                                                                                                             |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CaptureSubmission` | `requestId`, 요청 지문, Capture ID, 작업 ID                                                                                                                         |
| `ProcessingJob`     | ID, Capture ID·버전, 원본 텍스트·URL 스냅샷, 선택 Asset ID, 요청 방식·프롬프트 Revision ID·직접 요청, 추가 조건, 실행기 ID·설정 버전, 상태·시각·실행 토큰·오류 코드 |
| `DerivedContent`    | 작업 ID, 결과 스키마 버전, 검증된 Markdown·출처를 담은 JSON, 출처, 생성 시각, 보고된 사용량·비용                                                                    |

자산 바이트는 복제하지 않고 Asset ID로 참조한다. 원본 텍스트·URL과 작업 정의는 요청 시 고정한다. 템플릿을 수정하더라도 이미 대기 중인 작업의 의미가 바뀌지 않도록 렌더링할 정의 또는 그 버전을 보존한다.

```text
queued → running → result_ready
                  ↘ failed
```

작업자는 DB 트랜잭션으로 하나를 점유하고 실행 토큰을 발급한다. 초기 동시 실행은 1개, 작업 제한은 120초, 결과 JSON 상한은 256KB다. 출력 토큰 한도를 지원하는 실행기는 4,096으로 제한한다. 결과 저장은 현재 실행 토큰과 `running` 상태가 일치할 때만 허용해 지연된 응답이 새 시도를 덮지 못하게 한다. 제한을 넘으면 작업 프로세스와 자식을 종료한다. 로컬 종료가 제공자의 이미 진행 중인 원격 호출이나 비용까지 취소한다고 표시하지 않는다.

재시작으로 실행 결과가 불명확해진 작업은 `실행이 중단됐어요` 실패로 남긴다. 비용이 드는 호출을 자동으로 다시 시작하지 않는다. 사용자의 재시도는 현재 원본을 다시 확인해 `retryOf`를 가진 새 작업으로 만들며 이전 결과·이력을 덮지 않는다. 같은 재시도 요청 ID는 중복 작업을 만들지 않는다.

작업 중 메모가 수정돼도 요청 스냅샷으로 처리한다. 결과를 볼 때 현재 Capture 버전과 비교해 다르면 `이전 내용 기준`을 표시하고 현재 내용으로 다시 요청할 수 있게 한다. 버전 차이 때문에 완성된 결과를 삭제하지 않는다.

## 실행기 어댑터와 하네스 경계

작업자는 `run(jobInput, outputSchema, limits)` 계약을 통해 실행기를 호출한다. `outputSchema`는 작업별 할 일·계획 구조가 아닌 Markdown과 출처를 담는 공통 응답 규격이다. 설치형 에이전트와 API는 같은 입력·결과·오류 규격을 사용한다. 실행기는 설정에서 선택하며 요청마다 자동으로 바꾸지 않는다. 선택한 실행기가 실패해도 다른 제공자나 유료 API로 자동 전환하지 않는다.

설치형 실행기는 작업별 임시 공간에 필요한 텍스트·선택 파일·결과 스키마만 받는다. DB, 전체 첨부 디렉터리, Docker 소켓, 개인 앱 관리 권한은 전달하지 않는다. 인증 정보는 실행기에만 제공한다. 실행 명령은 서버 설정의 고정 프로그램과 인자이며 사용자 메모를 셸 명령으로 조합하지 않는다.

메모·URL 본문은 분석 자료로 전달하고, 사용자가 작성한 프롬프트·직접 요청과 구분한다. 첫 실행 정책은 서버가 준비한 자료에 대한 텍스트 응답이며 도구 권한은 프롬프트가 아니라 실행기 설정으로 제한한다. 결과는 크기·스키마·URL을 서버에서 검사한 뒤 저장하며 HTML이나 실행 가능한 코드를 그대로 렌더링하지 않는다. 입력 요청문·원문·키는 일반 로그에 남기지 않고 작업 ID, 소요 시간, 오류 코드, 제공자가 보고한 사용량만 기록한다. 사용량을 보고하지 않는 실행기는 값을 `null`로 남겨 추정 비용을 사실처럼 표시하지 않는다.

URL 수집은 작업자가 맡는다. HTTP/HTTPS 공개 주소만 허용하고 DNS 해석과 각 리다이렉트에서 로컬·사설·예약 주소를 차단한다. 초기 제한은 10초, 리다이렉트 3회, 응답 2MB, 추출 텍스트 50,000자다. 실제 수집 주소와 시각을 출처에 남긴다. 에이전트의 임의 웹 탐색은 첫 템플릿에 허용하지 않는다.

## 상태·결과 UI와 API

목록 카드의 현재 높이와 NEW 배치를 유지한다. 시간 줄에는 작은 AI 상태만 추가하고 결과 본문은 상세에서 보여준다. 상세는 대기·처리 중·완료·실패를 구분한다. 완료 결과는 원문 다음 별도 영역에서 읽고 복사할 수 있다. 실패에는 원인과 명시적 재요청을 제공한다. `result_ready`는 사용자가 내용이나 기한을 승인했다는 뜻이 아니다.

할 일 후보는 [투두 설계](2026-09-28-task-workspace-design.md)에 따라 명시적으로 등록한다. 자유 프롬프트 결과의 Markdown 체크리스트나 사용자가 선택한 문장도 이 등록 경로를 쓸 수 있다. AI가 Capture·Task를 수정하거나 Page에 자동으로 글을 넣지 않는다. 공개 공유 API에는 작업 요청·결과 조회·프롬프트 관리 경로를 등록하지 않는다.

페이지 정리는 [페이지 연결 설계](2026-09-27-capture-page-connection-design.md#2026-09-29-메모-관리와-페이지-정리의-구분)를 따른다. 후속 구현에서는 완료 결과를 검토한 뒤 기존 페이지나 새 하위 페이지에 필요한 내용과 출처를 담는다. 확인 전 결과는 별도로 보존하며 완료만으로 문서를 수정하지 않는다. 임시 문서는 필수 경로로 두지 않는다. 검증된 Markdown을 편집 블록으로 변환하고 원본·결과 ID를 연결하며 재시도 중복과 부분 이동을 막는다. 결과 담기·블록 분배·AI 실행은 아직 없다.

- `GET /api/prompt-templates`: 종류별 프롬프트 목록·현재 버전·실행 가능 여부. 인증 비밀값은 제외한다.
- `GET /api/prompt-templates/:id`: 관리 화면과 요청 미리보기에서 사용할 현재 본문·버전 조회.
- `POST /api/prompt-templates`, `PUT /api/prompt-templates/:id`: 생성 또는 `expectedVersion`을 검사한 수정·새 버전 저장.
- `PATCH /api/prompt-templates/:id`: 보관·복원. 참조된 버전을 삭제하지 않는다.
- `POST /api/captures`: 기존 multipart에 선택적 요청 ID·AI 설정. 응답은 `{ item, aiJob?, aiError? }`다.
- `POST /api/captures/:id/ai-jobs`: 기존 원본 또는 재시도 요청. `requestId`, `expectedVersion`, 요청 방식·프롬프트 버전·추가 조건·Asset ID, 선택적 `retryOf`를 받아 현재 원본 버전과 자산·이전 작업의 소속을 검증한다.
- `GET /api/captures/:id/ai-jobs`: 해당 원본의 작업 목록과 결과 메타데이터.
- `GET /api/ai-jobs/:id`: 작업 상태와 검증된 결과.

화면에 보이는 항목의 진행 중 작업만 가벼운 폴링으로 갱신하고 완료·실패 후 멈춘다. 창이 보이지 않을 때 폴링을 중단한다. WebSocket·SSE나 페이지 편집기 코드를 입력함 첫 로드에 추가하지 않는다.

## 검증 시나리오

1. 체크를 끄고 저장하면 작업이 생기지 않고 실행기 호출도 없다. 켜면 한 줄이 펼쳐지고 기본 템플릿을 바꿀 수 있다.
2. 느린 실행기를 사용해도 Capture 저장 응답과 입력 초기화가 먼저 완료된다. 작업 등록과 저장 확인 후 서버를 재시작해도 대기 요청이 남는다.
3. 응답을 잃은 동일 제출·동일 AI 재요청은 Capture·작업을 중복하지 않는다. 같은 ID의 다른 요청은 409다.
4. 미연결 실행기·지원하지 않는 파일·실행 제한 초과·잘못된 결과가 원본 저장·검색·수정을 망가뜨리지 않는다.
5. 실행 중 원본을 수정하면 결과에 이전 버전 표시가 생긴다. 재시도 뒤 늦게 온 이전 결과는 새 결과를 덮지 않는다.
6. 명령처럼 생긴 메모와 URL 본문, 위험한 결과 URL, 다른 Capture의 Asset ID를 검증한다. URL 수집은 리다이렉트·DNS를 통한 내부 주소 접근도 막는다.
7. 데스크톱, 320px·390px 모바일, 밝음·어두움에서 긴 추가 요청·오류·실제 결과를 확인한다.
8. URL 리서치와 자유 요청 사례로 공통 응답·출처·자료 부족 처리를 검사한다. 프롬프트 수정·보관 뒤에도 이전 작업의 버전과 본문이 남는지 확인한다. 테스트용 가짜 실행기 결과는 실제 AI 응답으로 표시하지 않는다.
9. 프롬프트 생성·수정·복제·보관, 잘못된 변수, 동시 수정 충돌을 확인한다. 자유 요청은 직접 작성과 저장된 프롬프트 모두 동작해야 한다.

## 구현 순서

1. 별도 투두 저장·홈 패널을 먼저 만들어 실제 할 일을 직접 관리할 수 있게 한다.
2. 웹 프롬프트 관리와 버전 있는 저장·치환 계약.
3. 공통 작업 큐·중복 방지·응답 계약, 체크 줄·기존 항목 요청·상태·결과 UI.
4. 선택한 실행기 하나와 URL 수집을 연결해 URL 리서치·자유 요청을 검증. 연결되지 않은 상태를 성공처럼 꾸미지 않는다.
5. 실행기의 지원에 맞춘 첨부 처리, 선택한 AI 결과의 투두 등록, 페이지 채택을 추가.

실행기 제품·인증·모델은 실제 연결 전에 확인한다. 이 문서는 특정 제품의 로그인 방식이나 이미지·구조화 출력 지원을 이미 검증한 것으로 취급하지 않는다.
