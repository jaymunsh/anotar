# 메모의 페이지 전환과 페이지 AI

2026-09-29. 사용자가 승인한 설계이며 [구현 계획](../plans/2026-09-29-memo-page-lifecycle.md)에 따라 구현했다. 현재 동작의 규격은 [CURRENT_IMPLEMENTATION.md](../../../CURRENT_IMPLEMENTATION.md), 검증 기록은 [수명 주기·페이지 AI 확인](../../../.omo/evidence/page_ai_lifecycle.md)을 따른다. Devin 모델 기본값은 `swe-2-high`다.

## 제품 관계

- **메모:** 빠르게 담은 내용이 정리 전 머무는 입력함이다.
- **페이지:** 내용을 정리하고 계속 편집·공유할 문서다. AI 결과를 편집 가능한 문서로 채택할 수 있다.
- **AI 요청:** 메모 또는 페이지의 특정 저장 버전을 대상으로 한 작업 이력이다. 작성 내용·요청문 사본·결과·출처는 불변이다.

## 메모 → 페이지

추천 기본 동작은 **페이지로 옮기기**다. 새 페이지·하위 페이지·기존 페이지에 결과나 메모 내용을 담고, 성공한 뒤 원본 메모를 **정리 완료**로 표시한다.

- 일반 메모·AI 요청 목록, 개수와 기본 검색에서 정리 완료 메모를 제외한다. 정리 완료 필터와 되돌리기로 원본을 다시 입력함에 놓을 수 있다.
- 원본 Capture·파일·AI 요청 이력은 보존한다. 휴지통 이동이나 영구 삭제와 구분한다. 페이지 정보의 출처·AI 이력에서 당시 내용을 확인한다.
- 본문에는 원본 메모 카드와 중복 원문을 자동으로 넣지 않는다. 선택한 문서 내용과 실제 자료 링크·출처만 넣는다.
- 원문·첨부 복사는 사용자가 고른 내용만 반영한다. 파일 바이트는 기존 Asset을 재사용한다. 페이지 원본은 블록 JSON이며 문서 전체 Markdown 교환은 유지한다.
- `organized_at`, `organized_page_id`로 정리 상태와 현재 연결 페이지를 기록한다. 여러 가져오기 이력은 별도 출처 관계와 기존 작업 영수증으로 남긴다. 페이지 본문 참조 색인과 출처 이력을 구분한다.
- 페이지 저장·출처 관계·정리 상태·작업 영수증을 한 트랜잭션에서 확정한다. 저장 실패 때 원본은 입력함에 남는다. 응답 유실 재시도는 최초 UUID·내용·선택을 재사용한다.
- 기존 가져오기 계약의 기본은 복사로 유지하고 새 화면은 명시적인 `disposition: 'organize'`를 보낸다. 기존 UUID 영수증·이미 작성한 페이지·메모는 자동 변경하지 않는다.
- 연결 페이지가 휴지통으로 가면 정리 완료 이력에서 그 상태를 보여주고 복원하거나 메모를 입력함으로 돌릴 수 있다. 복사한 파일·기존 AI 이력은 유지한다.

## 페이지 AI와 수정

페이지 도구에 **AI 요청**을 제공한다. 페이지 전체 또는 선택한 블록을 입력으로 삼고 기존 프롬프트 템플릿·추가 지시·작업자와 상태·결과 표시를 재사용한다.

1. 요청 전 페이지의 미저장 변경을 저장한다. 실패·충돌 상태에서는 먼저 저장 문제를 해결한다.
2. 저장 버전, 해당 블록 ID와 원본 문서, Markdown 입력, 당시 템플릿·추가 지시를 요청 사본으로 고정한다. 참조 대상의 본문·파일 바이트를 자동으로 포함하지 않는다. 기존 입력 한도를 넘으면 범위를 줄이도록 안내한다.
3. 작업이 실행되는 동안 페이지는 계속 편집할 수 있다. 결과는 별도 제안으로 표시하고 자동으로 본문을 바꾸지 않는다.
4. 결과에 **문서 아래 추가 / 선택한 블록 교체 / 새 하위 페이지**를 제공한다. 기본은 문서 아래 추가다. 선택 영역이 없는 요청에서는 블록 교체를 제공하지 않는다.
5. 교체는 요청 당시 선택한 블록과 문서 버전이 유지됐을 때만 적용한다. 요청 후 문서가 바뀌면 **요청 후 문서가 수정됨**을 표시하고 교체를 막는다. 최신 버전을 확인해 추가하거나 범위를 다시 골라 재요청할 수 있다.
6. 반영은 `expectedVersion`과 UUID로 검사한다. 성공 직전의 문서·제목 수정본, 새 문서와 반영 영수증을 원자적으로 저장한다. 응답 유실은 같은 반영을 확인하고 다른 편집본을 덮지 않는다.
7. 반영 직전 수정본으로 되돌릴 수 있다. 되돌리기도 현재 버전을 검사하고 새 편집 이후의 내용은 자동으로 덮지 않는다. 일반 편집기의 실행 취소와 서버 수정본을 구분한다.

AI 수정본은 블록으로 검증해 반영하며 바뀌지 않은 블록·첨부·목차·페이지 링크는 유지한다. 전체 페이지를 Markdown으로 다시 파싱해 일괄 교체하는 동작은 첫 버전에 넣지 않는다. 결과 사본을 고쳐도 원래 요청·AI 결과는 변경하지 않는다.

## 구현 전 구조와 변경 범위

구현 전 `ai_jobs`는 `capture_id NOT NULL`과 Capture 버전 비교에 연결돼 있었다. 페이지 요청을 위해 다음 저장 구조 변경을 함께 적용한다.

- 작업 테이블에 nullable `capture_id`·`page_id`를 두고 둘 중 정확히 하나를 소유자로 둔다. 기존 작업 ID·요청 사본·결과·재시도 관계를 보존하는 이관을 먼저 검증한다.
- 작업자와 상태·이력 조회는 메모/페이지 대상과 저장 버전을 다룬다. 공개 공유 화면에는 AI 실행·개인 이력 API를 제공하지 않는다.
- 본문 출처 카드 대신 페이지의 출처 메타데이터를 만든다. 목록·검색·복원·파일 접근은 정리 완료와 휴지통을 각각 처리한다.
- AI 채택 직전 수정본과 반영 영수증을 저장한다. 페이지 AI 첫 버전부터 재시도 중복·버전 충돌·되돌리기를 함께 구현한다.

## 추천 진행 순서와 검증

1. 메모 정리 상태·본문 출처 카드 제거·페이지 출처 정보와 되돌리기.
2. 메모/페이지 공통 AI 작업과 페이지 요청·상태·이력.
3. 결과 추가·선택 교체·하위 페이지, 반영 직전 수정본과 복원.

각 단계는 임시 저장소로 전환 실패의 원자성, 기존 영수증 재전송, 목록·검색 제외/복귀, 파일 보존, 이력 이관, 요청 중 편집, 반영/복원 충돌과 응답 유실 중복 방지를 검사한다. 화면은 기존 팔레트·글꼴·컴팩트한 도구를 재사용한다. 실제 기존 문서는 마이그레이션이나 검증을 위해 자동으로 재작성하지 않는다.
