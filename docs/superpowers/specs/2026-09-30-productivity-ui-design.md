# 생산성 UI 완성도 개선

사용자의 `진행해봐~`는 직전 제안의 다섯 항목을 순차 구현하는 승인이다. 혼자 쓰는 leneu의 빠른 입력·원본 보존·조용한 문서 화면을 유지하며 탐색과 반복 정리를 줄인다. 코드 수정, 로컬 검증과 문서화 범위이며 커밋·원격 배포·실제 AI 호출은 포함하지 않는다.

## 설계

1. **탐색:** 즐겨찾기·최근 열람은 같은 SQLite의 private side table로 저장한다. Page 본문/수정일/version을 바꾸지 않는다. 활성 페이지 metadata만 읽고 최대 8개씩 표시하며 즐겨찾기는 100개까지 저장한다. 열람은 성공적으로 열린 개인 문서에서 기록하고 읽기 실패 때 기록하지 않는다. 휴지통은 목록에서 제외한다. 페이지 트리 이동은 명시 목적지 선택기/키보드 동선과 성공·실패·재시도 피드백을 제공한다. 자손으로 이동은 막고 서버 기존 검증을 유지한다. 홈에는 최근 열람으로 이어서 작업하기가 보이며 기존 최근 수정 목록을 보존한다.
2. **메모:** PC 1101px 이상에서 `/memo` 목록과 상세를 함께 유지한다. 이전/다음은 현재 목록 범위에서 이동하며 수정·정리·삭제 요청 중에는 이동하지 않는다. 모바일은 기존 보호된 상세 시트를 유지한다. 입력함 일반 메모에 선택 모드를 제공하고 최대 20개를 한 Page에 정리한다. 항목별 원문·첨부 선택을 확인하며 AI 결과를 자동 채택하지 않는다. 새/기존 페이지로 묶는 작업은 원자적 트랜잭션, UUID 불변 영수증, Page/Capture 버전 검사와 전체 실패 rollback을 갖는다. 응답 유실/새로고침의 동일 요청은 Page/블록/원본 정리를 중복하지 않는다. 성공 전 사본·선택을 보존하고 원본/첨부를 삭제하지 않는다.
3. **홈:** 작은 입력을 우선하며 이어서 작업하기, 기한 있는 할 일, 준비된 AI 결과·미확인 댓글의 다음 행동을 쉽게 찾는다. 기존 상태/API를 재사용한다. 결과 준비를 검토/반영 완료로 해석하지 않는다. 관리/프롬프트/백업/휴지통은 접을 수 있는 보조 탐색으로 묶는다. AI 실행 현황과 요청 원본의 용어를 구분한다.
4. **편집·키보드:** 기존 선택 블록 이동·목차·템플릿·첨부·이력은 보존한다. 선택된 블록의 작업 진입점을 가까이 표시하고 문서 관리 메뉴를 분류한다. `⌘K/Ctrl+K`에 내용 검색과 분리된 새 메모·페이지·할 일·현재 페이지 도구 등의 명령 영역을 제공한다. 실제 동작 이벤트로 연결하며 한글 조합 Enter가 명령을 실행하지 않는다. 검색 결과/명령의 초점·Esc·접근 가능한 설명을 유지하고 편집기를 초기 번들로 끌어오지 않는다.
5. **시각 규격:** 숲색/차콜 테마·현재 서체를 유지한다. 보조 글씨 12px 이상, 조작 32px 이상 PC/44px mobile, 일관된 focus/disabled/loading 상태. 문단은 읽기 폭을 제한하고 일정/지도/표/코드 rich block은 기존 넓이를 사용할 수 있다. 댓글 위치/패널의 안정성을 보존하며 장식 애니메이션/지속 레이아웃 애니메이션을 추가하지 않는다.

## 검증

새 의미 있는 서버 동작은 failing test → 구현 → scoped test. UI는 임시 DB·실제 Chrome에서 1440/390/320px 밝음/어두움 한 묶음으로 검사한다. 탐색 preference 교차 브라우저·읽기 실패/삭제 필터·Page 불변, 이동 실패/키보드; batch 원자성/충돌/UUID/첨부/불변 원본/복구; 명령 IME와 동작 연결; PC 상세 목록 유지/변경 중 이동 금지를 검증한다. 문제를 한 번에 수정하고 필요한 delta만 재확인한다. 전체 tests/build, 기존 영향 경로 QA, 독립 scoped review로 마무리한다.

## 후속 범위

범용 속성 데이터베이스/태그/저장 뷰는 직전 제안의 후속 아이디어이며 이번 다섯 항목에 포함하지 않는다. 실제 서버/휴대폰 설치/AI 제공자는 별도 환경이다.
