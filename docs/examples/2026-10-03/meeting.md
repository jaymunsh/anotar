빠른 메모를 더 많이 쌓는 것보다, 필요한 자료를 읽으며 한 편의 문서를 완성하기 쉽게 만드는 방향으로 정리했다. 이번 결정은 **목적별 템플릿, 자료 가져오기, 긴 문서 읽기**를 하나의 작성 흐름으로 연결하는 것이다.

## 회의 개요

2026년 10월 3일 사용자와 개발 에이전트의 대화에서 나온 요구와 반영 결과를 정리한 기록이다. 별도 회의를 개최한 기록은 아니다. 검토 대상은 leneu의 페이지 작성과 여행 계획 공유다.

사용자는 생산성·가독성·리포트 정리를 개선하고 싶었고, 에이전트도 활용할 수 있는 템플릿과 더 나은 여행 문서를 요청했다. 완성 기준은 ‘기능이 존재한다’보다 ‘실제 내용이 들어간 글을 읽고 고칠 수 있다’에 가깝다.

## 안건과 논의

### 어떤 문서부터 템플릿으로 만들 것인가

리서치·여행·회의·개발 기록을 우선 대상으로 골랐다. 같은 빈 문서에서 출발하더라도 질문과 근거를 쓰는 글, 날짜별로 움직이는 계획, 합의된 결정을 남기는 기록은 읽는 순서가 다르기 때문이다.

템플릿의 안내 문구는 작성할 위치를 알려주는 용도로 둔다. 에이전트가 이를 실제 사실이나 완료된 작업처럼 채워서는 안 된다. 모르는 내용은 미확인으로 남기고 확인 근거를 적는다.

### 자료를 가져올 때 원본은 어떻게 다룰 것인가

메모와 AI 결과를 보며 문서를 작성하려면 자료를 옆에 열어둘 수 있어야 한다. 단순히 전부 복사하는 것보다 읽는 사람이 필요한 부분을 골라 넣는 흐름이 적합하다.

이번 범위에서는 텍스트 전체 또는 발췌를 문서 끝에 넣기로 했다. 자료를 가져왔다고 원본 메모의 상태를 자동으로 바꾸지 않고, 첨부나 연결된 다른 문서를 따라가며 복사하지 않는다.

### 여행 문서는 무엇을 먼저 보여줄 것인가

날짜별 일정표를 중심에 두고 예약·교통·예산·준비물·비상 대안을 따로 정리한다. 이동 시간과 관광 시간은 활동 유형으로 구분하고, 실제로 필요한 안내는 시간표에서 바로 읽을 수 있게 둔다.

모바일에서는 고정 시간 열 때문에 설명이 좁아지는 문제가 있었다. 설명을 행 아래 전체 폭으로 내려 쓰고, 빈 일정표에서는 사용할 수 없는 지도 도구를 줄이기로 했다.

## 결정 사항

| 결정 | 적용 방식 |
| --- | --- |
| 네 가지 내장 템플릿 제공 | 앱과 에이전트가 같은 버전의 정의·작성 지침 사용 |
| 기존 글을 임의로 교체하지 않음 | 빈 페이지에서 템플릿 적용, 홈에서는 새 페이지 생성 |
| 원본을 읽으며 발췌하기 | 메모·페이지·AI 결과 검색과 원문 선택 제공 |
| 가져오기 전 문서 한도 검사 | 서버와 같은 규칙으로 확인한 뒤 본문 변경 |
| 날짜별 여행 일정표 사용 | 지도와 시간표를 한 흐름으로 읽고 모바일 설명 폭 확보 |
| 긴 글의 현재 위치 표시 | 스크롤에 맞춰 목차의 현재 제목 강조 |

위 항목은 이번 대화에서 승인된 범위와 반영 결과다. 다중 사용자 공동 편집, 자동 문서 재작성, 실제 기기 검증 완료까지 포함하는 결정은 아니다.
