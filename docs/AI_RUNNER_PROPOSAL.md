# AI 요청 개선 제안 — 2026-10-05

상태: 설계 제안. 아래 범용 실행기와 PC 연결 프로그램은 아직 구현하지 않았다.

## 확인한 현재 상태

- server/ai/runner.mjs는 HTTP 게이트웨이 또는 Devin을 선택한다. 실행기는 환경변수로 정하며 요청마다 선택하지 않는다.
- HTTP 게이트웨이는 prompt/input/materials와 정책을 보내고 결과를 검증한다. Devin은 프로세스 실행·취소·출력 제한을 처리한다.
- 2026-10-05 Hive 직접 어댑터와 Hive/Devin 설정·선택을 로컬 반영했다. 아래 다중 CLI·PC 실행은 초기 제안이며 현재 구현은 Hive와 Devin까지다.
- 이 PC에는 Codex, Devin, Claude, OpenCode 실행 파일이 있다. 이번 확인은 설치와 도움말까지만이며 로그인 유효성이나 실호출 성공을 확인한 것이 아니다.

## 제안하는 요청 화면

1. 작업: 요약 / 문장 다듬기 / 할 일 추출 / 자유 요청.
2. 입력: 선택한 내용 / 문서 전체 / 직접 입력. 실제 전달할 텍스트를 펼쳐 확인한다.
3. 템플릿: 이름과 저장 당시 버전, 적용된 변수 값을 보여 준다.
4. 실행기: Hive·Codex·Devin·Claude·OpenCode 중 등록된 실행기를 고른다. 서버/내 PC, 모델, 연결 상태를 함께 표시한다.
5. 결과: 읽기 좋은 Markdown 본문을 먼저 보여 준다. 요청 원문·템플릿·모델·실행 시간·사용량은 접는 상세 영역에 둔다. 제공자가 주지 않은 사용량은 미보고로 표시한다.
6. 적용: 복사 / 새 페이지 / 현재 문서에 추가 등 명시적인 동작으로 반영한다. 재시도는 새 실행 이력으로 남긴다.

## 실행 구조

웹 요청 → 서버 작업 큐 → 선택한 실행기 → 결과 검증·저장 → 웹에서 확인·적용.

- 서버 실행: Oracle에 설치·인증된 CLI 또는 Hive API를 서버 worker가 실행한다.
- PC 실행: PC 연결 프로그램이 서버에 나가는 연결로 작업을 받아 로컬 CLI를 실행한다. 브라우저가 PC의 CLI를 직접 실행하지 않는다. PC가 꺼져 있으면 대기 상태로 두며 다른 유료 실행기로 자동 전환하지 않는다.
- 두 위치를 지원하되 실행 프로필마다 위치·제공자·모델을 고정한다. 요청 저장 시 이 선택을 사본으로 남겨 설정 변경 후에도 과거 실행을 설명할 수 있게 한다.
- CLI 명령과 허용 인자는 운영 설정에서 정한다. 브라우저 입력을 셸 명령으로 연결하지 않는다. 인증 정보는 해당 실행 장치에 보관한다.
- 요약·다듬기 작업에는 자료 텍스트만 전달한다. 임시 작업 폴더, 파일 수정/셸/MCP 등 도구 제한, 타임아웃·취소·출력 크기 제한을 각 CLI가 실제 지원하는 방식으로 적용하고 검증한다.
- PC worker를 추가하면 기기별 인증·작업 임대·중복 실행 방지·결과 재전송을 설계해야 한다. 이미 완료된 요청을 연결 복구 때문에 자동으로 다시 실행하지 않는다.

## 구현 순서

1. 공통 실행 프로필과 요청 사본 규격, Hive 어댑터.
2. 한 CLI 어댑터로 요약·취소·실패·출력 검증을 먼저 확인.
3. 나머지 CLI 어댑터와 설치·인증 상태 표시.
4. PC 실행이 필요하면 연결 프로그램과 기기 관리.
5. 요청·결과 UI를 위 흐름으로 통합.

CLI는 자동 실행을 지원하지만 사용하는 계정·모델의 한도와 요금은 별개다. 계정 로그인 사본을 웹 화면이나 Git에 넣지 않는다.
